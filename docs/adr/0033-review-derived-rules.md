# 0033: レビュー由来の落とし穴は `.claude/rules/` にテーマ別で集める

ステータス: 採用

## 文脈

CodeRabbit のレビュー指摘（37 PR・スレッド約 40 件と、レビュー本文に畳まれた
nitpick / outside-diff 約 35 件）を棚卸ししたところ、指摘は少数のテーマに
強く偏っていた。
E2E モックの緩さ、テストが失敗を検知しない形、検証の置き場所、非同期 UI の
競合、GitHub アダプタの縁、記述と実装のずれ。同じ形の指摘が別の PR で
繰り返されており、対応した学びが規約として残っていなかった。

もう 1 つ、指摘の約 1/4 は「直さない」と理由を返して決着していた。この却下
理由は CodeRabbit 側の Learnings には残るが、リポジトリ側には残らない。
残さないと、将来の実装やセルフレビューが同じ「修正」を善意で入れ直す。

置き場所の候補は既にある。ルートと各ディレクトリの `CLAUDE.md` は構造と
設計判断を持ち、ADR は個別の判断を持つ。落とし穴集をどこに置くかを決める
必要があった。

## 決定

**`.claude/rules/` にテーマ別の Markdown として置く。** frontmatter の
`paths` で対象ファイルを絞り、そのファイルを読むときだけ読み込ませる。

- **切り口はディレクトリではなくテーマ。** ディレクトリ別は既に各
  `CLAUDE.md` が担っていて、同じ軸で切ると二重になる。指摘のクラスタが
  そのまま「触るときに要る単位」だった。
- **却下した指摘は「やらないこと」として同じテーマに入れる。** 理由と
  出典 PR を添える。採用した指摘と同じだけ再発を防ぐ価値がある。選ぶ基準は
  下と同じで、その PR 限りの却下は入れない。
- **入れる基準は 3 つ。** 再発しうる一般則である。lint / 型 / CI で
  塞げない。既存の規約に無い。単発の実装バグと機械で塞げるものは
  入れない。肥大化すると読まれなくなる。
- **棚卸しは繰り返さない。** PR のレビュー対応（`/pr-review`）の最後に、
  決着した指摘をその場で還流する手順を組み込む。`/rv` は点検の観点として
  rules を参照する。

**追記（#126）。** 上の最後の 1 行が守られていなかった。`/rv` は rules を参照
しつつ、**SKILL.md の側にも観点の一覧を手で持っていた**。指摘を還しても育つのは
rules だけで、一覧は止まったまま残る。#108（9 件）と #121 の還流もまるごと
抜けていた。2 つを足す。

- **セルフレビューの観点は rules と `CLAUDE.md` 群にだけ置く。** `/rv` の
  SKILL.md は手順・分類・打ち切り条件だけを持ち、観点の写しを持たない。
  **写しを持つと、還流した指摘が次のセルフレビューに届かない。** rules の
  `paths` が差分にかからない領域は、そのこと自体を報告に出す（追いついていない
  合図なので）。
- **PR ごとの初回指摘数を `docs/review-findings.md` に記録する。** 書くのは
  還流と同じ場面。**別の場面にすると、片方だけ忘れたことに気づけない。**
  直した数と取り下げの数を分けて数える（理由は「帰結」の最後）。

## 採らなかった案

- **各 `CLAUDE.md` への追記。** 全体則は既に 200 行近く、遅延読み込みの
  粒度もディレクトリ単位しかない。テーマ（例: テストの書き方）は
  ディレクトリを横断する。
- **CodeRabbit の設定（`knowledge_base`）で rules を共有する。** Claude と
  レビュアーが同じルールブックを見る状態にできるが、CodeRabbit が
  `.claude/rules/` を読むかの確認とチューニングが要るので、まず運用して
  中身が安定してから別途判断する。

## 帰結

- 対象ファイルを触る作業では、過去に踏んだ落とし穴が自動で文脈に載る。
- 「直さない」の理由が引けるので、レビューでの同じ議論と、善意の逆流の
  両方を防げる。
- rules は規約の置き場所が 1 つ増えるということでもある。既存の
  `CLAUDE.md` と同じ内容を書かない規律が要る（各ファイル冒頭で参照に
  倒す）。
- **rules は返事を安くするが、指摘の発生は止めていない。** #81 で撤回した
  `satisfies Reply<T>` を「やらないこと」に残したあとも、同じ形が #96 と #105 で
  来た。**rules を読ませる設定は入れていない**（上の「採らなかった案」）ので、
  ここで観測できるのは「書いても同じ指摘が来た」までで、読んだ上で来たのかは
  分からない。どちらであれ**却下の記録が効くのは返事の側**なので、記録では
  取り下げを別に数える。
- 取り下げを減らしたいなら、効くのは rules ではなく**レビュアーから見える場所**
  （PR 本文、コードの隣のコメント、ADR）に判断を置くこと。#117 は ADR 0043 に
  「読める人がどこまで広がるか」を書き足したことで撤回まで 1 往復で済んだ。
