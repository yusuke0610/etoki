# 0055. 配色は OS に従い、キャンバスと 1 つの値を共有し、シーンには載せない

- 状態: 採用
- 日付: 2026-09-15

## 背景

UI デザインの見直し（#62）でダークモードを持つことにした。画面の大半は
Excalidraw のキャンバスで、Excalidraw は自前のテーマ（`appState.theme`）と、
メニューの「ダークモード」切り替えを持っている。一方で etoki のパネル・
ヘッダー・サイドバーは手書きの CSS で、色が直書きされていた。

決めることは 3 つあった。どこからテーマを決めるか、キャンバスと etoki の画面で
値をどう揃えるか、テーマをどこに残すか。

## 決定

### 既定は OS の設定に従い、手で選んだときだけ覚える

etoki はログインの前にも画面を出し、認証そのものが任意なので（ADR 0015）、
利用者ごとの設定を置ける構成と置けない構成がある。**どちらの構成でも使える
好みの手掛かりは、OS の設定しか無い。**

手で選んだテーマはブラウザ（`localStorage`）に覚える。**ただし OS と同じ
テーマを選んだときは覚えず、覚えていた選択も消す。** 選んだものを常に覚えると、
一度切り替えた人は OS の設定を変えても付いてこなくなり、しかも「OS に従う」へ
戻す口が無い。専用の「システムに従う」選択肢を足す案もあったが、切り替えの口を
Excalidraw のメニューに寄せる（次節）以上、項目は増やせない。

### 切り替えの口は Excalidraw のメニュー 1 つにし、値は App が持つ

Excalidraw はテーマの切り替えをメニューに持っている。etoki のヘッダーにも
切り替えを置くと、**同じ画面に同じ意味の口が 2 つ並ぶ。** 持ち出しと取り込みの
口を 1 つに寄せたのと同じ理由で、今回は増やさない（ADR 0045）。

値を持つのは App の 1 箇所で、Excalidraw には `theme` として渡す。メニューで
切り替えられたら `onChange` から App に返す。**BoardPage やキャンバスで持ち直すと
値が 2 つになり、パネルとキャンバスの片方だけが暗い画面が起きる。** ログインや
作成先の選択の画面にはキャンバスが無いので、ボードより上に置く必要もある。

「選び直した」かどうかは、**キャンバスが前回と違うテーマを言ってきたか**で判断
する。渡している `theme` と比べる形にすると、OS の設定が変わって渡す値を
差し替えた直後に届く古いテーマの `onChange` を「選び直した」と取り違え、OS に
従うのをやめてしまう。

### テーマはシーンに載せず、未保存の判定にも入れない

テーマは描いた内容ではなく見る人の好みで、共有したボードを開いた相手の配色を
決めるものではない（ADR 0017）。Excalidraw の直列化もテーマを落とすので、保存・
書き出し・大きさの計測（ADR 0045 の `sceneJSON`）には初めから入らない。

**未保存の判定（`sceneSignature`）にも入れない。** 基準は「保存が書くかどうか」
（web/CLAUDE.md）で、入れると切り替えただけで未保存になり、離れるたびに確認が
出る（ADR 0021）。

### 色は役割の名前の変数で持ち、ダークは変数だけを差し替える

規則ごとにダーク用の上書きを書くと、規則を足した日にダークだけ抜ける。
**直書きの色が 1 つでも残ると、そこだけ明るいまま残る。** 変数の名前は色味では
なく役割で付ける（`.hint` が読むのは「灰色」ではなく「薄い文字」で、ダークでは
明るい灰色になる）。

コントラストはライトとダークの両方で axe に掛ける（ADR 0039）。片方で通っても、
もう片方で AA を切っていることは見えない。実際、ダークだけで「ボードを削除」の
文字がブラウザ既定のボタン地の上で AA を切っていた。

## 採らなかった案

- **テーマをサーバーに利用者ごとに保存する。** 認証を設定しない構成では置き場所が
  無く、置ける構成と置けない構成で挙動が分かれる。見た目の好みのために契約と
  永続化を増やす理由が無い。
- **CSS フレームワークやデザインシステムを入れてテーマを任せる。** 依存と
  バージョンの連動が増える（ADR 0035）。今回の見直しは手書きの CSS のまま進める。
