# 0100. ボードは作成先を選ばずに作り、作成先は描いたあとでボードの上から選ぶ

- 状態: 採用
- 日付: 2026-11-17
- ADR 0017 の「ボードの作成に作成先を必須にする」を改める（要件 1 を見直す）
- ADR 0090 を置き換える。GitHub を設定していない構成だけの例外だったものを、
  どの構成の規則にする
- ADR 0014 の「未選択のボードは開いたときに選択画面に入る」と、ADR 0074 の
  「作成先を設定したあとに開く口で取り直す」を改める

## 背景

GitHub を設定した構成で「新しいボード」を押すと、名前の次にリポジトリと
Project を選ぶ画面になり、「最初の draft issue を作ると、以後は変更できなく
なります。」と言われる。**1 本も描かないうちに draft issue の行き先を決めさせて
いる**（中核思想 1）。ADR 0090 はこの緊張を、GitHub を設定していない構成に
ついてだけ解いた。

ホストして人に出すと決めた（#464）。ホスト版は認証ありの構成で動かすので、
そのままだと次のようになる。

- 書き込める Project を持たない人は、ログインしても 1 本も描けない。
- GitHub App は個人アカウントの Projects v2 に触れない。個人のアカウントで来た
  人は、Organization を作り、App を入れ、Project を紐づけるまで全員止まる。
- ログインなしのお試し（#466）は作成先を持てない。

ADR 0017 が作成先を必須にした理由は要件 1（ボードの作成にはリポジトリへの
アクセス権が要る）だった。**draft issue を作れるかは、今も作成のときに GitHub が
決めている**（要件 3）。描く段で縛っていた理由は「書けない人にボードを作らせ
ない」だけで、それは描くことを止める理由にならない。

## 決定

### ボードは名前とひな形だけで作る。どの構成でも

- `POST /api/boards` は、作成先を丸ごと省けば、どの構成でも未選択のボードを作る。
  **一部だけ送ったら 400**（ADR 0090 と同じ）。一部を残すと、選んでいないのに
  選びかけの値を持つボードができる。GitHub の無い構成だけを通す口は外す。
- 新しいボードのダイアログは作成先の選択に進まず、その場で作る。作成先を訊かない
  ことは押す前に文で言う（中核思想 3）。
- **要件 1 を「描くことにはアクセス権が要らない」に改める。** 要件 3 はそのまま
  効く。作成先の候補は書ける Project に絞ってあり（ADR 0014）、作成では GitHub が
  403 を返す。書けない人が止まるのは、draft issue を作ろうとしたときになる。

### 作成先は描いたあとで、ボードの上のダイアログで選ぶ

- **未選択のボードもキャンバスをそのまま開く。** 開いたら作成先の選択から始める
  形（ADR 0014 / 0090）はやめる。
- 開く口は 2 つ。キャンバスのメニュー（未選択なら「作成先を選ぶ」、選んであれば
  「作成先を変更」）と、作成の帯（未選択のとき、「GitHub に作成する」の代わりに
  「作成先を選ぶ」と理由の文）。
- **画面を移らない。** 選ぶあいだもボードの画面を外さない。引いた解釈はフロントの
  メモリにしか無いので、外すと絵解きの結果と手直しが消え、選んだあとに絵解き直す
  （課金される）ことになる。作成の直前に選ぶ流れで、それがいちばん起きやすい。
- **設定の応答で、手元のボードをその場で差し替える。** キャンバスを作り直さない
  ので、開く口で取り直さない（ADR 0074 の取り直しをやめる）。画像と版は持ち越す。
  設定の応答は画像を運ばず、版は基準にしない（改名と同じ、ADR 0092）。
- **作成先が変わったら、その Project に書けるかを訊き直す。** 開いたときに 1 度
  訊くだけだと、選ぶ前の答え（未選択なら unknown）が残り、書けない Project に
  作らせる。
- 開いていることは URL に載せ、履歴には積まない（ADR 0059 の選び直しと同じ）。
- Kind / Parent の確認（ADR 0088）は今と同じく、選んだときにダイアログの中で
  見せる。作成の直前に選んでも同じダイアログを通るので、順序は「選ぶ → 確かめる
  → 作る」のまま。
- 選べるのは今と同じく owner だけ（ADR 0017）。owner でない人には、作成の帯で、
  選べないこととオーナーに頼むことを言う。

### 「まだ選んでいない」を状態として見せる

作成の帯と、下の帯の作成先を出している場所（「作成先: 未選択」）。空のまま
にすると、選んでいないのか読み込めていないのかが読めない。

### 作成先を選ぶ口は、未保存でも保存中でも止めない

以前は未保存のあいだと保存中に「作成先を変更」を止めていた。**選ぶとキャンバス
ごと外れたから**で、止める理由はそれだけだった。いまはキャンバスが外れず、作成先の
設定はシーンの版を進めない（ADR 0092）。作成との前後はサーバーがボード単位で
直列化する（ADR 0014）。並べても食い違うものが無い。

止めるのは、作成先を設定している最中にダイアログを閉じることだけ。閉じると、
設定できなかったときに理由を出す先が無くなる（新しいボードのダイアログと同じ）。

## 検討したが採らなかった案

### 認証なしの構成でだけ、作成先を省けるようにする

この件（#450）の当初の案。ホスト版は認証ありの構成で動かす（#464）ので、人に
出す構成に壁が残る。

### 作成のボタンから、作成先の選択画面へ移る

画面を移ると、絵解きの結果と手直しが消える。

### 新しいボードのダイアログに、作成先の任意の欄を足す

描く前に行き先を考えさせる口が残る（中核思想 1）。選ぶ口を作る前と後の 2 つの
場面に持つと、片方だけ直す形にもなる。

### 前に使った作成先を、既定で選んでおく

作成先は最初の作成で固定される、取り返しのつかない選択（ADR 0014）。システムが
決めずに開発者に選ばせる（中核思想 3）。1 件しか無くても自動で確定しない、と
同じ理由。

## 影響

- 作成先が未選択のボードが、どの構成でも普通に生まれる。一覧では「作成先が
  未選択」の節に並ぶ（ADR 0019 の射影のまま）。
- 作成先の選択画面（別の画面）は無くなり、選ぶのはボードの上のダイアログ 1 つに
  なる。新しいボードのダイアログから選択画面へ進み、やめたら入力を残して開き直す
  流れも無くなる。
- 書ける Project を持たない人もボードを作って描ける。作れないことは、作成先を
  選ぶダイアログ（候補が無い）と作成のところ（GitHub の 403）で見せる。
- 一覧のカードの破線の枠と「開くと作成先を選べます」（#200、ADR 0090）は外す。
  開いた先はどの構成でもキャンバス。
