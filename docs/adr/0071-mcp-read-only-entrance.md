# 0071. 既存のサーバーに MCP の入口（/mcp）を開き、読み取りだけを出す

- 状態: 採用（認証ありの構成で開く形は ADR 0076）
- 日付: 2026-10-03

## 背景

etoki の状態（ボード、注釈の 3 状態、作った draft issue、実行の履歴）を、画面を
経由せずに MCP のクライアント（Claude Code など）から読めるようにしたい（#184）。
論点 A〜E は 2026-09-25 に issue で決めた。ここにはその決定と、実装で決めた
ことを残す。

## 決定

### 既存のサーバーに組み込み、Streamable HTTP で `/mcp` を開く

**`etoki mcp` を別のプロセスで起動する形（stdio）は採らない。**

- 作成先の固定を守る排他（`usecase.BoardLocks`）と LLM の上限
  （`usecase.LLMLimiter`）はメモリにしか状態を持たず、SQLite を複数の
  プロセスで共有しないことが前提にある（`internal/CLAUDE.md`）。別のプロセスに
  すると、どちらも素通りする。
- GitHub App の構成では、GitHub を叩くトークンの出どころはセッション中の利用者
  （ADR 0015）。別のプロセスにはその手段が無い。

**`/api` とは別の入口にする。** MCP のクライアントは画面を意識しない。画面の
配信や `/api` の都合と切り離しておく。使うには etoki を起動しておく必要がある。

### 公開するのは読み取りの 3 つだけ

`list_boards` / `list_annotations` / `list_annotation_runs`。それぞれ
`GET /api/boards`、`GET /api/boards/{id}/annotations`、
`GET /api/boards/{id}/annotations/{annotationId}/runs` と 1 対 1 にする。
作った draft issue は `list_annotations` の `items` に含まれているので、別の道具に
しない。

**何かを動かす道具（解釈・作成）は出さない。** 要るなら別の issue で足す。

- 解釈：注釈の範囲の画像はブラウザでしか作れない（ADR 0018）。MCP からは
  テキストだけの解釈になり、画面からの解釈と入力が食い違う。
- 作成：作るものを選んで手直しする役（ADR 0024）がエージェントに移る。人の
  確認をどこに挟むかを決めないまま出すと、取り消せない操作（ADR 0009）に
  人を通らずに届く（中核思想 3）。

### 返す JSON は `/api` と同じ形にする

道具の出力は `api/openapi.yaml` から生成した型をそのまま使う（ADR 0011）。
**組み立ても `/api` のハンドラと同じ関数を通す。** 口ごとに詰め替えを書くと、
契約に足したフィールドが片方にだけ載り、生成型が同じなのでゼロ値のまま
コンパイルが通る。

**配列を返す 2 つだけ、オブジェクトで 1 段包む**（`boards` / `runs`）。MCP の
2025-06-18 版と 2025-11-25 版は、構造化された結果と出力のスキーマをオブジェクトと
定めている。配列を許したのはその後の版（SEP-2106）で、そちらに追いついていない
クライアントにも読めるようにしておく。包むのは 1 段だけで、中身は `/api` の応答
そのもの。

失敗は `/api` と同じ code を頭に付けた文で返す（`not_found: not found`）。
写し替えの表は `errors.go` の 1 つを引き、見つからないときに理由を載せない
規則（ADR 0016 / 0017）も同じにする。

### 認証なしの構成でだけ開く

利用者は画面と同じ「認証なしの操作者」。**GitHub App を設定した構成では
道具を組み立てず、503 を返す。** 利用者を決める手段が無いまま開くと、ログイン
せずに全ボードが読める。認証ありの構成で開くのは OAuth で行う（#185）。

**認証なしの構成では既定で開く。** 有効にする設定は置かない。読み取りだけで、
`/api` と同じバインド先の制限（ADR 0004）と Host / Origin の検証（ADR 0013）が
効く。`/api` が開いている構成で `/mcp` だけを閉じても、守れるものが増えない。

### 使えないことは capabilities に載せない

issue では「`GET /api/capabilities` で使えないことを見せる」と決めていたが、
**載せない。** capabilities は画面が押す前に理由を出すための口で、**使う側の
いない値を契約に置かない**（ADR 0030）。画面は `/mcp` を叩かないので、載せても
読む人がいない。MCP のクライアントは `/mcp` の 503 で知る。

同じ理由で、**503 の本文は `ErrorResponse` ではなく text/plain にする。**
`ErrorResponse` の code は画面が日本語を引くための列挙で（ADR 0034）、増やすと
画面に読まれない文言を 1 つ持つことになる。`/mcp` で SDK 自身が返すエラー
（405 / 413 など）も text/plain なので、同じ口では形が揃う。

### Host の検証は originGuard 1 つに任せる

`/mcp` は `/api` の外にあるが、originGuard（ADR 0013）の内側に置く。**MCP の
SDK が持つ DNS リバインディングの守りは外す。** 残すと、`ETOKI_ALLOWED_ORIGINS`
で許したホストを SDK だけが弾き、`/api` は通るのに `/mcp` だけ 403 になる構成が
できる。同じ問いに 2 つの答えを持たせない。

### セッションを持たない

道具は読み取りだけで、サーバーからクライアントへ送るものが無い。セッションを
持つと、再起動で消えるセッションの扱いを抱える。

### SDK は `internal/httpapi` に閉じる

公式の `github.com/modelcontextprotocol/go-sdk` を使う。Streamable HTTP の
ハンドラが `http.Handler` として得られ、Gin に載せられる。

**置き場所は `internal/httpapi` の中にした。** issue では `internal/mcpapi` の
ように並べる例を挙げていたが、道具の出力は `/api` と同じ詰め替えとエラーの
写し替えを通す必要がある。別のパッケージにすると、それらを公開し直すか移す
ことになり、契約の面が 2 か所に分かれる。SDK の型がユースケース層と `port/` に
入らない、という本来の線はこれで守れる。

### `api/openapi.yaml` には載せない

`/mcp` は JSON-RPC を運ぶ 1 つの口で、REST のエンドポイントの並びとしては書け
ない。道具の名前と入出力の正本は道具の定義（`internal/httpapi/mcp.go`）で、
出力の中身は上のとおり `openapi.yaml` の生成型そのもの。

## 帰結

- `/api` の一覧・3 状態・履歴のハンドラは、応答の組み立てを関数に切り出した。
  MCP の道具もそれを呼ぶ。
- 契約に足したフィールドは、何もしなくても MCP にも載る。外したいものが
  出てきたら、そのときに MCP 側の型を分ける。
- `make dev` の Vite は `/mcp` を転送しない。MCP のクライアントはバックエンド
  （:8080）に向ける。**ADR 0076 で改めた。** 認証ありの構成では許可の途中で画面へ
  転送されるので、Vite も `/mcp` を転送し、クライアントは :5173 に向ける。

## 採らなかった案

- **stdio で別のプロセスにする。** 上に書いたとおり、メモリの排他と上限が
  素通りし、GitHub App の構成でトークンが無い。
- **有効にする設定（`ETOKI_MCP` など）を置く。** 読み取りだけの口を閉じても、
  同じものが `/api` から読める。設定が 1 つ増えるぶん、開いているのかどうかを
  利用者が確かめる手間が増える。
- **配列をそのまま返す。** SDK は配列の出力も扱えるが、2025-11-25 版までの
  定めに沿うクライアントには、出力のスキーマが定めの外になる。
