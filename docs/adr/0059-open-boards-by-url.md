# 0059: 開いているボードはクエリで URL に載せ、ログイン後の戻り先は state と一緒に持つ

ステータス: 採用

## 文脈

**開いているボードが URL に現れなかった。** どのボードを開いているかを持って
いたのは `App` の state だけで、リロード・共有・ログインし直し・ブラウザの
戻る / 進みのどれでも、戻る手段は「サイドバーから探す」しかなかった（issue #149）。

共有（ADR 0017）が入ってから、ボードは「自分が作ったものを 1 枚ずつ開く」もの
ではなく、**人に渡して一緒に見る**ものになった。渡す手段が名前だけなのは、
その使い方に合っていない。招待した相手は、サイドバーの木を作成先とボード名で
探すことになる（ADR 0019）。

## 決定

### 形はクエリ（`/?board={id}`）にする

**パス（`/boards/{id}`）は採らない。** ADR 0032 は「未知のパスに `index.html` を
返す SPA の fallback は持たない」と決めている。パスにするならその判断を覆す
必要があり、覆すと**打ち間違えた URL が 404 ではなく 200 + HTML で返る。**
配る範囲を `/boards/` 配下に絞れば被害は減るが、**減らすために配信側が画面の
ルーティングを知る**ことになり、画面を足すたびに両方を直す形が生まれる。

クエリなら配るパスは `/` のままで、配信側は 1 行も変わらない。得られなかったのは
URL の見た目だけで、**払わずに済んだのは配信の判断**である。ADR 0032 は
「ルーティングを入れるときに、必要になった時点で一緒に足す」と書いているが、
**この機能はルーティングを必要としない。**

`react-router` も入れない。載せる状態は 2 つ（どのボード、選び直しかどうか）
しかなく、ライブラリを足すと依存とバージョンの連動が増える（ADR 0035）。
組み立てと解釈は `web/src/location.ts` の純関数 2 つに閉じてある。

### 作成先の選び直しは載せるが、作成中は載せない

選び直し（`?board={id}&picking=1`）は、そのボードの中のモードなので載せられる。
**作成中（新しいボードの名前を入れて作成先を選んでいる最中）は載せない。**
載る材料である名前とひな形が URL に無いので、載せても読み込み直した先で復元
できない。**復元できない状態を URL が指すと、URL は嘘をつく。**

**URL から選び直しに入れる条件は、画面が「作成先を変更」を出す条件と同じ**
（owner だけ、固定前だけ。ADR 0014 / 0017）。緩めると、画面から押せないはずの
操作に URL からだけ入れてしまい、進んだ先で 403 / 409 を受け取る（中核思想 3）。
通らなかった指定は URL からも落とす。

### 戻る / 進むは「止める」ではなく「書き戻す」

キャンバスが外れる導線には未保存の確認を通す（ADR 0021）。戻る / 進むも導線の
1 つなので `confirmDiscard` を通すが、**ここだけは他の導線と形が違う。**
`popstate` が届いた時点でブラウザはもう動いており、アプリ側に止める手立てが無い。

できるのは、捨てないと言われたときに**見えている場所を積み直して URL を画面に
合わせる**ことまでである。**戻す（`history.back()`）形は採らない。** 何手ぶん
動かされたのかを知る手立てが無いので、戻す量を決められない。

`popstate` の中でも「取ってから訊く」順は崩さない。訊いてから取ると、取って
いるあいだの描き足しを確認なしで捨てる。

### ログイン後の戻り先はサーバーが state と一緒に持つ

**戻り先を URL で持ち回らない。** 認可のコールバックに載せる形にすると、
戻ってきた URL の中身が戻り先を決めることになり、オープンリダイレクトを塞ぐ
責任が**毎回の照合**に移る。

`state` はすでにサーバー発行・単回使用・期限つきで保存してある（ADR 0015）。
そこに相乗りさせれば、**外から書ける面が 1 つも増えない。** 検証は
`AuthService.Start` の 1 箇所だけで、通すのは自オリジンの相対パスのみ。
コールバック側は保存済みの値をそのまま使い、検証し直さない（検証を 2 箇所に
置かない）。

**弾いた戻り先では state を発行しない。** 発行すると、400 を返したぶんだけ表が
育つ。

**不正値を黙って `/` に落とさない。** 落とすと、渡した値が消えたことに呼び出し
側が気づけないまま、思っていない場所に着地する。400 で弾いて直させる。

## 結果

- `/?board={id}` でボードを開け、リロードでも開いたまま残り、人に渡せる。
- 戻る / 進むがボードの切り替えに効き、未保存の確認もそこを通る。
- セッションが切れて入り直した人は、開いていたボードへ戻る。
- **ADR 0032 の判断は変わらない。** 配るパスは `/` のままで、fallback は無い。
  ADR 0032 の理由に書いてあった「ログイン後の戻り先も `/` である」だけが
  「戻り先はクエリを持つが、パスは `/` のまま」に変わる。
- **権限の無いボード ID の見せ方は変わらない。** 非メンバーにも消えたボードにも
  同じ `not_found` が返り（ADR 0016 / 0017）、URL から開いたときも同じ画面に
  落ちる。**開けなかったボードは URL に残さない。** 残すと、読み込み直すたびに
  同じ失敗を繰り返す。
- `oauth_states` に `return_to` 列が増える。既存の行は空文字（= `/` に戻す）。
- **`port.SessionRepository` の `SaveState` / `ConsumeState` が変わる。**
  `port/` は外部リポジトリが実装するための公開面（ADR 0001 / 0015）なので、
  セッションの置き場所を自前で差している実装は追随が要る。**戻り値を並べずに
  `port.OAuthState` で束ねた**のは、次に state と一緒に持ちたいものが出たときに
  同じ破壊的変更を繰り返さないため。
- **ブラウザの履歴に残るのはボードの切り替えだけ。** 選び直し・作成中・削除・
  ログアウトは URL を置き換える。積むのは「戻る」で引き返せるべきものだけで、
  引き返せない場所（消えたボード、ログアウト前）を積むと、押した先で画面と
  URL が食い違う。
