# 0024. 作る前に選ばせ、手直しさせる（構造の変更は画面に出す）

- ステータス: 採用
- 日付: 2026-08-16

## 文脈

解釈結果は `onCreate(state.result)` で**まるごと**作成に送られていた。開発者にできる
のは「全部作る」か「作らない」の二択で、item を 1 件外すことも、誤字を直すことも
できない。

LLM の出力は揺れる。8 件のうち 1 件だけ的外れ、というのは普通に起きる。そのとき
取れる手は「全部作って GitHub 側で消す」か「全部捨てて解釈し直す」しかなかった。
draft issue の作成は取り消せない（ADR 0009）ので、前者は後始末が残る。

ADR 0023 で本文まで**見せる**ところは埋まったが、**選ばせている**のは実行するか
どうかだけで、何を作るかは LLM が決めたままだった。中核思想 3 は「システムは自動で
判断せず、状態を見せて開発者に選ばせる」であり、見せるところで止まっている。

## 決定

**作成の直前に、作るものを選び、title / body / kind を手直しできるようにする。**

### 契約もサーバーも変えない

変えるのは画面と、送るときの組み立てだけにした。成り立つ理由は 3 つある。

- 作成のリクエストボディは `Interpretation` そのもので、`CreationService.Create` が
  `in.Validate(annotation.Granularity)` で受け取った内容を検証し直す。フロントが
  何を間引いても 2 階層の制約は守られる。
- 粒度はリクエストではなく**注釈**（シーンの `customData.etoki`）から取る。間引いても
  判定の基準が動かない。
- `contentHash` の入力は保存済みシーンのテキストと粒度だけで、解釈結果は入らない。
  **受け取った値をそのまま送り返す限り、手直ししても照合は成立する**（ADR 0010）。

`summary` は編集させない。GitHub には作らない確認材料であり（ADR 0006）、LLM が
どう読んだかの記録として残すべきもの。書き換えられると、確認したものが何だったのか
分からなくなる。

### 親を失うことは黙って起こさない

**epic の選択を外すと、その epic を親に持つ issue も一緒に外れる。** 親だけ消えて子が
残ると、開発者が選んだつもりのない「親なしの issue」が GitHub にできる。

ただし外れた issue は 1 件ずつ戻せる。「epic は要らないが issue は作りたい」は普通に
起きる要求で、塞ぐ理由が無い。戻した issue には
**「epic に属さない issue として作られます」と画面に出したうえで**、`parentLocalId` を
落として送る。**この表示は便利のためではなく、構造が変わったことを黙って起こさない
ためにある。** 同じことが kind を epic から issue に変えたときにも起きるので、判定は
「その項目が実際に持てる親」1 つに寄せてある（`interpretationDraft.ts`）。

epic を戻しても、外れた子は自動では戻らない。外したものを勝手に戻すと、外した操作が
どこまで効いているのか分からなくなる。

### 画面側の検証は正本ではない

作成ボタンを止める条件（1 件も選ばれていない / タイトルが空 / 粒度 epic なのに epic が
0 件）はサーバーの `Validate` と重なる。**重なっていることを承知で置いている。**

正本はサーバー側で、画面側は押す前に止めるためのもの。**食い違ったときに起きるのは
「押せて 400 が返る」までで、画面が通したものが検証を素通りすることはない。** 注釈の
判定規則（`isAnnotation`）のように両側を揃える必要がある定義とは性質が違うので、
`web/CLAUDE.md` の「バックエンドと揃える必要がある約束」には入れない。

### 下書きは `BoardPage` に持ち上げない

編集中の内容は解釈結果を表示しているコンポーネントが持つ。保存も解釈のやり直しも
`InterpretationState` を done から外すので、その枝ごと unmount されて編集は捨てられる。

持ち上げると `save` と `interpret` の両方に破棄を書き足すことになり、片方を忘れると
保存したあとに古い編集が残る。**捨てる契機を自分で数えないための配置。**

## 結果

- 解釈結果のタイトルと本文が入力欄になる。E2E は文字列ではなくラベルと値で辿る
  （`e1 のタイトル` のように `localId` で分ける。タイトルで分けると編集の途中で
  ラベルが変わる）。
- 粒度に `issue` を指定した注釈では kind を変えさせない。epic を 1 件も作れないので、
  選ばせる理由が無い。
- 選択から外した項目も薄く残す。消すと、何を外したのかを確かめられない。
- 手直しした内容がそのまま `sync_items` に控えられる（ADR 0023）。記録されるのは
  LLM が出したものではなく、開発者が作らせたものになる。
