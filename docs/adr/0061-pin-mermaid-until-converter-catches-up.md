# 0061. mermaid を 11.13.0 に固定し、既知の脆弱性を受け入れる

- 状態: 採用
- 日付: 2026-09-26

## 背景

図のドラフト（ADR 0040 / 0041）で、**ER 図とシステム構成図が必ず「置けない」で
終わっていた**（#180）。変換器（`@excalidraw/mermaid-to-excalidraw` 2.2.2）は
mermaid の内部構造を読んで図形を組み立てるが、mermaid を `^11.12.1` で引いて
いる。11.14.0 以降の mermaid では `erDiagram` と subgraph 付きの `flowchart`
（構成図はこれで書かせている）の読み取りに失敗し、画像 1 枚に落ちる。etoki は
画像を置かない（ADR 0040）。

利用者に打ち手が無い。「種類を変えてください」と案内しても、原因は種類ではなく
依存の版にある。課金を伴う呼び出しの結果が毎回捨てられる。

上流には同じ報告があり（excalidraw/mermaid-to-excalidraw#107 / #108）、提案
されている修正も mermaid を 11.12.1 に固定するもの（同 #112）。**上流が直しても、
古い mermaid を使う状態は変わらない見込みが高い。**

## 決定

### mermaid を `overrides` で 11.13.0 に固定する

変換器の依存を上書きし、図形になる最後の版に揃える。11.13 系は 11.13.0 しか
出ていない。11.17.2（2026-09 時点の最新）でも直っていないことを E2E で確かめた。

変換器を直接直す（パッチを当てる）案は採らない。読んでいるのは mermaid の文書化
されていない内部構造で、etoki が追随し始めると mermaid の版ごとの差分を持つことに
なる。

### 11.13.0 に残る既知の脆弱性は受け入れる

固定のあいだ、11.15.0 と 11.16.1 で直った advisory を受け取れない。CSS / HTML
インジェクション、設定 API とアーキテクチャ図のプロトタイプ汚染、gantt / radar /
xychart の無限ループ。**どれも mermaid に渡る文字列を書ける者が攻撃者になる。**

etoki で mermaid に渡る文字列は、**その画面を見ている本人のプロンプトから LLM が
作ったものだけ**で、描かれるのも本人のブラウザの中だけ。

- 会話はメモリだけでサーバーに残らない（ADR 0041）。他のメンバーの mermaid が
  自分のブラウザで描かれる経路は無い。
- 置いたあとにシーンに載るのは Excalidraw の要素で、mermaid の文字列ではない。
  共有ボードを開いても mermaid は走らない。
- LLM の接続先を決めるのは etoki を動かす人の設定で、利用者ではない。

自分で書いたものを自分のブラウザで描くだけなので、壊せるのは自分の画面まで。
**ER 図と構成図が使えないことのほうを重く見た。**

### 固定を外す条件と、それを判断する場所

**`web/e2e/diagramChat.spec.ts` の「図形として置ける」が、`overrides` を外した
状態で通ったら外す。** 変換器の新しい版が出たら、`overrides` を消して回す。

### Dependabot には外させない

`.github/dependabot.yml` の `ignore` には入れない。mermaid は間接依存なので
version updates の対象外で、入れても外すものが無い。**脆弱性の知らせ（Dependabot
alerts）は残す。** 新しい advisory が出たら、上の受け入れがまだ成り立つかを
そこで見直す。mermaid を上げる PR が来ても上の E2E が落ちるので、黙って壊れる
ことは無い。

## この判断を見直すとき

**mermaid の文字列が本人のプロンプト以外から来るようになったら、脆弱性の受け入れ
を見直す。** 既存の設計（mermaid）を取り込む機能（#180 の後続）はそれに当たる。
取り込む文字列は外から来るもので、上の理由が成り立たない。
