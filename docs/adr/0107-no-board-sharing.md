# 0107. ボードの共有を外し、ロールで操作を分けない

- 状態: 採用
- 日付: 2026-11-27
- ADR 0017 の招待・ロール・403 の使い分けを置き換える
- ADR 0078 の「共有」のダイアログを置き換える
- ADR 0053 の招待の前の確認を置き換える

## 背景

2026-11-25 に、人に使ってもらうための開発を終え、作者が自分で使う形に切り替えた
（#491）。ログインも 1 人に絞った（ADR 0105）。招待できるのは一度ログインした相手
だけ（ADR 0017）なので、自分のほかに招待できる相手がいない。

それでも共有の仕組みは残っていた（#495）。

- 招待・ロールの変更・メンバーを外す口と、招待の前に相手を見せる口（ADR 0053）
- owner / editor / viewer のロールで操作を分ける判定と、ロール不足の 403
- 画面の「共有」のダイアログ、ロールの表示、読むだけの人への見せ方

使われないのに、保守と検査の対象に残る。バックエンドを触るたびに自動で読まれる
規約（`internal/CLAUDE.md` の「ボードのメンバーと権限」）にも載っていた。

## 決定

### 共有を、画面・契約・ユースケースから外す

招待・メンバーの一覧・ロールの変更・メンバーを外す口と、招待の前の引き当てを
契約から消す。画面からは「共有…」のダイアログを消す。

**画面だけ隠す形にはしない。** API と判定が残り、保守の量が変わらない。

### ロールで操作を分けない

- **ボードのメンバーなら、すべての操作を通す。** `boardGuard` が見るのはメンバー
  かどうかだけにし、ロールの上下（`port.BoardRole.AtLeast`）は消す。ログインを
  1 人に絞ってあるので（ADR 0105）、通るのは自分だけになる。
- **ロールは契約からも消す。** ボードと権限の応答の `role`、ロールの型、ロール
  不足の 403（`forbidden_role`）と、招待とロールの変更から来るエラーコード。
  画面のロールの表示と、読むだけの人への見せ方（キャンバスを描けなくする、
  絵解きと作成の帯や etoki AI のタブを出さない、理由の文）も消す。
- **非メンバーには、これまでどおり 404 を返す。** 所有者で絞る仕組み（ADR 0016）
  は #496 で畳む。
- **`board_members` の表は残す。** ロールの列も残し、ボードを作ったときの持ち主の
  行には、これまでどおり owner を書く（列の CHECK が求める）。表は所有者の絞りと
  一緒に #496 で畳む。マイグレーションを伴う変更を、共有を外す変更と同じ PR に
  しないため（#491）。招待済みの行が残っていても、その人はログインできないので
  実害は無い。

### 「この Project に書けるか」は残す

`GET /api/boards/{id}/access` の `projectAccess`（ADR 0017）は残す。1 人で使って
いても、GitHub の資格情報に Project への書き込み権限が無いことに、作成を押す前に
気づける。GitHub の 403 を専用のエラー（`forbidden_project`）に写すことも残す。
**判定ではなく状態として見せる**扱いはそのまま（中核思想 3）。

### 共有が使えるかを返す値も外す

`GET /api/capabilities` の `sharing` と、その理由（`sharing_not_configured`）を
消す。押す前に理由を見せる先（共有のダイアログ）が無くなる。

### ログインを通す相手は、まだ一覧で受ける

ADR 0105 は、ユースケース層だけは通す相手を一覧で受け、共有を外すときに 1 人へ
戻すとしていた。共有のテストが 2 人目のログインを要るためだった。

**ここでは戻さない。** 2 人目のログインを要るテストは、共有のほかにも残っている。
MCP の許可が利用者ごとに分かれること（ADR 0076）と、ボードを所有者で絞ること
（ADR 0016）を見るテストで、どちらも 2 人がログインして互いのものが見えないことを
確かめている。戻すと、畳む予定の仕組みのテストを、畳む前に書き直すことになる。
それぞれを畳むとき（#494・#496）に 1 人へ戻す。組み立て口
（`etoki.NewAuthenticator`）が渡すのは、これまでどおり 1 人だけ。ADR 0105 の該当の
節にも印を付けた。

## 採らなかった案

- **ロールを契約に残し、いつも owner を返す。** 契約は変えずに済むが、意味の無い
  値が残り、#496 でまた触ることになる。
- **owner の行だけを通す。** 招待済みの行を無効にする守りは残るが、ロールの概念が
  1 つ（owner か否か）だけ残り、#496 でまた外すことになる。守る相手（ログイン
  できる 2 人目）もいない。
- **ADR 0017・0078 を置き換え済みにして、生き残る判断をこの ADR に書き写す。**
  写す量が多く、採らなかった案と経緯が元の ADR から読めなくなる。生き残る判断は
  元の ADR の中に残し、置き換えた節にだけ印を付ける。

## 結果

- 403 は、GitHub の側の拒否（`forbidden_project`）と cross-site の拒否
  （`cross_site_rejected`、ADR 0013）だけになる。ロール不足の 403 は無い。
- `internal/CLAUDE.md` の「ボードのメンバーと権限」は「ボードの持ち主と権限」に
  名前を変え、所有者の絞りと `projectAccess` の話だけにした。
- ロールで出し分けると書いた ADR の節は、効かなくなる（0034・0041・0042・
  0045・0059・0062・0065・0077・0079・0080・0089・0093）。それぞれの節に印を
  付けた。
- ボードを削除すると、シーンと実行の記録と一緒に `board_members` の行も消える
  ことは変わらない。画面の確認の文からは「メンバー」を外した。
- 共有で招いた人が残っていたボードでも、その人は開けない（ログインできない）。
  一覧や画面に、その人の名前が出ることも無くなる。
