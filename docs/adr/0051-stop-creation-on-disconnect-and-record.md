# 0051: 接続が切れたら作成を止め、作れたぶんは切れない文脈で記録する

ステータス: 採用

## 文脈

作成が途中で失敗しても、作れたぶんは run として記録する（ADR 0009）。この判断は
**エラーが返ってくる経路**を前提にしていた。

実際には、GitHub への書き込みにも記録にもリクエストの `context.Context` を
そのまま渡していた。`net/http` はクライアントの接続が閉じるとこれを切るので、
作成中にタブを閉じる・リロードする・回線が切れると次の順に進む。

1. GitHub への書き込みが途中で止まる（ここまでは ADR 0009 の想定どおり）
2. 記録（`SaveRun`）にも同じ切れた文脈が渡り、トランザクションを始められない
3. **GitHub には draft issue があるのに、run が 1 件も残らない**

記録が無いので 3 状態は `uncreated` のまま。開き直した開発者は何も作られて
いないと判断して作り直し、取り消せない draft issue が重複する。ADR 0009 が
いちばん避けたかった状態に、例外ではなく日常の操作で入っていた（#140）。

停止も同じ形だった。`Shutdown` は処理中のハンドラを待つだけで文脈を切らないので、
猶予（10 秒）を超えた作成はプロセスごと終わり、やはり記録が残らない。

画面も止めていなかった。離脱の確認（ADR 0021）は未保存のときだけ出る。解釈が
保存を要求するので、作成を押す時点ではふつう保存済みで、作成中に閉じても何も
訊かれない。

## 決定

**接続が切れたら GitHub への書き込みを止め、作れたところまでを記録する。**

- **記録はリクエストの文脈から切り離す。** 取り消しだけを外し（`WithoutCancel`）、
  待つ長さには上限を置く。1 件でも書けたら、接続が切れても記録は残る。結末は
  `incomplete`、理由は切れたこと（ADR 0043 の形のまま）。
- **次の 1 件に手を付ける前に、文脈が切れていないかを見る。** 止めるのを GitHub
  クライアントに任せない。`port.GitHubClient` は差し替えられる公開面で
  （ADR 0001）、切れた文脈で失敗するかどうかは実装しだいになる。
- **停止では、猶予が尽きる前にリクエストの文脈を切る。** 猶予の半分で切り、
  残り半分で止まった作成が記録まで終わるようにする。停止を始めた瞬間には
  切らない。保存のような短い処理まで巻き込むため。
- **作成中も離脱を確認する。** ADR 0021 の対象を「未保存」から「取り消せない
  処理の実行中」まで広げる。閉じれば作成はそこで止まり、結果は閉じた人に
  届かない。

### 採らなかった案：切れても最後まで作る

接続が切れても GitHub への書き込みを続ける案は採らない。

- **画面が結果を受け取れない。** 最後まで作っても、閉じた人が見るのは次に開いた
  ときの状態だけになる。何件作られたのかを読む口は履歴（ADR 0007）しか無く、
  作成が「押した人の知らないところで進む」ことになる（中核思想 3）。
- **止めても失うものが無い。** 作れたぶんは記録され、状態は `created` になり、
  履歴に `incomplete` が残る。残りを作るかどうかは、開き直した開発者が決められる。
- 停止の猶予とも噛み合わない。最後まで作るなら、猶予を作成の最長時間に合わせて
  延ばす必要がある。

## 結果

- 作成中に接続が切れても run は残る。重複の原因になる「作ったのに記録が無い」は、
  DB 自体が書けないときに限られる（そのときは作った item ID をエラーに載せて
  ログに残す、これまでどおり）。
- 停止の猶予が 10 秒のままでも、走っている作成は記録まで終わる。記録に使える
  時間は猶予の残り半分で、ロック待ちが長引かない限り 1 回の書き込みには足りる。
- 作成中にタブを閉じようとすると、ブラウザの確認が出る。
