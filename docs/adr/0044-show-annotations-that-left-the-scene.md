# 0044: シーンから消えた注釈は、別のリストとして見せるだけにする

ステータス: 採用

## 文脈

注釈にした frame をキャンバスから消して保存すると、`GET /api/boards/{id}/annotations`
からその注釈が消える（#111）。`AnnotationService.ListStates` が `scene.Annotations()`
を回して組み立てるので、シーンに無い注釈は結果に現れない。

**記録のほうは消えていない。** `sync_runs` / `sync_items` は残り、GitHub 側の draft
issue も残る。読む口も用意してある——`ListRuns` は**シーンに注釈が残っているかを
見ない**（ADR 0007）。ところが画面がその口を叩くのは注釈カードからだけで、消えた
注釈にはカードが無い。**辿れるように作ってある口に、導線だけが無かった。**

`ListStates` は `ListItemsByBoard` でボード全体の畳み込みを取っておきながら、
シーンに残っている注釈のぶんだけ配って残りを捨てていた。材料は取れている。

GitHub には draft issue が残っているのに etoki の画面からは存在しないことになる、
というのは ADR 0009 が避けたかった状態そのものである。

> 記録されていない draft issue は etoki からは存在しないのと同じで、GitHub を
> 直接見に行くしかなくなる。

## 決定

**捨てていたぶんを返し、見せるだけにする。消しも作り直しもしない**（中核思想 3）。

- **同じ応答で返す。別の口を足さない。** `GET /api/boards/{id}/annotations` の
  応答を `BoardAnnotations`（`annotations` と `detached` の 2 本）にする。
  畳み込みはすでにボード全体で引いているので、**問い合わせは 1 件も増えない。**
  口を分けると、同じ問いを 2 回投げることになる。
- **2 本に分ける。`AnnotationStatus` に混ぜない。** 消えた注釈には
  **比べる相手のテキストがシーンに無い**ので 3 状態が決まらず、frame が無いので
  名前も粒度も取れない。混ぜると、決められない値を埋めるために架空の既定を置く
  ことになり、「名前の無い注釈」（ADR 0022）と見分けが付かなくなる。
  4 つ目の `SyncState` も足さない。3 状態は etoki の中心で、比較の結果ではない
  値をそこへ入れると判定の意味が変わる。
- **見分ける材料は「何を作ったか」と「いつ実行したか」。** 名前は返しようが
  ないので、`items`（畳み込み、ADR 0026）と `lastSyncedAt` を出す。画面は
  そこから run 履歴と Project へのリンク（ADR 0025）へ辿らせる。
- **1 件も作っていない注釈は出さない。** 目的は GitHub に残っているものへ辿れる
  ようにすることなので、辿る先が無いなら出す意味が無い。消した frame の残骸が
  並ぶだけになる。
- **並びは ID 順に固定する。** 畳み込みは map で返るため、揃えないと開き直す
  たびに順が入れ替わる。
- **引き直しても繋がらないことを画面に書く。** frame を引き直すと要素の ID が
  変わるので、以後は別の注釈として扱われる。書かないと「引き直せば戻る」と読める。

## 結果

- frame を消したまま保存して後から気づいても、GitHub に残っているものへ辿れる。
  **消した直後に undo すれば元から戻る**（要素の ID が変わらない）ので、ここが
  効くのは保存してしまったあとだけ。
- 契約が変わる。`GET .../annotations` は配列ではなくオブジェクトを返す。生成物
  （Go / TypeScript）と E2E のモックが同じコミットで揃う（ADR 0011 / 0012）。
- 画面は注釈のカードとは別の節に出す。解釈も作成もできないので、同じ形にすると
  「押せない注釈」が状態の一覧に並ぶことになる。

## 採らなかった案

- **`detached` 専用のエンドポイントを足す。** 追加のリクエストが 1 本増える。
  サーバーはすでに同じ畳み込みを引いており、捨てていただけなので、増やす理由が
  無い。契約を壊さずに済むのは利点だが、単一利用者のローカルツールで、サーバーと
  画面は同じコミットで出ていく。
- **`AnnotationStatus` に `detached: true` を足して 1 本のリストで返す。**
  必須の `name` / `granularity` / `state` を埋められない。埋めれば嘘になり、
  任意にすればシーンに在る注釈のほうまで「無いかもしれない」になる。
- **消えた注釈を etoki が自動で消す（`sync_runs` ごと片づける）。** 取り消せない
  作成の追跡表を、キャンバスの操作をきっかけに自動で捨てることになる（ADR 0007
  と正面からぶつかる）。**畳みたいならボードごと消す手段がある**（ADR 0042）。
- **frame を自動で引き直して復元する。** 要素の ID を etoki が決めることになり、
  「frame は Excalidraw のフレームツールで作らせる」という線（ADR 0036）を越える。
  座標から構造を推測しないのと同じ理由で、消えたものの復元も推測になる。
- **消すときに警告を出す。** 消したことを etoki が知るのは保存されたあとで、
  Excalidraw 側の削除操作には割り込めない。割り込めたとしても、ブレスト中に構造を
  意識させないという中核思想 1 に反する。**気づける形は、消したあとに出す側で持つ。**
