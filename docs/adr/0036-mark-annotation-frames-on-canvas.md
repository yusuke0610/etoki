# 0036: 注釈にした frame はキャンバスに重ねて見分けさせる（要素は変えない）

ステータス: 採用

## 文脈

注釈の判定規則は「`type === "frame"` かつ `customData.etoki` を持つ」であり、
**注釈の frame とユーザーが自分の用途で使った frame が混在するのが前提**
（ルートの `CLAUDE.md`）。frame 単体を条件にすると、ブレスト中に囲んだだけの
frame まで注釈と誤認するので、この規則自体は動かせない。

ところが `markAsAnnotation` は `customData` を足すだけで、**見た目を一切変えて
いなかった。** 注釈にした frame とただの frame がキャンバス上で完全に同じに
見える。前提として混在させておきながら、混在したものを見分ける手段が無い。
パネルには一覧が出るが、名前の無い frame は「注釈 2」と採番されるだけで
（ADR 0022）、キャンバスのどれなのかは押してみるまで分からない。

システムは自動で判断せず状態を見せる（中核思想 3）と言いながら、いちばん基本の
状態が見えていない。

## 決定

- **キャンバスに重ねて見せる。要素には触らない。** 注釈にした frame の位置と
  大きさから矩形を割り出し、Excalidraw の外側に DOM で重ねる
  （`web/src/excalidraw/annotationOverlay.ts` と
  `web/src/board/AnnotationOverlay.tsx`）。粒度もバッジに出す。
- **座標変換はライブラリの `sceneCoordsToViewportCoords` に任せる。** 同じ式を
  書き写すと、ズームの扱いが変わったときに枠だけが取り残される。
- **重ねる枠は押せない。** `pointer-events` を切ってある。飛び先はパネルの
  カードが持っており（ADR 0022）、キャンバス上の操作は Excalidraw のもの。
- **読み上げには出さない**（`aria-hidden`）。同じ情報はパネルが一覧として持って
  いる。二重に読ませると、注釈の数だけ同じ見出しが並ぶ。

## 結果

- 注釈を外すと枠は消える。**戻す処理を持たなくてよい。** 要素を書き換えていない
  ので、外した跡が残りようがない。
- 枠は自分では追従しないので、スクロールとズームのたびに引き直す。`onChange` が
  スクロールとズームでも呼ばれることに依存しており、そこが切れると枠だけが元の
  位置に残る。`web/e2e/annotations.spec.ts` が固定している。
- 見分けが付くのは**保存の有無に関わらず**。判定材料はキャンバスの要素なので、
  注釈にした瞬間に出る。パネルの「状態」欄が保存済みシーン基準であるのとは
  出どころが違う。

## 採らなかった案

- **frame の `name` に印を付ける。** `name` は `content_hash` の入力
  （`internal/domain/scene.go`）なので、見分けるために名前を書き換えると状態が
  「変更あり」に落ちる。見分けたいだけの操作が同期の状態を動かすのはおかしい
  （ADR 0022 で名前を触らないと決めたのと同じ理由）。加えて、ユーザーが手で
  編集できる文字列なので、印だけ消されて `customData` が残る形にもなる。
- **frame の色や線種を変える。** Excalidraw は frame をライブラリ側の定数で
  描いており、要素ごとの色を持たない。要素に書いても描画に効かない。
- **etoki が注釈用の frame を自前で生成する。** frame を Excalidraw のフレーム
  ツールで作らせているのは、境界にまたがる要素の帰属判定をライブラリに任せる
  ため（ルートの `CLAUDE.md`）。見た目のために自前生成へ倒すと、frame を選んだ
  理由が消える。
