# 0077: 「絵解き」は保存を挟み、未保存のときだけ保存してから進む

ステータス: 採用（保存だけの口は ADR 0089）

## 文脈

ADR 0018 は、解釈のテキストを保存済みシーンから、画像を画面から取ると決めた。
2 つを揃えるために、**未保存のあいだは「解釈する」を押せなくした。** その結果、
画面の手順は「右上の『保存』→ 注釈を開く →『解釈する』」になった。

保存が要るのは etoki の都合である。判定も解釈のテキストも保存済みシーンを基準に
しているから要るのであって、解釈を押す人が知っている必要のあることではない。
それなのに、知らないと「解釈する」は押せないままで、理由の文（「保存してから
解釈できます」）を読んで初めて手順が分かる。**使う人が意識しなくてよいことを、
画面が前提にしていた**（中核思想 1）。

詳細で粒度や種別を選び直すと、その場で未保存になる。選び直した直後に「解釈する」
が押せなくなり、右上の「保存」へ手を伸ばしてから戻る往復が、選び直すたびに
起きていた。

## 決定

### 保存を、押した操作の中に入れる

- **右上の「保存」を「絵解き」にする。** 未保存なら保存してから、絵解きの面を
  開く。注釈が 1 件ならその詳細、0 件か複数ならパネルの注釈の一覧を開く。
  右上のボタンはどの注釈かを指していないので、複数あるときに選ぶのは人
  （中核思想 3）。
- **詳細の「解釈する」を「絵解く」にする。** 未保存なら保存してから読む。
  **未保存を押せない理由にしない。** 押せない理由は設定の不足（ADR 0030）だけに
  なる。
- **保存できなかったら、開かない・読まない。** 衝突（ADR 0020）・失敗・排他の
  どれでも同じ。読むと、書けていないシーンのテキストと画面の画像が食い違い、
  ADR 0018 が塞いだ穴を開け直すことになる。理由は保存の失敗として、通知と衝突の
  帯がこれまでどおり言う。
- **保存と一覧の取り直しを待つあいだに変わったら、保存し直してから開く・読む。**
  保存が送るのは押した時点のシーンで、待つあいだの描き足し・粒度の選び直し・
  注釈の付け外しは未保存のまま残る。そのまま読むと、テキストは押した時点の
  シーン、画像はいまのキャンバスになり、同じ穴が開く。そのまま開くと、待つ
  あいだに付けた注釈は保存済みの一覧に無いので、詳細がその場で閉じる。確かめ
  直すのは最後の待ち（取り直し）のあと。
- **保存で消えた注釈は読まない。** 押す前か待つあいだに、フレームを消したか
  注釈から外した場合。保存済みの一覧に無いので詳細は閉じていて、読んでも結果を
  出す先が無い。
- **保存済みの一覧を取り直せなかったら、開かない・読まない。** 開く先も読むか
  どうかも保存済みの一覧で決めるので、前の一覧のままでは決められない。保存が
  要らなかったときも取り直す。手元の一覧は、前の取り直しが失敗していれば古い。
  理由は取得の失敗として通知が言う。

ADR 0018 の「テキストと画像の由来を揃える」はそのまま守る。揃え方が「押させない」
から「保存を挟む」に変わるだけで、**担保が UI 側だけである点も変わらない。**

### 未保存のときだけ保存する

保存は、全部の注釈の引いた解釈と作成の状態を捨てる（保存すると前提のシーンが
変わるため）。押すたびに保存すると、詳細を開き直すたびに前の結果が消え、
引いた解釈を見比べる（#39）ことができなくなる。

未保存のときに保存すれば、押した注釈の前の結果も、ほかの注釈の結果も消える
ことは変わらない。**黙って消さない。** 未保存のあいだは、詳細の本文で「保存して
から読むこと」と「これまでの結果を捨てること」を押す前に言う。

### 自動保存ではない

ADR 0021 は「自動保存もローカルの下書きも持たない」と決めた。ここで入れる保存は
**開発者が押した 1 回の操作に付随するもの**で、時間や変更をきっかけに走らない。
押さなければ保存されないことは変わらない。

中核思想 3（自動で判断しない）にも当たらないと考える。保存は「絵解く」の前提を
整えるだけで、GitHub には何も作らない。**取り消せない操作（作成）には付けない。**
作成は `contentHash` の照合（ADR 0010）で、保存済みと食い違った作成を弾いたまま
にする。

### 保存だけの口は `⌘/Ctrl+S`

ブレストの途中で保存だけをしたいことはある。その口は `⌘/Ctrl+S`（#145）に残す。
右上には保存だけのボタンを置かない。表示は未保存のあいだだけ「未保存」の隣に
出し、**「絵解き」の隣には置かない。** 並べると絵解きのショートカットに読める。

**ADR 0089 で改めた。** キーボードの無い端末では `⌘/Ctrl+S` を押せず、保存の
ために絵解きの面を開くことになっていた（#296）。未保存のあいだ「未保存」の隣に
ふつうの格の「保存」を出し、ショートカットの案内は見える文から外した。

### 言葉は入口だけ変えた（中身は ADR 0086 で揃えた）

この ADR の時点で変えたのは、ボタン（「絵解き」「絵解く」「絵解き直す」）と、
開いた面の見出し（「絵解き」）だけで、「解釈結果」や「解釈できませんでした」の
ような文言は据え置いた。言葉を全体で揃えるかは、パネルの名前を整える作業
（#248）と合わせて決めることにした。

その後、ADR 0086 で画面の中身の言葉も「絵」「絵解き」に揃えた。「解釈結果」は
「絵解きの結果」に、「解釈できませんでした」は「絵解きできませんでした」になった。
コードや契約の名前（`interpret`）は変えない。

読むだけのロールには「絵解き」を出さない。もとの「保存」と同じで、保存も解釈も
できない人に押せないボタンを並べない。注釈の詳細は一覧から読める。

## 採らなかった案

- **未保存のあいだは「絵解く」を押せなくし、隣に理由を出す。** ADR 0066 の形に
  そのまま沿うが、粒度や種別を選び直した直後に行き止まりになる。選ぶ場所が
  詳細にある以上、この往復は詳細を開くたびに起きる。
- **押すたびに保存する。** 上の理由で、開き直すたびに引いた解釈が消える。
- **絵解きの面を本物のモーダル（`<dialog>`）にする。** 開いているあいだ
  キャンバスを触れなくすれば、未保存になる経路は面の中の選び直しだけになる。
  しかし「開いたまま描き足して、解釈し直す」という往復（ADR 0065）を捨てることに
  なる。
- **「保存」を残して「絵解き」と並べる。** 主となる操作が 1 つの面に 2 つ並ぶ
  （#203）。どちらを押せばよいかを読む人に選ばせることになり、保存を意識させない
  という目的が半分しか果たされない。

## 結果

- 「絵解き」→「絵解く」の 2 手で解釈まで進める。保存を知らなくてよい。
- 未保存のまま「絵解く」を押すと、ほかの注釈のぶんも含めて、それまでに引いた
  解釈が消える。押す前に本文で言う。
- 保存は「絵解き」の内側で走るので、保存中は「絵解き」が「準備中…」と、詳細の
  「絵解く」が「絵解き中…」と名乗る。
- E2E の保存は `⌘/Ctrl+S` を通す。右上の「絵解き」を押すと面やパネルが開き、
  保存だけを確かめたい spec の前提が変わるため。
