# 0091: 図のドラフト生成もサーバー側のジョブにし、会話はジョブの入力から戻す

ステータス: 採用

## 文脈

解釈は ADR 0085 でサーバー側のジョブにしたが、図のドラフト生成はリクエストに
結びついたままだった（#329）。生成は解釈と同じ枠（ADR 0044）を取るので、生成中に
ボード一覧へ戻ると #307 と同じことが起きる。

- 画面は会話を忘れ、サーバーは生成を続けて枠を握る。戻って生成し直すと 429。
- 枠は解釈と共有なので、そのあいだは解釈も 429。

解釈と違って、図のドラフトは**会話（往復）を持つ。** 会話はフロントのメモリに
しか無い（ADR 0041）ので、ジョブにして結果だけを戻しても、どの指示への答えかが
分からない。

## 決定

### 解釈と同じ形にし、置き場を共有する

始めるのと受け取るのを別のリクエストにする。読んでも消えない・捨てるのは明示的な
操作・状態はメモリだけ・見えるのは始めた本人のそのボードのジョブだけ・開いたときに
1 回だけ引く、はどれも ADR 0085 と同じ理由で同じにする。

**置き場は解釈と 1 つにする。** 止める手（取り消しと上限時間）、枠を戻してから
終わりを書く順、panic をジョブの失敗にすること、他人のジョブを見せないことは、
どちらでも同じでなければならない。2 つに書くと、片方だけ直したときに枠を握った
まま残るジョブができる。

### 同じものを返すのは、入力が丸ごと同じときだけ

走っている最中に同じ入力が来たら、新しく始めずにそのジョブを返す（ADR 0085 と
同じく、二度課金しない）。**同じかどうかは、種類・指示・往復・下の印のすべてで
見る。** 指示だけで見ると、往復が違うのに走っている答えが返り、送った会話と違う
答えが積まれる。どこか 1 つでも違えば、枠に弾かれる（429）。

### ジョブは自分の入力を返し、画面はそこから会話を戻す

ジョブは始めたときの入力（種類・指示・往復）を持ち、一覧と取得で返す。開き直した
画面は、受け取っていないジョブの入力から、会話を「送っている最中」の形に戻す。
送った指示も入力欄に戻す。送っている最中の画面は、送った指示が入力欄に残ったまま
止まっているので、それと同じにする。

**会話を保存するのではない。** ADR 0041 は変えない。ジョブが入力を持つのは、
そのジョブが捨てられるまで（受け取ったら捨てる、終わってから 1 時間）。受け取った
あとの会話は、これまでどおりボードを離れたら消える。ADR 0041 が保存しない理由に
挙げた「誰の会話か」「他のメンバーに見えるか」は、ジョブが操作者ごとに閉じている
（ADR 0085）ので立ち上がらない。

採らなかった案:

- **結果だけを戻す。** どの指示への答えかが分からない。#329 で問いとして挙げた
  とおり。
- **会話を画面の外（App）に持つ。** リロードやタブを閉じると消え、走っている
  ジョブの答えがまた行き場を失う（ADR 0085 が画面の外に state を持つ案を採らな
  かったのと同じ理由）。
- **受け取ったあとも最新のジョブを残し、会話の置き場にする。** 会話をサーバーに
  持つことになり、ADR 0041 を変える。困っていたのは走っている生成で、そこを
  超える。

### 変換の投げ直しの印を契約に載せる

置けなかった図の投げ直しは、変換器の英語のメッセージを含むので、画面では固定文に
置き換えている（`web/CLAUDE.md`）。これまで印は画面だけが持ち、サーバーには
送らなかった。ジョブから戻した会話で印が消えると、**投げ直しが利用者の指示として
並ぶ。**

印を契約に `internal` として載せる。サーバーはプロンプトに使わず、預かって返す
だけ。

採らなかった案: **戻すときに、文言の形で投げ直しを見分ける。** 利用者が同じ文を
書けば外れる。推測で決める判定を、確かめる手段の無いところに置くことになる。

### 直前のドラフトは戻さない

走っている生成や、失敗した生成を戻したとき、直前のドラフトは出さない。残りの
往復を数えるのはサーバーで（ADR 0041）、ジョブが返すのは今回の結果のぶんだけ。
往復の mermaid からドラフトを組み立てると、残りの回数をフロントで数えることになる。

代償として、戻した直後に前の図を置くには、結果を待つか送り直す必要がある。

## 帰結

- `generateDiagramDraft` の応答が 200（ドラフト）から 202（ジョブ）に変わる。
  ドラフトの形は変わらず、`DiagramJob.result` に入る。
- LLM の呼び出しの失敗を記録する場所が、ジョブの置き場の 1 つになった。リクエストの
  中で記録していた httpapi の `failLLM` は無くなった（ADR 0087 の「記録する場所」）。
- 図への指示の入力欄は、パネルではなくフック（`useDiagramDraft`）が持つ。戻した
  指示を入れる先が要る。
- 走っている生成を画面から止める口は無い。種類を変えると、会話ごと捨てて止まる。
