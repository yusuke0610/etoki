# 0021: 未保存のまま離れる直前に確認を出す（自動保存も下書きも持たない）

ステータス: 採用

## 文脈

保存は明示操作である。自動同期・自動更新・自動作成を実装しないという中核思想
どおり、シーンも開発者が「保存」を押したときにだけ書く。

一方で、離脱を止める仕組みが何も無かった。`beforeunload` の登録もローカルへの
下書き保存も無いので、未保存のままリロード・タブを閉じる・戻るを踏むと描いた
ものが全部消える。画面には「未保存」バッジが出ているが、バッジは離脱を止めない。

ブレストは etoki の最初のフェーズなので、ここで失うと注釈・解釈・作成が全部
やり直しになる。

## 決定

**自動保存も、ローカルへの下書き保存も入れない。離脱の直前に確認を出す。**

- `dirty` のあいだだけ `beforeunload` を登録する。リロード・タブを閉じる・戻るは
  アプリ側で止められないので、ブラウザに確認させるしかない。
- キャンバスが外れる導線（ボードの切り替え、新しいボードの作成先選択、ログアウト）
  では `window.confirm` で確かめる（**ADR 0100 で改めた。** 作成先は選ばずに
  ボードを作り、描いたあとでキャンバスを外さないダイアログで選ぶので、作成先の
  選択はキャンバスが外れる導線ではなくなった）。**確認は外す前に置く。** 外してから訊いても、
  そのときには消えている。
- **確認と外すことのあいだに待ちを挟まない。** 挟むと、待っているあいだに描き足した
  ぶんを確認なしで捨てる。ボードの切り替えは「取ってから訊く」（取得を待ってから
  確認し、そのまま差し替える）。ログアウトは訊いた直後にキャンバスを外し、通信は
  その後で待つ。
- **未保存かどうかは ref で持つ。** state だと、待ちを挟んだ判定が待ち始めた時点の
  値を見る。判定に使うだけで表示には出ないので、再描画も要らない。
- 断られたら何もしない。承諾されたらそのまま捨てる。**確認の裏で保存しない。**
  捨てるつもりの試し描きまで残ると、保存が明示操作である意味が無くなる。

**自動で保存しないと決めた以上、失う直前に知らせる責任が対になる。** 明示保存は
「押し忘れが起きない」という前提の上に成り立っていない。押し忘れは構造的に起きる。

## 結果

未保存の内容が黙って消えることは無くなった。代わりに、離れるたびに確認が出る場面が
増える。出るのは `dirty` のあいだだけなので、保存してから離れる限り目に入らない
（**#432 で改めた。** 手直しした下書きがあるあいだも出る。保存済みでも出る。
下の追記）。

`beforeunload` の文面はブラウザが決める。アプリから渡した文字列は表示されないので、
何を失うのかは `window.confirm` を出せる側（ボードの切り替え）でだけ説明できる。

「未保存かどうか」はキャンバスを持つ `BoardPage` が決め、離れる導線は `App` が
持っている。判断の材料を親に上げる形にしてあり、`App` から `dirty` を作り直しては
いない。作り直すと「未保存」の定義が 2 箇所になる。

## 追記（#432、手直しした下書き）

**手直しした下書きも、失う直前に確認を出す対象に入れる。** 絵解いた結果の下書きは
フロントのメモリにしか無く（#39）、タイトルや本文を手直ししたあとに離れると、
手直しの手間と、もう一度絵解く料金と待ち時間を失う。保存しないと決めたもの（シーンの
自動保存も下書きの保存もしない）を失う直前に知らせる、という上の責任は同じく
ここにも掛かる。

- **確認を出す場面は 2 つ。** 離れる前（上と同じ導線と、作成先の選び直し。
  **ADR 0100 で改めた。** 選び直しはキャンバスを外さないダイアログになったので
  訊かない）と、保存の前。保存は引いた解釈を捨てる（`discardAfterSave`）ので、手直しした下書きも
  消える。保存の前の確認は、保存の入口そのもので訊く。押した保存を呼ぶ側で
  包むと、包みを通らない口（失敗の通知の「再試行」）から確認なしに保存される。
  **下書きは保存しない。** 確認の裏で保存しないのと同じく、下書きを
  サーバーにもローカルにも置かない。置くかどうかは、確認で足りないと分かってから
  決める。
- **訊くのは手直ししたときだけ。** 「手直しした」は、まだ送っていない項目の
  タイトル・本文・種別・「更新する / 新しく作る」を変えたこと。選択の変更は、その
  下書きからまだ何も作っていないあいだだけ数える（作ったあとの選択は作った残りで、
  失っても困らない）。絵解いたままの下書きで訊くと、確認に慣れて読まなくなる。
  判定は純関数 1 つ（`draftEdited`）に置く。
- **失うものを言い分ける。** 未保存のシーンは描いた内容を、下書きは手直しを失う。
  両方あれば両方を言う。`App` には未保存と別の口（`onDraftsEditedChange`）で
  上げる。1 つに畳むと文言を分けられない。
- **下書きは `DraftEditor` が持ったまま、手直ししたかだけを上げる。** 下書きを
  `BoardPage` に上げると、保存と絵解き直しの両方に破棄を書き足すことになる
  （`DraftEditor` の doc）。外れるときに下ろすので、捨てられた手直しが確認を出し
  続けることは無い。

**残したもの。** 絵解き直す・引いた解釈を選び直すと、その注釈の手直しは確認なしに
消える。押した本人がその場で手直しを見ている操作で、ここでは足していない。保存で
捨てる範囲を、中身が変わった注釈だけに狭める案（作成の照合と同じ contentHash で
残せる）も、「保存は解釈を捨てる」という画面の約束を変えるので別に決める。
