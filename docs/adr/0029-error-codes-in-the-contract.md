# 0029: エラーは契約の code で表し、文言は画面が持つ

ステータス: 採用

## 文脈

エラーの表し方が 3 層に散っていた。

**画面**は日本語をコンポーネントにべた書きしていた。同じ「取得できませんでした」が
5 通りの書き方で存在し、`String(e)` が `ApiError: etoki: insufficient role` を
そのまま出す箇所もあった。理由を組み立てる `describe` は 1 ファイルの private
関数で、他の画面からは使えなかった。

**サーバー**は `errorJSON` に 1 本化されていて `ErrorResponse` にも揃っていたが、
本文は `err.Error()` をそのまま流していた。`etoki: board target is locked` のような
Go の内部文言が境界を越えて画面に出ていた。**写し替え（sentinel error → HTTP
ステータス）は 5 箇所**にあった。

問題は文言の散らばりよりも、**ステータスだけでは打ち手が決まらない**ことにある。

| 409 の原因 | 利用者がすべきこと |
| --- | --- |
| `ErrSceneConflict` | いまの内容を控えて開き直す |
| `ErrTargetLocked` | 作成先はもう変えられない（諦める） |
| `ErrContentHashMismatch` | 解釈からやり直す |
| `ErrPreviousItemUnknown` | 解釈からやり直す |
| `ErrAlreadyMember` / `ErrLastOwner` | 入力を変える |

403 も 2 つある。`usecase.ErrForbidden`（etoki のロール不足 → owner に頼む）と
`port.ErrForbidden`（GitHub が拒んだ → リポジトリの権限）で直す場所が違う。
**この 2 層を分けて持つと決めてある**（ADR 0017）のに、画面に出た時点で区別が
消えていた。

画面でこれを分けようとすると `e.message` の文字列照合になる。つまり **Go の
エラー文言が事実上の API 契約**になっていた。境界の定義は OpenAPI に置くと決めた
（ADR 0011）のに、エラーだけがそこから漏れていた。

## 決定

**失敗の原因は契約の `code` で表す。文言は持たせない。**

### `code` は必須にする

`ErrorResponse` に `ErrorCode`（enum）を足し、**required にする。** 任意にすると、
足し忘れた経路だけが対応表から漏れて静かに既定の文言に落ちる。必須なら
`errorJSON` の引数になり、忘れるとコンパイルエラーになる（`internal/CLAUDE.md`
の認可と同じ「忘れたら気づける形で持つ」）。

`error` は残す。GitHub や LLM が返した本文が実際の手掛かりになる経路がある。
**ただし利用者向けの文言ではないので、画面は既定で畳む。**

**`*_not_configured` を 1 つに畳まない。** 設定するものが違う
（`ETOKI_LLM_API_KEY` / `ETOKI_GITHUB_TOKEN` / GitHub App）ので、畳むと画面が
「何を設定すればよいか」を言えなくなる。

### Go 側は 1 表に畳む

`internal/httpapi/errors.go` に sentinel → (status, code) の表を 1 つだけ置く。
5 つの `fail*` は表を引くだけにした。**5 つは互いに素で、同じ sentinel が別の
ステータスに写る箇所は無かった**ので畳める。エンドポイントごとに残るのは
**表に無かったときの既定だけ**で、GitHub を叩く一覧取得だけが 502、それ以外は
500 になる。

ログの出し分けは畳まない。どのエンドポイントで何を記録するかは写し替えとは
別の判断で、表に混ぜると「記録するために表を引く」ことになる。

Go の内部文言（`etoki: ...`）は**書き換えない**。表示に出なくなるので直す理由が
無い。ログと開発者向けの手掛かりとしてそのまま使う。

### 画面は code → 日本語を 1 モジュールで持つ

`web/src/api/errorMessage.ts` に `Record<ErrorCode, string>` と純関数を置いた。
`web/src/board/roles.ts` の `ROLE_LABELS` と同じ形で、**`Record` にすることが
担保**になる。`ErrorCode` は生成物なので、契約に code を足して文言を書き忘れると
`tsc` が落ちる。

各コンポーネントが持つのは**操作の名前**だけ（`保存できませんでした`）。原因の
文言は表から来る。`ApiError` に `code` を持たせ、401 の特別扱い（ログイン画面へ
落とす）も `code === "login_required"` の上に載せ直した。

**`ApiError.code` は `ErrorCode` ではなく `string` で持つ。** サーバーが画面より
新しいと、まだ知らない code が来る。型で締めると知らない値を「知っている」ものと
して扱うことになり、対応表から漏れたことに気づけない。知らない code のときだけ、
サーバーの本文をそのまま前に出す。

### 表示は「打ち手が先、手掛かりは畳む」

`ErrorNotice` を 1 つ置き、`message`（何をしようとして、次にどうするか）を出して
`detail`（サーバーの本文）は `<details>` に畳む。**捨てはしない。** GitHub の
レート制限や LLM の設定不足は、本文にしか手掛かりが無い。

`CreatedRun.error`（部分失敗の本文）には code を足さない。1 件ずつ理由が違いうる
ので 1 つの code に落ちない。**畳んで見せる扱いだけ揃える。**

### i18n の仕組みは入れない

文言は日本語のみ。対応表が 1 箇所になったので、必要になってから差せる。

## 結果

同じステータスでも打ち手ごとに違う文が出るようになった。`ErrorResponse` の
`code` が必須なので、写し替えを足し忘れるとコンパイルが通らず、文言を足し
忘れると `tsc` が落ちる。

**表そのものの取りこぼしはコンパイラでは防げない**ので、`internal/httpapi/
errors_test.go` が `usecase` と `port` のソースから `Err*` を数え直し、表に無い
sentinel があれば落とす。境界に出てこない 2 つ（`port.ErrConflict` /
`port.ErrAlreadyExists`）は理由つきで除外してある。ユースケース層が自分の
エラーに写し替えて返すので、ハンドラまで届かない。

E2E のモック本文は生成型で縛ってあるため（ADR 0012）、`code` の追加で全部が
`tsc` に落ちた。**モックだけが古い契約のまま緑になる、が起きていないことの
確認になっている。**

残したもの:

- **衝突の範囲は写し替えだけ。** 同じ code でも、画面の場面によって出したい文が
  違う場面は出てくる（例: 404 が「ボードが無い」なのか「メンバーの解除先が無い」
  なのか）。いまは操作の名前で吸収している。足りなくなったら、場面ごとの上書きを
  対応表の外に置く。
- **`badRequest` だけは表を引かない。** ボディのバインドはユースケース層に届く
  前に落ちるので sentinel を持たない。ここだけハンドラが code を決める。
