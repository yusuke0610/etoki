# 0012: E2E はバックエンドを起動せず、契約の型でモックする

ステータス: 採用

## 文脈

3 状態の表示と「開発者が押したときだけ動く」という約束は、複数のレイヤを
またいで初めて成立する。ハンドラの単体テストと vitest では、注釈カードの中に
状態バッジが出ることや、解釈するまで作成ボタンが現れないことを確かめられない。

一方で etoki の主要な操作は外部サービスに繋がっている。解釈は LLM を呼び、
作成は GitHub Projects v2 に書き込む。実物に繋ぐと、テストが API キーと
ネットワークに依存し、しかも作成は取り消せない。

## 決定

**Playwright で E2E を書き、バックエンドは起動せず `page.route` で差し替える。**

確かめたいのは画面側の約束であって、外部連携そのものではない。外部連携は
アダプタの単体テストとフェイク実装が受け持つ。E2E がそこまで担うと、遅くて
壊れやすいテストが一式増えるだけになる。

モックの応答本文は `web/src/api/types.ts`（OpenAPI の生成物）で型を付ける。
E2E の典型的な嘘は「モックだけが古い契約のまま緑になる」ことなので、そこを
型で塞ぐ（ADR 0011）。`tsconfig.json` の `include` に `e2e` を足してあるのは
このためで、外すと仕組みが働かなくなる。

ルートのマッチングはグロブではなくパス名の述語で行う。Vite の dev サーバーは
`/src/api/types.ts` も配信するため、パスの途中に `api` を含むグロブだと
アプリ自身のソースまで傍受してしまう。

ブラウザは nixpkgs の `playwright-driver.browsers` を devShell から渡す
（`PLAYWRIGHT_BROWSERS_PATH`）。`playwright install` にダウンロードさせると、
そこだけ `flake.lock` の外でバージョンが決まる。**その代わり
`web/package.json` の `@playwright/test` は `playwright-driver` と同じ
バージョンに固定する必要がある。** 揃っていないと、Playwright が要求する
リビジョンのブラウザが見つからず E2E が起動しない。

`make test` には含めない。`make test` は保存のたびに回せる速さを保ちたい。
E2E はコミット前と CI で回す。

## 結果

- 画面の約束（3 状態の表示・解釈してからでないと作成できない・途中失敗の
  見せ方・保存で解釈結果を捨てる）が実ブラウザで固定された。
- 外部サービスとの繋ぎ込みそのものは E2E では検証されない。アダプタの
  単体テストが落ちれば分かる、という前提に乗っている。
- `nix flake update` が `playwright-driver` を動かしたら、`@playwright/test`
  も同じバージョンに上げる必要がある。片方だけ動かすと E2E が起動しない。
- キャンバスの操作は Excalidraw のショートカットに依存する。ライブラリ更新で
  ショートカットが変わると `scene.spec.ts` が落ちる。
