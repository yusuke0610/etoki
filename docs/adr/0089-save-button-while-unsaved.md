# 0089: 保存だけの口を、未保存のあいだ「未保存」の隣にボタンで出す

ステータス: 採用

ADR 0077 の「保存だけの口は `⌘/Ctrl+S`」を改める。

## 文脈

ADR 0077 で右上の「保存」を「絵解き」にし、保存だけの口は `⌘/Ctrl+S` にした。
**タッチ端末（スマホ・タブレット）にはキーボードが無い**ので、保存するには
「絵解き」を押すしかなかった。押すとパネルか詳細が開き、スマホでは全面が
それで覆われる。描き続けるには閉じて戻る（#296）。

- ブレストする人が、保存のために絵解きの入口を押すことになる（中核思想 1）。
- 自動保存しない（ADR 0021）ので、押し忘れは構造的に起きる。保存の口が重い
  ほど、離れる前の確認に頼る場面が増える。
- タブレット（重ねる置き方）では、押せない「`⌘/Ctrl+S` で保存」の案内が出て
  いた。スマホの帯では CSS で隠していた。

ADR 0077 はタッチ端末に触れていなかった。ADR 0075 は「機能は幅で絞らない」と
決めていたが、保存だけの口はキーボードの有無で絞られていた。

## 決定

### 未保存のあいだ、「未保存」の隣に「保存」を出す

- **右上の島（スマホでは上の帯の 1 段目）に、未保存のあいだだけ「保存」を
  出す。** 押すと保存だけをする（`⌘/Ctrl+S` と同じ）。絵解きの面もパネルも
  開かない。
- **保存済みのあいだは出さない。** 押しても書くものが無い。「未保存」の印と
  一緒に出て一緒に消えるので、印とボタンが同じ状態を言う。
- **ふつうの格にする。** 主となる操作は「絵解き」の 1 つのまま（#203 の
  「1 つの面に 1 つ」）。
- **幅でも入力の種類でも出し分けない**（ADR 0075 の「別の境目を持たない」）。
  キーボードのある端末でも出す。キーボードの有無は画面から確かめられず、
  タブレットにキーボードを付ける人もいる。
- 読むだけのロールには出さない。「絵解き」と同じで、保存できない人に押せない
  ボタンを並べない。

### `⌘/Ctrl+S` は残し、案内は読み上げにだけ渡す

ショートカットはそのまま効く。**見える文の案内（「`⌘/Ctrl+S` で保存」）は
やめ、ボタンの `aria-keyshortcuts` で伝える。** 見える文にすると、キーボードの
無い端末で押せない口を案内することになる。端末で出し分けると、上の「出し分け
ない」に当たる。

見える案内が消えるぶん、ショートカットを画面から知る手段は減る。それでも
よいとしたのは、保存の `⌘/Ctrl+S` が OS をまたいだ慣習で、知らずに押しても
効くから。口そのものはボタンで見えている。

### 押せない理由は 1 つを両方から指す

「保存」と「絵解き」はどちらも保存を始めるので、同じ式で止まる（取り込み中・
作成中、`web/src/board/exclusion.ts`）。**理由は 1 つだけ出し、2 つのボタンから
`aria-describedby` で指す。** 2 つ並べても、止めている操作も待てば解けることも
同じなので、読む量が増えるだけになる。

**文は両方に当てはまる形にする**（「作成が終わるまで保存も絵解きもできません」）。
片方の名前だけを言うと、もう片方が押せない理由が読めない。

### 「絵解き」は保存を挟んだまま

ADR 0077 の決定（未保存なら保存してから開く・読む、未保存のときだけ保存する）は
変えない。絵解く人が保存を知らなくてよいことも変わらない。改めるのは「右上には
保存だけのボタンを置かない」の 1 点だけ。

### どの ADR の記述が生きているか

ADR 0065・0066・0075 は保存を独立した口として書いたままで、ADR 0077 は置き換えを
明記していなかった（#296）。この ADR で次のとおりに揃える。

- **ADR 0065** の「『未保存』と『保存』は、メニューにもパネルにも入れず右上に
  出す」、**ADR 0066** の「保存は右上」、**ADR 0075** の「1 段目に保存」と「保存を
  押せるので、パネルも詳細もモーダルにしない」は、**再び当てはまる。** 違うのは、
  保存が未保存のあいだだけ出て、隣に「絵解き」が並ぶことだけ。
- **ADR 0077** の「保存だけの口は `⌘/Ctrl+S`」と「右上には保存だけのボタンを置か
  ない」は、**この ADR で置き換える。**

## 採らなかった案

- **タッチ端末でだけ「保存」を出す。** ADR 0075 の「別の境目を持たない」に
  当たる。タッチの有無（`pointer: coarse` など）はキーボードの有無と一致しない。
- **メニューに「保存」を置く。** ADR 0066 は、待たされる操作は外に置くと
  決めた。保存はいちばん押すもので、メニューを開く 1 手が毎回増える。スマホでは
  メニューの入口が下にあり、上の「未保存」から遠い。
- **`⌘/Ctrl+S` の案内をタッチ端末で出さないことだけを直す。** 保存のたびに
  絵解きの面が開く重さは残る。
- **「未保存」の印そのものを押せるようにする。** 押せるものに見えず、名前が
  「未保存」では押すと何が起きるのかが読めない。
- **保存済みのあいだも「保存」を出す。** 押しても書くものの無いボタンが、
  「絵解き」の隣に残り続ける。押せば変更が無いまま保存が走り、引いた解釈を
  捨てる（ADR 0077）。
- **主となる操作（緑）にする。** 1 つの面に主となる操作が 2 つ並ぶ（#203）。
  ADR 0077 が「保存」と「絵解き」を並べる案を採らなかった理由はこれで、ふつうの
  格なら当たらない。

## 結果

- タッチ端末でも、絵解きの面を開かずに保存できる。
- 未保存のあいだ、右上には「保存」と「絵解き」の 2 つのボタンが並ぶ。主となる
  操作は「絵解き」のまま。
- 「保存」から保存しているあいだも、「絵解き」は「準備中…」と名乗る。どこから
  始めても保存中は両方が止まり、それぞれが自分の名前で待っていることを言う。
- **E2E で保存だけを確かめるときは、引き続き `⌘/Ctrl+S` を通す**（`saveScene`）。
  「保存」は未保存のあいだしか出ないので、保存済みのまま保存を走らせる spec では
  使えない。
