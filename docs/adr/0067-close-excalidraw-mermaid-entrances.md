# 0067. Excalidraw 自身の mermaid の入口を閉じる

- 状態: 採用
- 日付: 2026-09-29

## 背景

etoki は mermaid を描く前にいくつか守りを掛けている。置けない形（画像 1 枚）は
置かない（ADR 0040）。固定した mermaid 11.13.0 に残る脆弱性は、「mermaid に渡る
文字列は本人のプロンプトから LLM が作ったものだけ」という理由で受け入れた
（ADR 0061）。

**この守りは etoki の口にしか掛かっていなかった**（#187）。Excalidraw 0.18.1 は
自分でも mermaid を描く口を持っていて、そこから入った文字列は etoki を通らない。
ヘッドレス Chromium で確かめた。

| 入口                                             | 0.18.1 での状態                                                                          |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| ツールバーの「その他」→「Mermaid to Excalidraw」 | **出ていて開ける。** 任意の mermaid を書いて描ける                                       |
| キャンバスへのテキストの貼り付け                 | **mermaid らしい文字列は勝手に変換される。** `gantt` を貼ると画像 1 枚として置かれた     |
| コマンドパレットの「Mermaid to Excalidraw...」   | 項目はあるが、パレット自体をライブラリが置かず export もしないので、etoki には出ていない |

貼り付けは issue を調べている途中で見つけた。ダイアログと違って**開く操作すら
要らない。** 設計の文書から mermaid をコピーしてキャンバスに貼るのは自然な操作で、
そのまま受け付けない種類（gantt / xychart など、描くだけでタブが固まるもの）や
設定の前置き（`%%{init: …}%%`）まで通る。固まると、自動保存を持たない（ADR 0021）
ので未保存のブレストが消える。

## 決定

**3 つとも閉じる。** etoki の口と同じ用途の、守りの無い口を並べておく理由が無い。
既存の設計を持ち込む口は etoki 側に作る（#181）。

### 「その他」メニューの項目は CSS で隠す

0.18.1 はこの項目を props で消させない。`UIOptions.tools` は `image` しか持たず、
`aiEnabled={false}` でも残る（同じメニューの AI 項目は消えるのに、これだけ条件が
付いていない）。隠す手段は CSS しか残らない。

**セレクタは脆い。** 項目の `data-testid` は隣の Web 埋め込みと同じ
`toolbar-embeddable` で使えないので、mermaid のアイコンだけが持つ `viewBox` で
見分けている。項目の上の「Generate」見出しも隠す。`aiEnabled={false}` のもとでは
この項目のためだけに残り、中身の無い見出しになる。

ライブラリにパッチを当てる案（`bun patch`）は採らない。項目を消す 1 か所では
済まず、貼り付けの分岐も書き換えることになる。版を上げるたびにパッチを当て直す
ことになり、当たらなくなったときの気づき方は CSS と変わらない（E2E）。

### 貼り付けは `onPaste` で止める

Excalidraw は `onPaste` を呼んでから mermaid の判定に進むので、ここで `false` を
返せば変換の前で止まる。判定は Excalidraw の `isMaybeMermaidDefinition` と同じに
する。**元は export されていないので写す**（`web/src/excalidraw/excalidrawMermaid.ts`）。

**広げても狭めてもいけない。** 狭めると漏れた分が守りなしで描かれ、広げると
普通の文字の貼り付けまで止まる。写しが元と揃っていることは、配布物の本文から
元の一覧と組み立て方を読んで比べるテストが見ている。

**止めたことは黙らない。** 貼っても何も起きないと、貼り損ねたのか弾かれたのか
区別が付かない。文言は「キャンバスに直接貼れない」ことと、文字のまま置くなら
テキストの入力中に貼ればよいこと（そこは Excalidraw が変換に回さない）。
貼った文字列を etoki の貼り付け（#181）に渡す形は、そちらが入ってから足す。

### コマンドパレットには `aiEnabled={false}` を渡しておく

いまは出ていないので効いていない。パレットの「Mermaid to Excalidraw...」は
`aiEnabled` で出し分けられているので、ライブラリがパレットを置くようになった日に
守りの無い口が黙って開かないよう、先に閉じておく。etoki は Excalidraw の AI 機能
（テキストからの図・マジックフレーム）を使っていないので、失うものは無い。

### ライブラリを上げたら戻りうることは E2E で見る

どれも Excalidraw の UI に外から手を入れているだけで、版が変われば黙って戻る。
`web/e2e/excalidrawMermaid.spec.ts` が、メニューに項目が出ていないこと、
パレットが開かないこと、mermaid を貼っても描かれないこと、普通の文字は貼れる
ことを見る。

## 結果

- ADR 0061 が受け入れの理由にした前提（mermaid に渡るのは LLM が作ったものだけ）が、
  固定を入れた時点から成り立っていなかった。0061 の、受け入れの理由を書いた箇所の直後に訂正を追記した。
- Excalidraw を上げるときに見るものが増える。落ちるのは上の E2E と
  `excalidrawMermaid.test.ts` で、どちらも「写しと隠し方を見直す合図」。
- ダイアログそのものは残っている。開発者ツールでキャンバスの状態を書き換えれば
  開きうる。それができるのは自分の画面を自分で壊せる本人だけで、ADR 0061 の
  受け入れと同じ範囲に収まる。
