# 0050: 通しの確認は偽の上流で手元から行い、偽物はアダプタとの往復で守る

- 状態: 採用
- 日付: 2026-09-14

## 背景

各層はそれぞれ固めてある。Go はフェイク実装で、E2E はバックエンドを起動せず
`page.route` で差し替える（ADR 0012）。その結果として、**フロント → Gin →
ユースケース → アダプタ → HTTP という並び全体を一度も通していなかった。**
ADR 0012 自身が「外部サービスとの繋ぎ込みそのものは E2E では検証されない」と
書いている。

その隙間に落ちるものがあった。フォントを外部 CDN へ取りに行く #114 と、
途中失敗が履歴に残らない #110 は、手元で通しを動かして初めて見え、どちらも
各層の単体テストは緑のままだった（#115）。

実物の GitHub と LLM に繋げば通しは動くが、鍵とネットワークが要り、作成は
取り消せない（ADR 0009）。気軽に何度も回せるものにならない。

## 決定

### 偽の LLM と偽の GitHub に向けて、実物のバイナリを動かす

`make try-fake` が偽の上流（`cmd/etoki-fakeupstream`）とビルド済みの etoki を
一緒に起動する。etoki は `ETOKI_LLM_BASE_URL` と `ETOKI_GITHUB_BASE_URL` を
偽物へ向けるだけで、コードに偽物のための分岐を持たない。

### CI にも `make test` にも入れない

**ADR 0012 の判断は覆さない。** 要るのは「しばらく触らなかったあとで、いま何が
壊れているかを 1 コマンドで確かめる導線」で、保存のたびに回すテストではない。
ブラウザを伴う通しを CI に入れると、ADR 0012 が避けた遅くて壊れやすいテストが
そのまま増える。CI で回すかどうかは、手元の導線を使ってみてから別に決める。

### 偽物が追うのは本物の API ではなく、etoki のアダプタが送るもの

偽の GitHub を本物に似せるほど確かめられる範囲は広がるが、**似せた偽物が
古くなると「緑なのに本物では落ちる」を偽物の側に作る**（ADR 0012 が E2E の
典型的な嘘として挙げたもの）。本物のスキーマに追いつき続けることはできない。

そこで、似せる範囲をアダプタが送るクエリと読むフィールドに限り、腐りは次の
2 つのテストで検知する。どちらも `make test` に入る。

- **本物のアダプタを偽物に向けた往復テスト**（`internal/fakeupstream`）。
  アダプタのクエリを変えて偽物が答えられなくなると落ちる。
- **本物の解釈メッセージに対する契約テスト**（`internal/usecase`）。偽の LLM は
  粒度と前回ぶんの ref をメッセージから読むので、文言を変えて読めなくなると
  落ちる。

**本物の GitHub と一致していることは、これでは確かめられない。** そこは
アダプタの単体テストと、実物に繋いだときの確認のまま残る。

### 状態はメモリだけ、DB は毎回作り直す

偽物に永続化を持たせると、偽物の中に「GitHub 側の記録」という 2 つめの正本が
できる。持たせない代わりに、`make try-fake` は起動のたびに一時ディレクトリへ
DB を作る。DB を使い回すと、記録が指す draft issue が偽物の側に無く、更新が
必ず失敗する。

### 本物の鍵を偽物へ流さない

`make try-fake` は `.env` を読まず、認証と鍵の変数を外して起動する。App を
設定していると認証の構成に入り、偽物ではログインできない。PAT の構成だけを
通しの対象にする。

### `ETOKI_GITHUB_BASE_URL` は GHES に向けられるとは言わない

開けた理由は偽物に向けるためで、GHES に向けるためではない。「GHE では
差し替える」という既存の doc は外した。etoki には認可側（`auth/github`）の
ホストを差し替える口が無く、アダプタが送る REST と GraphQL のパスを GHES で
確かめたこともない。**確かめていない向け先を、設定できるふりで持たせない。**

`.claude/rules/validation-boundaries.md` は「GHES のホストは `BaseURL` を設定する
導線を作るときに一緒に開ける」と言っているが、今回は開けない。GHES の利用者が
いない段階で認可と REST の経路まで開けると、確かめようのない設定が増える。
開けるときは、認可のホストと合わせて 1 つの変更にする。

## 結果

- 手元で作成 → 変更あり → 更新までを、鍵もネットワークも無しで通せる。
- 図のドラフト生成は通しの対象外。偽の LLM は解釈と同じ JSON を返すので、
  画面では mermaid として読めずに失敗する。
- GitHub App の構成（ログインとインストール経由のリポジトリ一覧）は通せない。
- 偽物が本物からずれていても、アダプタと往復できている限りテストは緑になる。
  それを受け入れる代わりに、偽物の保守が本物のスキーマに引きずられない。
