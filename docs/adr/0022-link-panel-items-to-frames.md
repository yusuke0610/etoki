# 0022: パネルの項目とキャンバスのフレームは選択で結ぶ

ステータス: 採用

## 文脈

ボードに複数のフレームを作ると、**注釈パネルのどの項目がキャンバスのどの
フレームなのか分からない。** 見分ける手がかりが 1 つも無い。

- 「選択中のフレーム」欄はボタンの文言（`このフレームを注釈にする`）しか
  出しておらず、複数を選ぶと完全に同一の項目が並ぶ。
- 「状態」欄の見出しは frame の `name` で、Excalidraw の frame は**既定で名前を
  持たない**（`name: null`）。名前を付けない限り全部が「（名前なし）」になる。
- パネルとキャンバスを結ぶ操作が無い。押しても何も起きず、キャンバスで選んでも
  パネルは変わらない。

名前を出せば済む話に見えるが、そうではない。**Excalidraw は名前の無い frame を
`Frame` としか描かず、採番もしない**（`getFrameLikeTitle` は `name === null` の
とき定数を返す）。つまりキャンバス側にも見分ける手がかりが無く、名前を軸にする
限り「どちらの `Frame` か」は決着しない。

名前付けを必須にする案は採らない。**ブレスト中に構造を意識させない**のが
etoki の前提であり（中核思想 1）、囲んだ端から命名を求めるのはその逆を行く。

## 決定

- **対応づけの主役は選択にする。** 状態欄のカードの見出しを押すと、キャンバスが
  そのフレームへ寄って選択される（`scrollToContent` と `updateScene`）。逆に
  キャンバスでフレームを選ぶと、対応するカードが強調される（`.selected` と
  `aria-current`）。名前に一切依存しないので、名前を付けていなくても必ず対応が
  分かる。
- **名前の無い注釈には etoki が番号を振る。** 一覧上の位置で「注釈 2」と出す
  （`web/src/board/annotationLabel.ts`）。採番は**名前の有無に関わらず位置で**
  行う。名前ありを飛ばして数えると、番号が一覧の位置を指さなくなる。
- **この番号はキャンバスのラベルとは一致しない。** キャンバス側は名前なしを
  すべて `Frame` と描くので、揃えようがない。番号は一覧の中で項目同士を指し分け
  るためだけのものであり、どのフレームかを確かめる手段は前項のクリックのほう。
- **まだ注釈でない frame には番号を振らない。** 一覧に並んでいないため位置を
  持たない。名前が無ければ「名前のないフレーム」と出す。意味の違う番号が同じ
  画面に 2 種類出るのを避ける。
- **キャンバスに無い注釈のカードは押せなくする。** 状態は保存済みシーンが基準
  なので、未保存で消したフレームの注釈が一覧に残る。押しても飛び先が無いので、
  理由を本文で出して `disabled` にする。

## 結果

- 名前を付けていなくても、押せばどのフレームか分かる。ブレスト中に命名を
  強いない前提（中核思想 1）を崩さずに済む。
- **未保存にはならない。** 選択とスクロールは appState 側の話で、未保存の判定
  （`sceneSignature`）は要素の `version` と `customData` しか見ない。ここが
  変わると、カードを押しただけで「保存してから解釈できます」に落ちる
  （ADR 0018）。`web/src/excalidraw/dirty.test.ts` が固定している。
- 番号が 2 つの意味を持たないよう、採番は注釈の一覧だけが持つ。frame 側に
  採番を足したくなったら、この ADR ごと見直す。

## 採らなかった案

- **Excalidraw と同じ表示名を再現する。** 再現しても全部 `Frame` になるだけで、
  見分けられない。
- **パネルからフレームをリネームさせる。** frame 名は `content_hash` の入力
  （`internal/domain/scene.go`）なので、見分けるために名前を付け直すと状態が
  「変更あり」に落ちる。見分けたいだけの操作が同期の状態を動かすのはおかしい。
- **座標の近さでキャンバスとパネルを結ぶ。** 構造を座標から推測しない
  （中核思想 2）。frame の帰属は Excalidraw が持っている。
