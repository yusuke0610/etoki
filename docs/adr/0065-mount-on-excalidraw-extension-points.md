# 0065. 画面の部品は Excalidraw の拡張点に載せ、配色は変数で上書きする

- 状態: 採用
- 日付: 2026-09-29

## 背景

ボードが全面キャンバスになる（ADR 0064）。etoki のもの——ボード名・状態・保存・
たまに押す操作・注釈パネル——をどこに置くかを決める必要がある。

素直な案は、自前の島を `position: absolute` でキャンバスの上に重ねることだった。
しかしキャンバスの上には**すでに Excalidraw 自身の島が浮いている**（メニュー・
ツールバー・ライブラリ・ズーム・ヘルプ）。隣に自前の島を並べると、角丸・影・
ボタンの高さ・フォント・狭い画面での振る舞いを、こちらで合わせ続けることになる。
**見た目を揃えるために始めた見直しが、揃わない部品を増やすところから始まる。**

もう 1 つ、開く場所がばらばらな問題がある。メンバーは上から帯、図のドラフトは
左から縦、注釈は右。**開くたびにキャンバスの形が変わり、Excalidraw のツール
バーの位置まで動く。**

`@excalidraw/excalidraw` 0.18.1 は `MainMenu` / `Sidebar` / `Footer` /
`WelcomeScreen` / `Button` を export している。**拡張点が公開されている以上、
自前で似たものを作るのは、揃えるための仕事を自分で増やすことになる。**

## 決定

### 拡張点に割り当てる

| 置くもの                                                 | 拡張点                   |
| -------------------------------------------------------- | ------------------------ |
| 注釈 / 図のドラフト / メンバー                           | etoki の右パネル         |
| 注釈 1 件の解釈の結果と、下書きの手直し                  | キャンバスの上の中央の面 |
| たまに押す操作と、一覧へ戻る導線                         | `MainMenu`               |
| 常に見える状態（ロール・作成先・確定しているか・大きさ） | `Footer`                 |
| ボード名・未保存・保存                                   | `renderTopRightUI`       |

**パネル 3 つは拡張点に載せず、etoki の右パネルにタブで並べる。** 開く場所を
1 つにすることが目的で、それは自前のタブでも果たせる。`Sidebar` に載せなかった
理由は下の「採らなかった案」。**1 度開いたタブは描いたまま隠す。** 切り替えても
手直し中の下書きが消えないようにするためで、初めて開くまでは描かない（押した
ときだけ引く約束を崩さない）。

**解釈の結果と下書きの手直しは、右パネルから出してキャンバスの上に広く開く。**
カードの中に出していたころは、手直しまで含めると 1 件で画面数枚分に伸び、
**ほかの注釈の状態というパネルの主題が読めなくなった。** 解釈と作成はブレストが
終わったあとの開発者のフェーズなので（中核思想 1）、キャンバスを一時的に覆っても
筋が通る。カードには「解釈する」と「解釈結果を開く」だけを残す。

- **画面は止めない（モーダルにしない）。** 解釈は「解釈する → 見比べる → 粒度を
  変えて解釈し直す」を行き来する作業で、止めると右パネルの粒度も右上の保存も
  触れなくなる。
- **1 度開いた注釈の面は描いたまま隠す。** 右パネルのタブと同じ理由で、閉じた
  だけで手直しが消えないようにする。
- **Excalidraw の UI より下に重ね、`.excalidraw` の外に置く。** 上に重ねると、
  左上から開くメニューが面の下に潜る。中に入れると色の変数がぶつかり、axe が
  色を判定できない（下の 2 つ）。

**「未保存」と「保存」は、メニューにもパネルにも入れず右上に出す。** いちばん
押すものと、隠してはいけない状態なので、他の切り替えに巻き込まれない場所に置く
（ADR 0064 の「状態は隠さない」、ADR 0066）。**ボード名を隣に置く。** 何を保存
するのかがボタンの隣で読める。左上には差し込む口が無く、右上の
`renderTopRightUI` が上端で使える唯一の口だった。

### 配色は Excalidraw の変数を上書きする

`--color-primary` から派生する変数と `--color-selection` を差し替える。これらは
`.excalidraw` と `.excalidraw.theme--dark` という単純なクラス選択子で定義されて
いるので、外から差し替えられる。**何をいくつ差し替えるかはここに数えない。**
ライブラリが増やしたり名前を変えたりするもので、写せばこちらだけが古くなる。

**`--color-primary` から導かれていない変数もある。** スライダーの軌道やロゴの
文字色がそれで、派生するものだけを差し替えると**そこだけ元の色が残る。** 差し替
える対象は「`--color-primary` の系統」ではなく「画面に出る色」で選ぶ。

**`:root:root .excalidraw` で書く。** `index.css` は Excalidraw の CSS より先に
読まれるため（`main.tsx` → `App.tsx` の順）、特異性が同じなら後に読まれた
ライブラリ側が勝つ。**`:root` を 1 つ足すだけでは足りない。** ライトは
`.excalidraw`、ダークは `.excalidraw.theme--dark` で定義されていて、後者とは
クラス 2 つぶんで並ぶだけになり、**ダークだけ元の色に戻る。** 2 つ重ねて超え
させる。

**ライブラリと同じ名前の変数を、etoki が持っていることがある。** ライブラリは
`.excalidraw` に自前の変数を多数持っていて、etoki の役割名とぶつかるものがある
（`--color-brand-hover`、`--color-warning`、`--color-danger`、`--color-success`
など）。**キャンバスの中に置いた etoki の部品は、ライブラリの値のほうを読む。**
右上の「未保存」がライブラリの薄い黄色になり、ほぼ読めなくなった。

- ブランドは etoki 側を `--brand-*`（`--color-` なし）で持つ。同じ名前で上書き
  すると、指定が自分自身を指して壊れる（循環参照になって値が落ちる）。
- 状態の色は、値を `--etoki-*` に持ち、中に置いた部品でだけ戻す。外では役割名の
  `--color-*` をそのまま読めるので、規則は書き換えずに済む。

**ぶつかる名前は、どれか 1 つに気づいた時点で全部を洗う。** 1 つずつ見つけて
いると、画面の色が変わったことにしか気づく手がかりが無い（下の axe を参照）。

**`--color-selection` はキャンバスの選択枠の色で、CSS 変数から読まれている。**
注釈の印を Excalidraw の選択色に合わせてある判断（`web/src/index.css`、ADR 0036）
は、両方を同じ値に差し替えることで保てる。片方だけ変えると、印と選択が別の色に
なって、合わせた理由が消える。

### 書体は Excalidraw の UI に揃える

etoki の画面の書体の先頭を、Excalidraw の UI と同じ Assistant にする（#203）。
キャンバスのメニューにはライブラリの項目と etoki の項目が並ぶ。英数字の字形が
違うと、2 種類の部品が混ざって見える。

**Assistant には日本語の字形が無い。** 日本語は後ろに並べた OS の書体で出るので、
1 つの文の中で和文と欧文の書体が分かれる。それでも揃えるのは、日本語は前から
どちらも OS の書体で、違って見えていたのが英数字だけだったため。

Assistant はライブラリが同梱していて、`App.tsx` が読む CSS の `@font-face` から
etoki 自身の配信元で配られる。**外へ取りにいかない**（キャンバスのフォントと同じ
約束、#114）。

### ADR 0055 の「切り替えの口」を読み替える

ADR 0055 は「テーマの切り替えの口は Excalidraw のメニューだけ」と決めた。理由は
**同じ意味の口が 2 つ並ぶのを避けること**で、メニューそのものを指していたわけ
ではない。

`MainMenu` の中身を etoki が決めるようになるので、テーマはその中の 1 項目になる。
**口は 1 つのままなので、0055 の理由は満たされている。** 値を持つのが App の
`useTheme` だけであることも変わらない。

### axe の除外を絞り直す

axe は `.excalidraw` を除いて掛けている（`web/e2e/helpers/a11y.ts` の
`expectNoAxeViolations`）。ライブラリ自身の DOM に etoki は手を入れられない
ためだった（ADR 0039）。

**`MainMenu` や右上・下の帯に etoki の中身を入れると、それが `.excalidraw` 配下に
入って検査の外に落ちる。** 除外はライブラリ自身が描く部品に限り、etoki が書いた
中身は掛ける側に残す。**ここを直さずに移すと、検査が静かに減る。**

**ただし、戻した部品の色のコントラストは axe では判定できない。** ライブラリの層に
重なっているので axe は背景色を決められず、違反ではなく「判定不能」に回す。上の
薄い黄色も axe は通した。**構造の検査（名前、`aria-describedby` の指す先）は
効くが、色は効かない。** 色は「キャンバスの外で同じ変数を読んだときと同じ色か」を
比べて守る。値を書き写して比べると、配色を変えた日にそこだけが古くなる。

## この判断を見直すとき

Excalidraw を上げたときに、拡張点の形か変数の名前が変わりうる。**変数名が変わると
色だけが元に戻り、テストは緑のまま通る。** 更新 PR（ADR 0035）で上がってきたとき
は、画面を開いて色を確かめる。

## 採らなかった案

- **自前の島を重ねる。** a11y の検査範囲は今のままで済むが、見た目を手で合わせ
  続けることになり、狭い画面の振る舞いも自前で持つ。揃わない部品が増える方向
  なので、今回の目的と逆を向いている。
- **`Excalidraw` を包んで etoki の UI に置き換える。** 包まない判断は既にある
  （ADR 0027）。拡張点に載せるのは包むことではなく、ライブラリが用意した口を
  使うだけなので、この判断とは衝突しない。
- **配色を Excalidraw の紫のままにして、etoki 側だけ変える。** 画面の大半が
  ライブラリの描くものなので、揃わない色が最も広い面積に残る。
- **解釈の結果をモーダルで開く。** 焦点の閉じ込めと背景の無効化をブラウザに
  任せられるが、開いているあいだ粒度を変えることも保存することもできず、
  解釈し直すたびに閉じて開き直すことになる。
- **解釈の結果を右パネルの 4 つ目のタブにする。** 開く場所は 1 つのままだが、
  幅が 320px のままなので、下書きのタイトルと本文が切れる問題が残る。
- **注釈・図のドラフト・メンバーを `Sidebar` に載せる。** この ADR の最初の版は
  こう決めていた。実装の前に調べると、`Sidebar` は**閉じると中身ごと外れ**、
  **タブを切り替えても隠れたタブの中身は外れる。** 解釈結果と図の会話は
  `BoardPage` が持っているので残るが、**手直し中の下書き・図への指示の書きかけ・
  招待の途中は、タブを切り替えただけで消える。** 作成は取り消せない（ADR 0009）
  ので、直す前の中身に戻ったことに気づかずに押すとそのまま作られる。持ち上げれば
  防げるが、`.excalidraw` の中に入れば色の変数がぶつかり、axe は色を判定できない
  （上の 2 つ）。見た目と狭い画面の振る舞いがライブラリに揃う利点より、失うものが
  大きい。
