# 0065. 画面の部品は Excalidraw の拡張点に載せ、配色は変数で上書きする

- 状態: 採用
- 日付: 2026-09-29

## 背景

ボードが全面キャンバスになる（ADR 0064）。etoki のもの——ボード名・状態・保存・
たまに押す操作・注釈パネル——をどこに置くかを決める必要がある。

素直な案は、自前の島を `position: absolute` でキャンバスの上に重ねることだった。
しかしキャンバスの上には**すでに Excalidraw 自身の島が浮いている**（メニュー・
ツールバー・ライブラリ・ズーム・ヘルプ）。隣に自前の島を並べると、角丸・影・
ボタンの高さ・フォント・狭い画面での振る舞いを、こちらで合わせ続けることになる。
**見た目を揃えるために始めた見直しが、揃わない部品を増やすところから始まる。**

もう 1 つ、開く場所がばらばらな問題がある。メンバーは上から帯、図のドラフトは
左から縦、注釈は右。**開くたびにキャンバスの形が変わり、Excalidraw のツール
バーの位置まで動く。**

`@excalidraw/excalidraw` 0.18.1 は `MainMenu` / `Sidebar` / `Footer` /
`WelcomeScreen` / `Button` を export している。**拡張点が公開されている以上、
自前で似たものを作るのは、揃えるための仕事を自分で増やすことになる。**

## 決定

### 3 つの拡張点に割り当てる

| 置くもの                                 | 拡張点     |
| ---------------------------------------- | ---------- |
| 注釈 / 図のドラフト / メンバー           | `Sidebar`  |
| たまに押す操作と、一覧へ戻る導線         | `MainMenu` |
| 常に見える状態（ロール・作成先・大きさ） | `Footer`   |

`Sidebar` はタブとドックの切り替えを持っているので、**開く場所が 1 つになり、
狭い画面での振る舞いもライブラリ側が持つ。**

**「未保存」と「保存」だけは拡張点に載せず、独立した島で右上に出す。** いちばん
押すものと、隠してはいけない状態なので、他の切り替えに巻き込まれない場所に置く
（ADR 0064 の「状態は隠さない」、ADR 0066）。

### 配色は Excalidraw の変数を上書きする

`--color-primary` から派生する変数と `--color-selection` を差し替える。これらは
`.excalidraw` と `.excalidraw.theme--dark` という単純なクラス選択子で定義されて
いるので、外から差し替えられる。**何をいくつ差し替えるかはここに数えない。**
ライブラリが増やしたり名前を変えたりするもので、写せばこちらだけが古くなる。

**`:root .excalidraw` で書く。** `index.css` は Excalidraw の CSS より先に読まれる
ため（`main.tsx` → `App.tsx` の順）、同じ `.excalidraw` で書くと後勝ちで負ける。
特異性を 1 つ上げて、読み込み順に依存しない形にする。

**`--color-selection` はキャンバスの選択枠の色で、CSS 変数から読まれている。**
注釈の印を Excalidraw の選択色に合わせてある判断（`web/src/index.css`、ADR 0036）
は、両方を同じ値に差し替えることで保てる。片方だけ変えると、印と選択が別の色に
なって、合わせた理由が消える。

### ADR 0055 の「切り替えの口」を読み替える

ADR 0055 は「テーマの切り替えの口は Excalidraw のメニューだけ」と決めた。理由は
**同じ意味の口が 2 つ並ぶのを避けること**で、メニューそのものを指していたわけ
ではない。

`MainMenu` の中身を etoki が決めるようになるので、テーマはその中の 1 項目になる。
**口は 1 つのままなので、0055 の理由は満たされている。** 値を持つのが App の
`useTheme` だけであることも変わらない。

### axe の除外を絞り直す

axe は `.excalidraw` を除いて掛けている（`web/e2e/helpers/a11y.ts` の
`expectNoAxeViolations`）。ライブラリ自身の DOM に etoki は手を入れられない
ためだった（ADR 0039）。

**`Sidebar` と `MainMenu` に etoki の中身を入れると、それが `.excalidraw` 配下に
入って検査の外に落ちる。** 除外はライブラリ自身が描く部品に限り、etoki が書いた
中身は掛ける側に残す。**ここを直さずに移すと、検査が静かに減る。**

## この判断を見直すとき

Excalidraw を上げたときに、拡張点の形か変数の名前が変わりうる。**変数名が変わると
色だけが元に戻り、テストは緑のまま通る。** 更新 PR（ADR 0035）で上がってきたとき
は、画面を開いて色を確かめる。

## 採らなかった案

- **自前の島を重ねる。** a11y の検査範囲は今のままで済むが、見た目を手で合わせ
  続けることになり、狭い画面の振る舞いも自前で持つ。揃わない部品が増える方向
  なので、今回の目的と逆を向いている。
- **`Excalidraw` を包んで etoki の UI に置き換える。** 包まない判断は既にある
  （ADR 0027）。拡張点に載せるのは包むことではなく、ライブラリが用意した口を
  使うだけなので、この判断とは衝突しない。
- **配色を Excalidraw の紫のままにして、etoki 側だけ変える。** 画面の大半が
  ライブラリの描くものなので、揃わない色が最も広い面積に残る。
