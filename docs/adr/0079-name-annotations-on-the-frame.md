# 0079: 囲みの名前は絵解きの面で付け、frame の name にそのまま書く

ステータス: 採用

## 文脈

名前の無い囲みは、一覧で「絵1」「絵2」と補った見出しで出る（ADR 0078）。
この番号は一覧の中の位置で、キャンバスのラベル（名前が無ければ Excalidraw が
`Frame` と描く）とは一致しない（ADR 0022）。どの囲みかは、カードを押して
キャンバスを寄せるまで分からない。

名前を付ける手段は Excalidraw のフレームのラベルをダブルクリックすることだけで、
etoki の画面からは気づけなかった。囲みの名前は解釈の入力でもあるので、絵解く
直前に整えたいのに、その場（絵解きの面）では触れなかった。

## 決定

### 名前は絵解きの面で付ける

名前も解釈の入力なので、「絵解く」を押す直前に整えられる場所に置く。読むだけの
ロールでは変えられない。

**口は見出しの隣の名前そのもの**（#305）。最初は粒度と種別の隣に「名前」の欄を
置いたが、見出しの隣にすでに名前が出ているので、同じ名前を二度見せることに
なっていた。いまは名前のラベルを押すとその場で欄になり、確定すると見出しが
新しい名前になる（保存を待たない。キャンバスの値を出す）。常設の欄は無い。
変えられないとき（読むだけ・注釈から外した・キャンバスに無い）は押せるものに
せず、理由は本文に出す（ADR 0039）。焦点は Enter と Escape のあとだけラベルへ
戻し、欄を離れて確定したときは奪わない。書く口が書けなくなった対象には、
書きかけを確定しない（入力した名前が黙って消えるため）。

### 書く先は frame の `name` そのもの

- **キャンバスのラベルにも同じ名前が出る。** 一覧とキャンバスの名前が揃い、
  どの囲みかが番号ではなく名前で分かる。
- **名前は解釈の入力に入るが、`content_hash` には入らない**（#303）。frame の
  `name` は解釈の入力のテキストとして先頭に足される（`internal/domain/scene.go` の
  `AnnotationTexts`）が、ハッシュは子のテキストとメタデータだけから出す
  （`AnnotationHash`）。名前だけを変えても状態は変わらず、次に絵解いたときに
  新しい名前で読まれる。

#### 名前とハッシュ（#303 で改めた）

最初は名前をハッシュにも入れ、作成済みの囲みの名前を変えると「変更あり」になる
ことを受け入れていた。名前は解釈の材料なので、変えたものを「変わっていない」と
扱う理由が無い、という判断だった。見出しの下にも「変えると『変更あり』に
なります」と添えていた。

使ってみると、名前を直しただけの囲みが「変更あり」に落ち、状態を戻す道が
絵解き直し（LLM を呼び、作成まで通す）しか無かった。run を書けるのは解釈と作成
だけで（ADR 0007）、解釈は課金され、回数と同時実行の上限（ADR 0044）にも数える。
読むだけのロールは押せない。**見出しを整えただけの操作に、その費用を払わせる
理由が無い。**

- **外すのは囲み自身の名前だけ。** 子のテキスト、粒度、図の種別はこれまでどおり
  ハッシュに入る。どれも LLM が読むものを変える。
- **解釈の入力からは外さない。** 名前は見出しであると同時に、何の囲みかを伝える
  材料でもある。名前だけ変えた囲みを絵解き直すかは開発者が選ぶ（中核思想 3）。
  「絵解く」は状態に関わらず押せる。
- **代償は導入時に一度だけ払う。** 名前を付けた作成済みの囲みは、記録した
  ハッシュに名前が入っているので、導入した時点で一度だけ「変更あり」に見える。
  名前の無い囲みは入力が同じなので変わらない。ADR 0047 で種別を足したときと
  同じ形で、中身は変わっていないので、更新するかどうかは開発者が選ぶ。記録した
  ハッシュを書き換えて揃える案は採らない。run は実行の記録で（ADR 0007）、
  あとから書き換えると何を確かめて作ったのかが分からなくなる。
- **作成時の照合（ADR 0010）は名前の変更で止まらない。** 解釈と作成のあいだに
  名前だけ変わっても作成は通り、作られるのは確認した下書き（解釈した時点の
  名前で読んだもの）になる。照合が守るのは、確かめた中身と違うものを作らない
  ことで、名前は中身ではなくなった。

### 確定したときだけ書く

- 確定は Enter か、欄を離れたとき。1 文字ごとに書くと、打つたびに未保存になり、
  「元に戻す」に 1 文字ずつ積まれる。
- **変換中の Enter では書かない。** 日本語の変換を確定する Enter で書くと、変換の
  途中の名前がキャンバスに載る。
- **Escape は書きかけを捨てるだけにする。** 書きかけが無いときだけ面を閉じる。
  書きかけを捨てたつもりで面ごと閉じると、何を捨てたのかが見えなくなる。
- **「絵解く」は押しても焦点を奪わない。** 欄を離れた瞬間に未保存になると、
  本文に保存の案内（ADR 0077）が出て帯が下へずれ、押し始めたボタンが指の下から
  逃げる。書きかけは、押した処理の中で確定してから読む。

## 採らなかった案

- **表示用の名前を `customData.etoki` に別に持ち、`content_hash` から外す。**
  名前を変えても状態は変わらないが、注釈のメタデータの形は Go と TypeScript の
  2 箇所に同じものがあり（ルートの `CLAUDE.md`）、共有のテストデータ、契約、
  ハッシュの仕様まで動く。導入した時点で、既存の囲みが一斉に「変更あり」に
  見えないかも確かめ直すことになる（ADR 0047 で一度起きた）。キャンバスの
  ラベルには出ないので、一覧との食い違いも残る。#303 で名前をハッシュから
  外したときも、置き場所は `name` のまま、ハッシュの入力だけを変えた。
- **名前だけの変更なら、絵解かずに「作成済み」へ戻す操作を置く**（#303 で検討）。
  名前を変えたら「変更あり」に落ちる仕組みはそのまま残り、戻すたびに人が押す。
  戻す run を書くには結末（ADR 0043）を決める必要もあり、何も作っていない run が
  履歴に並ぶ。
- **入力するたびに書く。** 上の理由で、未保存と「元に戻す」が 1 文字ずつ動く。

## 結果

- 名前を付けた囲みは、一覧・絵解きの面・キャンバスで同じ名前になる。
- 作成済みの囲みは、名前を変えても「作成済み」のまま。新しい名前を GitHub の
  item に反映したいなら、絵解き直して更新する。
- パネルの中の「注釈」という語（「注釈 3 件」など）は、この作業でも変えていない。
  画面の名前を「絵解いた」「絵N」にした（ADR 0078）あとで、その語で使う人が
  迷うかを画面で確かめてから決める。
