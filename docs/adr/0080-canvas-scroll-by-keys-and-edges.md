# 0080: キャンバスの移動を etoki が足す（矢印キーと、ドラッグ中の端）

ステータス: 採用

## 文脈

キャンバスの移動に、2 つの不便があった（#250）。

1. **要素をドラッグしたまま画面の外へ運べない。** 端に寄せてもキャンバスが
   流れないので、広いボードで囲みを遠くへ動かすには、離してスクロールし、
   掴み直す必要があった。
2. **何も選んでいないとき、矢印キーで何も起きない。** 読むだけのロール
   （`viewModeEnabled`）では矢印キー自体が効かない。キーボードでボードを
   見て回る手段が無かった。

Excalidraw 0.18.1 はどちらも持っていない。スクロールを動かすのはホイール・
手のひら・スクロールバー・PageUp/PageDown だけで、矢印キーは選んだ要素を
動かすためにしか使われない。props で足す口も無い。

## 決定

**どちらも etoki の側で足す**（`web/src/board/useCanvasScroll.ts`）。量を
決める純関数は `web/src/board/canvasScroll.ts` に置く。

### 矢印キー

- **何も選んでいないときだけ使う。** 選んだ要素があれば、矢印キーはそれを
  動かすためのもの。
- **焦点がキャンバスの枠そのもの（`.excalidraw-container`）か、どこにも無い
  ときだけ使う。** 枠の中の部品（ツールバーのラジオ、メニュー）と etoki の
  部品（右のパネルのタブ、入力欄、ダイアログ）は矢印キーを自分で使う。
  「`.excalidraw` の中なら」と広く取ると、ツールの選択を矢印で移れなくなる。
- **修飾キー付きは使わない。** ⌘/Ctrl+矢印はフローチャートの図形を足す
  Excalidraw のショートカット。
- **読むだけのロールでも使える。** 見て回る手段がほかに無い。描かせない約束
  （ADR 0017）は要素についてのもので、見る位置には掛からない。

### ドラッグ中の端

- **要素をドラッグしているあいだ**（`selectedElementsAreBeingDragged`）、
  ポインターが見えているキャンバスの端の帯に入ったら、深さに比例した速さで
  流す。範囲選択や図形を描いている途中では流さない。
- **端は見えているキャンバスの枠で測る。** 重ねる置き方（ADR 0075）では右の
  パネルが浮いているので、その左の縁を右端にする。パネルの下を端にすると、
  パネルに重なるまで運ばないと流れない。
- **流すたびに、同じ位置で `pointermove` を 1 つ投げる。** Excalidraw は掴んだ点
  からのずれを `pointermove` のたびにシーンの座標で測り直して要素を置くので、
  ポインターを止めたまま流すと要素がシーンに残って離れていく。投げた
  `pointermove` を Excalidraw が新しいスクロールで測り直し、要素が付いてくる。

## 採らなかった案

- **Excalidraw の内部（`App` の `translateCanvas` など）を直に呼ぶ。** 公開されて
  おらず、届く手段は React の内部を辿ることしか無い。スクロールは公開の
  `updateScene` で足りる。
- **キャンバスの外（etoki の部品）にも矢印キーを効かせる。** 焦点がタブや
  入力欄にあるときに奪うと、そちらの操作が壊れる。キャンバスを押せば焦点は
  枠に戻る。
- **端で流すのを frame だけにする。** 運びたいのは frame に限らず、仕組みも
  同じになる。

## 結果

- **Excalidraw の内部の振る舞いに寄りかかる。** 当てにしているのは 3 つ。
  ドラッグの `pointermove` を `window` で聞いていること、その `target` は
  HTML 要素であることしか見ないこと、要素の位置を「掴んだときの位置 + ずれ」で
  決めていること。どれも公開の約束ではないので、**Excalidraw を上げたら
  `web/e2e/canvasScroll.spec.ts` で確かめる。** 崩れると、要素がポインターに
  付いてこなくなる。
- 矢印キーで見る位置を動かしても、未保存にはならない（スクロール位置は保存が
  書かない、`web/CLAUDE.md`）。
