# 0086: 画面の語彙を「絵」「絵解き」に揃え、「フレーム」は Excalidraw の枠だけを指す

ステータス: 採用

## 文脈

ADR 0077 と 0078 は、入口の名前だけを使う人の言葉に変えた。右上のボタンと
詳細のボタンは「絵解き」「絵解く」、パネルのタブは「絵解いた」、名前の無い
囲みの見出しは「絵1」、キャンバスの印は「絵」になった。中身の言葉
（「注釈 3 件」「を注釈にする」「解釈結果」「解釈できませんでした」）は、画面で
確かめてから決めるとして据え置いた（ADR 0077 / 0078 / 0079）。

try-fake を初めて使う人の順に通して確かめたところ、1 つの流れの中で同じものの
呼び名が変わっていた（#294）。「名前のないフレーム を注釈にする」を押すと、
カードは「絵1」になる。押した操作とできたものの名前が違うので、同じものだと
結びつけにくい。失敗の文は「解釈できませんでした」で、押したボタンは
「絵解く」である。

## 決定

### 画面に出る「注釈」は「絵」、「解釈」は「絵解き」にする

- **「注釈」→「絵」。** 「絵 3 件」「〈名前〉を絵にする」「〈名前〉を絵から外す」
  「保存済みの絵はありません」「キャンバスに無い絵」。
- **「解釈」→「絵解き」。** 「絵解きの結果」「絵解きできませんでした」
  「絵解きのあとにボードが変わりました。絵解きからやり直してください」。
- 失敗の文言は `web/src/api/errorMessage.ts` の中だけで直す（ADR 0034）。
- 機械的に置き換えると日本語として通らないものは、言い方を変える。
  「注釈を付け外し」は「フレームを絵にしたり外したり」、「解釈では既存の
  draft issue の更新でした」は「絵解きの結果では、既存の draft issue の更新でした」。

### 「フレーム」と「絵」の役割を分ける

- **「フレーム」は Excalidraw のフレームツールで引いた枠そのもの**を指す。
  「選択中のフレーム」「名前のないフレーム」「フレームツール（F）で囲んで」は
  そのまま残す。囲むのは人で、etoki はその枠を作らない（ADR 0047）。
- **「絵」は、etoki が絵解きの対象として扱うフレーム**を指す。「フレームを絵に
  する」が 2 つの境目になる。ブレスト中に引いたフレームのすべてが絵になるわけ
  ではない（ルートの `CLAUDE.md` の判定規則）ので、2 つの語を 1 つに畳まない。
- 中核思想 1 に従い、新しい語には issue / epic を持ち込まない。「draft issue」
  「epic」のような GitHub の語は、GitHub に作るものを指す場面でそのまま使う。

### 識別子は据え置く

コード・契約・ADR の語（`annotation`、`interpret`、`AnnotationStatus` など）は
変えない。理由は ADR 0078 と同じで、画面の名前は使う人に向けたもので今後も
変わりうる。追随させると、契約と生成物が動き、変更の範囲が画面の外へ広がる。
ADR の本文でも「注釈」「解釈」は識別子に対応する語として使い続ける。

コメントも対象にしない。コメントは識別子の側の語で読むものなので、画面の
文言を引用している箇所だけを合わせる。

## 採らなかった案

- **入口を「注釈」「解釈」に戻し、中身に揃える。** ボタンとタブを内部の名前に
  戻すことになり、ADR 0078 が「内部の名前を画面に出していた」として変えた
  判断を戻す。使う人がしているのは「フレームで囲む → 絵解く」で、それを
  内部の名前で言い直す理由が無い。
- **「注釈」だけを残し、「解釈」だけを「絵解き」にする。** 囲んだものの名前
  （「絵1」「絵」の印）と一覧の見出し（「注釈 3 件」）の食い違いが残る。#294 が
  指摘した形のうち、半分しか解けない。

## 結果

- 囲んでから絵解くまでの画面に「注釈」「解釈」が出なくなる。
- ADR 0077 / 0078 / 0079 で保留していた中身の言葉は、この ADR で決まった。
- 画面の文言を足すときは、この語彙で書く。識別子と ADR の語との対応は
  「絵 = annotation」「絵解き = interpret」になる。
