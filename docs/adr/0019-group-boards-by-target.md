# 0019: ボードは作成先でまとめて見せ、Project の表示名はスナップショットで持つ

ステータス: 採用

## 文脈

ボードは必ず 1 つの作成先を持つ（ADR 0014）。持っているのに、画面に出るのは
作成時の選択画面と、ボードを開いたあとの右上のバッジだけだった。サイドバーの
一覧は名前が並ぶだけで、**どのボードがどこへ draft issue を吐くのかは開くまで
分からない。** ボードが増えるほど、作成先を取り違えたまま作成に進める余地が
残る。draft issue は取り消せないので、これは見せていない状態そのものである
（中核思想 3）。

まとめ方の候補として「利用者 → リポジトリ → プロジェクト → ボード」という木が
挙がったが、これは実体の構造ではない。

- 利用者とボードは多対多である。共有すれば同じボードが複数の利用者にぶら下がる
  （ADR 0017）。根を利用者にすると、根はつねに 1 つ（＝自分）で情報量が無い。
- リポジトリと Projects v2 も包含ではない。Project は org / user の直下にあり、
  リポジトリには**リンクされる**だけで、多対多である。etoki が 2 段で選ばせて
  いるのは「利用者はリポジトリで考えるが、draft issue は Project に属する」の
  橋渡しであり（ADR 0014）、GitHub の構造を写したものではない。

もう 1 つ、データ側の穴がある。`boards` が持っているのは `project_id`
（`PVT_kwDO...` という不透明な node ID）だけで、番号もタイトルも無い。今の
データで木を描くと、第 2 階層が人に読めない文字列になる。

## 決定

- **一覧はリポジトリ → Project → ボードの入れ子で見せる。** これは実体の包含
  ではなく、**ボードを作成先でまとめ直した射影**である。1 つの Project に複数の
  ボードがぶら下がり、1 ボードは必ず 1 つの Project に属する（移行前の未選択の
  ボードだけが例外）。
- **並べ替えはしない。** 一覧は `updatedAt` の降順で返るので、その順を保ち、枝は
  最初に現れた順に並べる。名前順にすると、使っていないリポジトリが頭に居座る。
- **既定はすべて開く。** 折りたたみは利用者が畳んだときだけ効く。
- **Project の番号と名前は、作成先を選んだ時点のスナップショットとして
  `boards` に保存する。** 選択画面はすでに GitHub から取得済みなので、
  問い合わせは増えない。
- **表示名は判定に使わない。** 作成先が選ばれているか（`BoardTarget.Selected`）も、
  固定済みか（`sync_runs` の有無）も、この 2 列とは無関係に決まる。表示名は
  任意で、送られてこなければ 0 と空文字（＝名前を知らない）で保存する。
- **作成先は一覧（`BoardSummary`）でも返す。** 一覧から外したままにすると、
  ボードごとに詳細を引くことになる。`targetLocked` だけは引き続き外す。算出に
  run の照会が要り、ボード数だけ問い合わせが増える。

## 結果

- どのボードがどの Project に吐くのかが、開く前に分かるようになった。
- **表示のために GitHub を叩かない。** GitHub が不通でも一覧は描ける。ここを
  「表示のたびに問い合わせ」にすると、`projectAccess` を `unknown` に倒した
  判断（ADR 0017）と逆を行くことになる。確かめられないときに一覧ごと落とす
  設計になってしまう。
- **これは GitHub 側の権限を複製することとは別物である。** ADR 0017 が禁じたのは
  「判定に使う値」を複製することで、複製した権限は必ず古くなり、効いている
  判定の手前にずれた判定を置く。表示名は判定に使わない。加えて
  `repository_owner` / `repository_name` はすでに文字列で持っており（ADR 0014）、
  同じ種類の古び方をする。
- **改名すると古くなる。** 番号は不変なので識別はできる。取り直すのは作成先を
  選び直したときだけで、**自動で GitHub に取りにいって書き戻すことはしない**
  （自動更新は実装しない・中核思想 3）。
- **移行前のボードは表示名が空のまま残る。** 作成先が未固定なら選び直しで埋まる
  が、固定済みなら埋まらない。その枝は「名称未取得のプロジェクト」と出す。
  node ID を出しても読めないので、名前が無いことをそのまま書く。
- E2E で「リポジトリ名のボタン」を押すときは、選択画面（`.picker`）に絞る必要が
  できた。サイドバーの枝が同じ名前を持つため、ページ全体から引くと 2 つ見つかる。
- URL では相変わらずボードを指せない。一覧の見え方と、ボードに固定のアドレスを
  与えるかどうかは別の判断なので、ここでは触れていない。
