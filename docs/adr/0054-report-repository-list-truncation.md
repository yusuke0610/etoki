# 0054: 作成先の候補は打ち切りを添えて返し、絞り込みは手元で行う

ステータス: 採用

## 文脈

作成先に選べるリポジトリの一覧は、`maxRepositories = 500` で頭打ちになる。
GitHub App の構成では、インストールごとに辿る REST のページ数も `maxRestPages = 20`
で止まる。どちらも「選択肢として画面に出すものなので、全部を取り切ることに意味が
無い」という判断で、それ自体は変えない。

問題は、**打ち切ったことが応答に現れないこと**だった（issue #150）。

- 目当てのリポジトリが出ないとき、開発者は「権限が無い」「GitHub App を入れて
  いない」「見た範囲の外にある」を区別できない。README の案内は前の 2 つしか
  挙げていないので、見当違いの設定を疑うことになる。
- 作成先はボードを作る前に選ぶ（ADR 0017）ので、選べないリポジトリにはボードを
  作れない。**行き止まりなのに、行き止まりの理由が読めない。**

中核思想 3（システムは自動で判断せず、状態を見せて開発者に選ばせる）から素直に
外れている。加えて、組織に属していれば 100 件を超えるのは珍しくないのに、画面は
平らなリストを並べるだけで絞り込みが無かった。500 件に届く前から目で探すのは
つらい。

## 決定

### 一覧の応答を配列からオブジェクトに変える

`GET /api/github/repositories` の 200 を、`Repository` の配列から
`RepositoryList`（`repositories` と `truncated`）に変える。`port.GitHubClient`
の `ListRepositories` も `port.RepositoryList` を返す形にする。

**ヘッダでは返さない。** `X-Etoki-Truncated` のようなヘッダなら契約の形を変えずに
済むが、画面が読む値が `api/openapi.yaml` に現れなくなり、生成した型から辿れない
（ADR 0011）。契約が正本だという分担のほうを優先する。

`truncated` が意味するのは「**上限に当たって辿るのをやめた**」であって
「まだある」ではない。辿るのをやめた以上、打ち切った先に候補が残っているかどうかは
サーバーにも分からない。画面の文言も「打ち切っています」に留め、「他にもあります」
とは書かない。

**件数も上限値も返さない。** 画面が出せるのは「ここまでしか見ていない」までで、
数を出すと上限を画面が知ることになる（ADR 0038 がシーンの上限を返さないのと同じ
理由）。

### 絞り込みは取得済みの候補に対して手元で行う

画面に絞り込みの入力を置き、`owner/name` の部分一致で並びを絞る。サーバーに
問い合わせ直さない。

**打ち切りの外は、絞り込んでも出てこない。** 問い合わせ直しても答えは変わらない
ので、絞り込みをサーバー側の検索にしても得るものが無い。「絞れるのは取れたぶん
まで」という事実は、打ち切りの知らせのほうが持つ。だから知らせは絞り込みの入力
より**手前**に置く。打った語で出てこなかったときに初めて読む場所ではなく、
最初から見えている必要がある。

絞り込んで 0 件になったときの文言は、「1 つも見つかりませんでした」とは別にする。
あちらは権限の話で、こちらは打った語の話。同じ文にすると直す場所を間違える。

## 結果

- 目当てが出ないときに、「権限」「インストール」「見た範囲の外」を利用者が
  区別できるようになる。
- `port.GitHubClient` のシグネチャが変わる。**外部リポジトリが自前の
  `GitHubClient` を実装している場合は追随が要る**（ADR 0001 の公開面）。返り値を
  構造体にしたのは、あとから「何件まで見たか」のような値を足すときに、同じ
  シグネチャ変更を繰り返さないため。
- 一覧の応答が配列でなくなるので、E2E のモック（`web/e2e/helpers/`）も形が変わる。
  生成型で縛ってあるので、直し忘れは `tsc` が落とす。
- `maxRepositories` / `maxRestPages` の値は変えない。変えても「打ち切りが見えない」
  という問題は残るし、大きくすれば一覧の取得だけが長くなる。

## 採らなかった案

- **打ち切りを画面に出さず、絞り込みだけを足す。** いちばん安いが、issue が
  挙げていた「区別できない」は絞り込みでは解けない。打った語で出ないのか、
  範囲の外なのかが、また分からなくなる。
- **候補に出ないリポジトリを `owner/name` で直に指定させる。** 打ち切りの外に
  出口を作る案。`GET .../projects` を直接叩けば Projects は引けるので実現可能
  だが、「使えるリポジトリ」の定義（ADR 0015）を画面側で回避する導線になる。
  入れるかどうかは別に決める（issue #150 に宿題として残す）。
- **一覧をページングして画面から辿れるようにする。** 500 件を人が辿る前提の
  UI になる。探すのに要るのは絞り込みで、辿る手段ではない。
