# 0098. 絵解きの質は、人が採点する評価セットで測る

- 状態: 採用
- 日付: 2026-11-16
- #429

## 背景

絵解きの出力が、そのまま使える issue になっているかを測る手段が無かった。
偽の LLM（ADR 0050）は決め打ちの JSON を返すので、テストが緑でも本物の
モデルが何を返すかは分からない。プロンプトを変えた PR（#413 / #419 など）は、
変えた理由をテストと ADR で説明しているが、出力がよくなったかは比べていない。

etoki の値打ちは「出てくる issue がそのまま使えるか」でほぼ決まる。ここを
測れないと、プロンプト・モデル・粒度の指定を変えたときに、よくなったのか
悪くなったのかを言えない。ローカル LLM（#430）や別の形の API（#456）を
勧めるときにも、どのモデルなら足りるかを示せない。

## 決定

### 代表的なボードと、人が書いた期待を組にして置く

`internal/usecase/testdata/eval/` に、1 ディレクトリ 1 ケースで置く。中身は
シーン・画像・入力（囲みの ID、背景、前回分）・期待の 4 つ。図の種別
（やること・シーケンス図・ER 図・システム構成図・指定なし）と、前回分との
対応づけ（ADR 0026）を測るものをそろえ、粒度の指定と背景（ADR 0093）は
ケースごとに変える。

**期待は文言ではなく、意味の箇条書きで書く。** 作ってほしいもの・作って
ほしくないもの・本文に入っていてほしいこと。タイトルの文言はモデルごとに
揺れるので、一致では測れない。期待を座標や近さから機械で作らない
（中核思想 2）。

### 本番と同じ口で絵解く

実行は Go のテスト（ビルドタグ `eval`、`make eval`）で、
`InterpretationJobs.Start` から入る。プロンプトの組み立て・出力の検査・
修正指示つきの再送・ジョブの上限は本番のものを通り、LLM は本番のアダプタで、
サーバーと同じ `ETOKI_LLM_*` に向けて呼ぶ。評価のために別の経路で呼ぶと、
測っているのが本番の絵解きではなくなる。評価のためだけの口は本番のコードに
足さない（テストからだけ見える出入口を使う）。

### 画像は画面の書き出しと同じ経路で作り、ケースと一緒に置く

画像は、絵解くときに画面が囲みから書き出すもの（ADR 0018）。シーンから Go で
描き直すと、本番で渡す画像とは別物になる。E2E のモックの上で「絵解く」を
押し、送られた画像をそのまま書く道具を置く（`make eval-images`）。

### 採点は人が付ける

報告は、ケースごとに期待と出力を並べ、機械で取れるもの（通ったか、呼んだ
回数、トークン数、時間）だけを埋める。漏れ・余計なもの・タイトル・本文・
構造の 5 つは空けておき、人が ○ / △ / × を付ける。

### `make test` と CI には入れない。道具は偽の LLM で守る

本物のモデルを呼ぶので鍵と課金が要り、結果はモデルの版で変わる。ADR 0050 と
同じく、手元で回す導線にする。ただし**道具（ケースの読み込み・実行・報告）は
タグの外に置き、`make test` で偽の LLM に向けて回す。** 誰も回さないあいだに
壊れると、課金して回した日に初めて気づく。

### 結果はリポジトリに残さない

報告は手元の `tmp/eval/` に書く。プロンプトやモデルを変える PR では、変える
前と後で回し、採点した表を PR の本文に貼る。結果はモデルの版と日付に縛られて
古くなるので、残すのはケースと、実行する仕組みだけにする。

## 検討したが採らなかった案

### LLM に採点させる

回すたびに人が見なくて済むが、その採点が妥当かを測る仕組みが別に要る。自動の
採点に寄せすぎると、絵解きではなく採点の仕組みを直す作業になる。ケースが
少ないうちは、人が見るほうが早い。

### 期待を文言の一致で照合する

機械で合否を出せるが、同じ意味の言い換えを落とす。モデルを替えれば言い回しは
必ず変わるので、比べたいもの（使える issue か）を測れない。

### CI で本物のモデルを回す

鍵を CI に置くことになり、PR ごとに課金される。結果がモデルの版で揺れるので、
赤が変更のせいか上流のせいかも分からない。

### 結果を `docs/` に残す

モデルの版と日付に縛られた値で、置いた日から古くなる。比べたいときは PR の
本文から辿る。

## 影響

- プロンプト・制約・モデルの既定を変える PR は、`make eval` の前後の表で
  よくなったかを示せる。回せないときは、回していないと書く
  （`CONTRIBUTING.md` の「確認していないこと」）。
- ケースを足すには 4 つ（シーン・画像・入力・期待）が要る。シーンを変えたら
  画像も作り直す。
- 期待の最初の版は、実装した PR で下書きした。基準を持つのは開発者なので、
  ケースを使いながら直していく。
