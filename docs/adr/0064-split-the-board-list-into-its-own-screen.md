# 0064. ボード一覧を別の画面に分け、ボードは全面キャンバスにする

- 状態: 採用
- 日付: 2026-09-29

## 背景

UI の見直し（#62）で、いまの画面を 0 から組み直すことにした。最初に決めるのは
「1 画面に何を出すか」で、ここが決まらないとヘッダーもパネルも置き場所が決まら
ない。

いまは 1 枚の画面に全部が載っている。左に 240px のサイドバー（ボードの木・新規
作成・アカウント）、右に注釈パネル、上にヘッダー。**ボードを開いてもサイドバー
は残る。**

2 つの問題がある。

**ブレスト中に、ブレストと関係の無いものが常に見えている。** 中核となる思想 1 は
「ユーザーはブレスト中に構造を意識してはならない」と言っている。ところが描いて
いるあいだ、画面には他のボードの一覧と、それが GitHub のどのリポジトリ・どの
Project に属するかが出たままになっている。**構造そのものが視界に居座っている。**

**ヘッダーが 12 個の横並びになっている。** 状態（ロール・作成先・大きさ・未保存）、
いつも押すもの（保存）、たまに押すもの（名前を変更・作成先を変更・書き出し・
取り込み）、パネルの開閉（メンバー・図のドラフト）、取り消せないもの（ボードを
削除）が、同じ高さ・同じ形で並ぶ。**いちばん目立つのは赤枠の「ボードを削除」**で、
いちばん押す「保存」はその隣に同じ大きさで置いてある。重みが逆になっている。

結果として、1440px の画面でキャンバスに使えるのは 870px ほどしかない。**画面の
主役はキャンバスなのに、主役がいちばん削られている。**

## 決定

### ボード一覧とボードを別の画面にする

`/` がボード一覧、`/?board={id}` がボード。**URL の形は変えない**（ADR 0059）。
クエリのままなので、未知のパスに `index.html` を返す fallback は要らないままで
済む（ADR 0032）。いま `App` が持っている分岐を書き換えるだけで、ルーティングの
仕組みは足さない。

一覧は作成先でまとめる（ADR 0019）。**別画面になって幅が取れるので、240px に
押し込んだ木ではなく、まとまりごとの見出しとカードで並べられる。**

### ボードの画面にサイドバーとヘッダーを置かない

ボードは全面キャンバスにする。etoki の部品は削るのではなく**キャンバスの上に
浮かせる**（ADR 0065）。

一覧へ戻る導線は etoki のメニューの最上段に置く。**未保存のまま離さない確認
（ADR 0021）はそのまま効く。** 画面が分かれても、離れる経路が増えるわけでは
ない。

### 状態は隠さない

浮かせたものを「必要なときだけ出す」形にはしない。**操作は隠してよいが、状態は
常に見えていなければならない**（中核となる思想 3）。とくに「未保存」を隠すと、
離れる瞬間まで気づけない（ADR 0021）。

## 帰結

- **E2E の `.picker` 絞り込みが要らなくなる。** サイドバーの木に作成先の選択画面
  と同じ名前のボタンが並ぶので `.picker` に絞ってあったが
  （`web/e2e/helpers/board.ts`、ADR 0019）、一覧とボードが同じ画面から消えるので
  衝突しなくなる。
- **一覧のカードに 3 状態の集計を出すかは、別に判断する。** `BoardSummary` は
  持っていない。`targetLocked` を外したのと同じ理由（ボード数だけ run の照会が
  増える）がそのまま効くので、契約を足すかどうかは一覧を作るときに決める。

## 採らなかった案

- **サイドバーを畳めるようにする。** 畳めるのは幅だけで、ブレスト中に一覧が
  「そこにある」ことは変わらない。畳んだ状態を覚えるかという設定も増える。
- **パス（`/boards/{id}`）にする。** ADR 0059 が挙げた理由がそのまま効く。打ち
  間違えた URL がすべて 200 + HTML で返るようになる。
- **ヘッダーを 2 段にして、状態の段と操作の段に分ける。** 並びは整理されるが、
  12 個並ぶことも、キャンバスの縦を食うことも変わらない。
