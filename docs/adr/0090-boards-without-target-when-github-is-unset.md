# 0090: GitHub を設定していない構成では、作成先を選ばずにボードを作れる

ステータス: 採用

ADR 0017 の「ボードの作成に作成先を必須にする」を、GitHub を設定していない
構成についてだけ改める。ADR 0030 の追記（#200）で「新しいボード」を止めた
ことも改める。

## 文脈

ADR 0017 でボードの作成に作成先を必須にした。理由は共有の文脈での要件 1
（ボードの作成にはリポジトリへのアクセス権が要る）。作成先の候補は GitHub から
引くので、**GitHub を設定していない構成ではボードを 1 枚も作れなかった**
（#297）。ADR 0030 の追記は、作れないことを認めて「新しいボード」を止め、理由を
出すところまでだった。

- README は「LLM を設定しなくても起動します。…ブレストだけ先にやる、という
  使い方を潰さないため」と書いている（ADR 0008）。この約束は LLM にしか効いて
  おらず、GitHub も設定しないとブレストを始められなかった。
- 新しいボードで最初に出る画面は「このボードの draft issue を作る先を選びます。」
  で、描く前に draft issue の行き先を決めさせている。中核思想 1 と緊張する。

ADR 0017 は GitHub を設定していない構成と、README の約束・中核思想 1 との関係を
検討していなかった。

## 決定

### GitHub を組み立てていない構成でだけ、作成先を省ける

- **サーバーは、GitHub を組み立てていない構成でだけ、作成先を省いた
  `POST /api/boards` を受ける。** 作成先が未選択のボードができる。判定はサーバーに
  置き、画面だけには持たせない（理由は「採らなかった案」）。
- **省けるのは 3 つ（owner / name / projectId）とも空のときだけ。** 一部だけ
  送ったら 400。一部を残すと、選んでいないのに選びかけの値を持つボードができる。
- GitHub のある構成では、これまでどおり作成先を省くと 400。

### 要件 1 は崩れない

ADR 0017 が作成先を必須にしたのは、draft issue を作る先へのアクセス権を
確かめるためだった。**GitHub の無い構成では draft issue を作れないので、守る
対象が無い。** `cmd/etoki` の配線では、GitHub の無い構成には認証も無い（ログイン
は GitHub App で行う）ので、ボードを作るのはローカルの 1 人だけになる。

GitHub をあとで設定すると、未選択のボードを開いたときに作成先の選択に入る
（ADR 0014 で移行前のボードに入れた経路と同じ）。候補は書ける Project に絞って
あるので、**draft issue を作れるようになる時点で要件 1 が効く。**

### 画面

- **「新しいボード」はどの構成でも押せる。** GitHub が未設定と分かっている構成
  （`capabilities.creation` が false）では、ダイアログの主となる操作を「次へ」
  から「作成」に変え、作成先を選ばずにその場で作る。選ばないことは押す前に文で
  言う（中核思想 3）。
- **作成先が未選択のボードを開いても、GitHub が未設定なら作成先の選択に入らず、
  キャンバスをそのまま開く。** 候補を引けない選択画面に入れると、選べないまま
  一覧へ戻るしかない。作れないことは、作成のところで「GitHub が未設定です」と
  言う（ADR 0030）。
- **一覧のカードの破線と「開くと作成先を選べます」は、開くと作成先の選択に入る
  ときだけ出す。** GitHub が未設定なのに出すと、押した先がキャンバスで約束と
  違う。未選択であることは、節の見出し（「作成先が未選択」）が言っている。
- **使える機能をまだ引けていないとき（`capabilities` が null）は、いつもの流れ
  （作成先を選ぶ）に倒す。** 省けると決めつけて作成先を送らないと、GitHub のある
  構成で 400 になる。ADR 0030 の「引けていないうちは止めない」と同じ向き。

## 採らなかった案

- **認証なしの構成全体で、作成先をあとから選べるようにする。** 中核思想 1 との
  緊張は GitHub のある構成にも残るが、選ぶ時点が作成の直前に寄るので、Kind /
  Parent の確認（ADR 0088）と順序を揃える必要が出る。#297 が問うたのは GitHub の
  無い構成で、そこでは選べる候補が無いことが決め手になる。GitHub のある構成は
  そのまま残す。
- **変えずに、README の約束を「LLM を設定しなくても」に限ると明記する。** ブレスト
  だけ先にやる使い方が、GitHub を設定するまで潰れたまま残る。
- **判定を画面だけに置き、サーバーは作成先なしをいつも受ける。** GitHub のある
  構成で API を直接叩けば、要件 1 を外したボードが作れる。判定はユースケース層に
  置く（作成先の固定を置いた ADR 0014 と同じ理由）。

## 結果

- GitHub も LLM も設定しない構成で、ボードを作ってブレストを始められる。README の
  「ブレストだけ先にやる」は GitHub にも効く。
- ADR 0017 の「作成先が未選択のボードは新規には生まれない」は、GitHub のある構成に
  ついてだけの記述になる。
- GitHub を設定したあとは、そのボードを開くと作成先の選択から始まる。描いた
  シーンはそのまま残る。
- GitHub が未設定のまま、未選択のボードでメニューの「作成先を変更」を押すと、
  選択画面に入って候補を引けない理由が出る。ADR 0030 が選択画面を capability で
  止めないと決めたとおりで、この ADR では変えない。
