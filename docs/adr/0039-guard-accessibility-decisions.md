# 0039: アクセシビリティは形と判断に分けて守る（判断は E2E、形は lint と axe）

ステータス: 採用

## 文脈

コードには意図をもって書かれた a11y の配慮がある。押せない理由を `title` に
隠さず本文として出す、`aria-describedby` でボタンと理由を結ぶ、エラーは
`role="alert"`。**しかし守っていることを確かめる仕組みが 1 つも無かった。**
`eslint-plugin-jsx-a11y` は入っておらず、E2E にも検査は無い。規約はコメントと
してしか存在せず、書いた人がそのコメントを読んだときだけ守られていた。

UI デザインの見直し（#62）は a11y を「崩してはいけないもの」として挙げ、
「デザインを入れ替えるときに一緒に消えやすい」と書いている。**消えやすいと
分かっているのに、消えたことに気づく手段が無い。** 順序として #62 より先に
置く必要がある。

## 決定

**守るものを 2 つに分け、別々の道具に割り当てる。** 混ぜると「lint を入れたから
大丈夫」になり、重いほうが抜ける。

|                                          | 例                                                        | 何で守るか                       |
| ---------------------------------------- | --------------------------------------------------------- | -------------------------------- |
| 形の規約                                 | `alt` が無い、`aria-*` の綴り、role の不正                | jsx-a11y（strict）               |
| 形の規約のうち、描かないと分からないもの | 実際の色のコントラスト、`aria-describedby` の指す先の実在 | axe（`web/e2e/a11y.spec.ts`）    |
| **判断の規約**                           | **押せない理由が本文として読める**                        | **E2E（`expectBlockedReason`）** |

- **判断の規約は既製のルールでは検知できない。** etoki 固有なので、押せない
  ボタン 1 つずつに対して手で書く。**押せないボタンを足したら spec にも足す。**
  並んでいないボタンは守られていない。
- **jsx-a11y は recommended ではなく strict。** 入れた時点の指摘を数えたら
  strict で 1 件（`no-autofocus`）しか出ず、recommended との差は「recommended が
  既定で緩めているオプション」だけだった。緩い側を既定にすると、緩めてあること
  自体が誰にも見えないまま効き続ける。
- **その 1 件は直さずに `eslint-disable` で理由を残す。** 名前の変更で
  `autoFocus` を外すと、押した「名前を変更」が消えた後にキーボードの焦点が
  `body` に落ちる。**外すほうが a11y は悪くなる。** ルールが見ているのは属性で、
  押した結果として現れた入力かどうかは見られない。
- **axe は `.excalidraw` を除いて掛ける。** 掛けた時点で Excalidraw 自身の
  メニューボタンが `button-name` に引っかかっていた。ライブラリの DOM の指摘は
  etoki には直せないので、除かないと直せない指摘が出続ける検査になり、やがて
  誰も見なくなる。（そのメニューボタンには、のちに etoki が名前を付けて検査に
  戻した。下の「追記」。）

## 採らなかった案

- **jsx-a11y だけで済ませる。** 静的解析は JSX の属性しか見ない。**入れた
  時点で `.hint` のコントラストが 4.48:1（AA は 4.5:1）で落ちていた**のを
  見つけたのは axe のほうで、jsx-a11y には最後まで見えない。**押せない理由を
  出しているのがその `.hint` だった。** 理由を本文で出す判断は、読めない色で
  出していたら半分しか果たしていない。
- **axe をページ全体に掛けて、Excalidraw の指摘を個別に抑制する。** 抑制の
  一覧を持つと、ライブラリが直したときにこちらが気づけない。除外の単位を
  「etoki が書いていない DOM」にしておけば、境界は 1 行で言える。
- **段階的な有効化（一部ルールだけ error）。** 指摘が 1 件なので要らない。
  大量に出るなら選ぶ意味があるが、選んだ結果として残った `eslint-disable` が
  並ぶと規約としては死ぬ。

## 帰結

- 新しい依存が 2 つ増える（`eslint-plugin-jsx-a11y` / `@axe-core/playwright`）。
  どちらも `.github/dependabot.yml` の `bun` グループが `*` で拾うので、
  更新の知らせは自動で付く（ADR 0035）。**`ignore` は足さない。** バージョンを
  固定する理由がまだ無い。
- `eslint-plugin-jsx-a11y` の peer にこのリポジトリの eslint のメジャーが
  入っていない。**動いてはいる**が、eslint を上げたときに落ちうる場所として
  `web/CLAUDE.md` に控えてある。**版の範囲はここに書き写さない。**
- axe は E2E でしか走らない。`make test` には入らないので、**コミット前に
  `make test-e2e` を回す条件（UI かハンドラを触ったとき）がそのまま
  a11y の検査の条件になる。**
- #62 に着手する前に置けた。入れ替えの前に無ければ、いちばん静かに失われる。

## 追記: メニューの入口には etoki が名前を付ける（#299）

上で「etoki には直せない」として外したメニューの入口（≡）は、判断した時点では
ライブラリの項目しか開かなかった。その後 ADR 0065 で etoki の操作（一覧へ戻る・
共有・書き出しなど）をこの中に入れたので、**etoki の操作の入口が、読み上げでは
「ボタン」としか聞こえなくなっていた。** 「ボード一覧へ戻る」の口はここにしか
無い。

**名前を付ける。** Excalidraw 0.18.1 の `MainMenu` は入口に名前を渡す口を持たない
ので、描かれたボタンに外から名前を付ける。

- **除外の単位を「etoki が書いていない DOM」から「etoki が手を入れていない DOM」に
  改める。** 入口は Excalidraw が描くが、名前は etoki が付けているので、直せる
  ものとして axe の検査に戻す。`.excalidraw` を除いて、etoki の部品だけを戻す形
  （ADR 0065）は変えない。
- **ライブラリの DOM に寄りかかる。** ライブラリが入口の描き方を変えれば黙って
  外れるので、ADR 0067 と同じく E2E で守る。
- **ライブラリが自分で名前を付けるようになったら、そちらに任せる。** 名前の
  付いている入口には触らない。言語の設定に沿った名前を、etoki の固定の文字列で
  潰さないため。

採らなかった案は 2 つ。

- **変えずに、代償をここに書き足す。** etoki の操作がこの入口の奥にしか無い以上、
  読み上げの利用者が一覧へ戻れない。直せないのではなく、直す手段がある。
- **ライブラリにパッチを当てる。** ADR 0067 と同じ理由で採らない。版を上げる
  たびに当て直すことになり、当たらなくなったときの気づき方は E2E と変わらない。

## 追記: axe の規則は、版の既定に任せず名指しで有効にする（#324）

**etoki が守ると決めた規則は、axe の既定で無効でも E2E の検査で名指しして有効に
する。** 最初に名指ししたのは
`label-content-name-mismatch`（WCAG 2.5.3、見えている文字が名前に含まれている
こと）。axe-core 4.13 までは実験扱いで既定では無効だったので、名前を見出しだけに
絞ったカードが検査されないまま通っていた（#311）。

jsx-a11y を strict にしたのと同じ筋で、既定に任せると、効いていないことが誰にも
見えないまま残る。版を上げて既定が変わっても、検査が黙って抜けない。
