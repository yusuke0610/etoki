# 0004. 単一ユーザーのローカルツールとして設計する

- ステータス: 置き換え済み（[ADR 0016](0016-boards-have-owners.md)）
- 日付: 2026-07-29

## 文脈

利用者は 1 人であり、現時点でサーバー基盤は存在しない。開発者が自分の端末で
起動して使う想定である。

一方で、ボード本体はサーバー側の `boards` テーブルで永続化する方針を採った。
つまりサーバーは状態を持つが、その状態を守るための認証機構は持たない。

## 決定

- 認証・認可・マルチテナントを実装しない。
- 既定のリッスンアドレスを `127.0.0.1:8080` とし、ループバックだけにバインドする。
  公開インターフェースにバインドしたい場合は利用者が明示的に指定する必要がある。
- GitHub PAT と LLM API キーはプロセスの環境変数から読む。ユーザーごとの
  資格情報管理は行わない。
- ボード ID はサーバーが発番する UUID とし、`boards` テーブルを唯一の正とする。

## 結果

- 実装が大幅に単純になる。セッション、権限モデル、資格情報ストアが不要。
- **この前提が崩れる（複数人で共有サーバーを立てる）場合、以下がすべて壊れる。**
  - リッスンアドレス（誰でも叩ける）
  - 環境変数による資格情報（全ユーザーが同じ PAT を共有してしまう）
  - `boards` に所有者の概念がない
  - 監査ログが存在しない

  共有化する際は、これらを順に潰す作業が必要になると認識しておく。
- **ループバックにバインドしていても、ブラウザ経由なら外部サイトから叩ける。**
  上の列挙は「共有サーバーを立てたら壊れるもの」だが、CSRF と DNS
  リバインディングはローカル起動のままでも成立する。Host と Origin を検証して
  塞いだ（ADR 0013）。この ADR の前提そのものは変わっていない。
- ブレスト自体は複数人で行うが、それは 1 台の画面を囲む運用を想定している。
  Excalidraw のリアルタイム共同編集は別サーバーを要するためスコープ外。

## 追記（2026-08-08）

この ADR は [ADR 0016](0016-boards-have-owners.md) に置き換えられた。
上で「前提が崩れたら壊れる」と挙げた 4 項目は、ADR 0013 / 0015 / 0016 で
順に塞いである。

**ただし既定の構成は変わっていない。** 認証を設定しなければ、いまも単一
ユーザーのローカルツールとして動く。この ADR が書いている前提は、その構成に
ついては現在も有効。
