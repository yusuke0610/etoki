# 0105. ログインを 1 人に絞り、認証なしで外に開かない

- 状態: 採用
- 日付: 2026-11-26
- ADR 0016 の「認証なしでループバックの外にバインドしても止めない」を改める
- ADR 0017 の共有は、2 人目がログインできないので使えなくなる（外すのは #495）

## 背景

2026-11-25 に、人に使ってもらうための開発を終え、作者が自分で使う形に切り替えた。
動かす先は Cloud Run。そこで 2 つの前提が崩れた（#492）。

1. **誰でもログインできる。** GitHub App を設定すると、GitHub のアカウントを持つ
   人なら誰でもログインできた（人に出す前提で「ログインできる人は絞らない」と
   決めていた）。Cloud Run は、ブラウザのログインを通すために未認証の呼び出しを
   許す形で置く。URL を知った人は誰でもログインして LLM を叩け、費用を払うのは
   作者になる。他人の GitHub トークンも DB に溜まる。
2. **認証の設定が抜けると、誰でも全部を使える。** 認証なしでループバックの外に
   バインドしても、警告を出して起動していた（ADR 0016）。Cloud Run では、秘密の
   値を 1 つ渡し忘れただけでこの組み合わせになる。

## 決定

### 通す GitHub の利用者を、設定で 1 人だけ渡す

- **`ETOKI_ALLOWED_GITHUB_USER_ID` に数値の ID を渡す。** login は使わない。改名で
  変わり、空いた login は別人が取れる（ADR 0053）。メールアドレスも使わない。
  etoki はいま取っておらず、取るには App の権限と呼び出しが増える。
- **照らす場所は 3 つ。** ログインの完了（`AuthService.Complete`）、セッションの
  解決（`Resolve`）、MCP のトークンの持ち主（`requireBearer`）。後の 2 つは、通す
  相手を変えた日に、外した人の入口を残さないため。
- **ログインの完了では、利用者を作る前に照らす。** 断った相手は `users` に残さず、
  資格情報も保存しない。残すと招待の引き当てに現れ、保存したトークンは他人の
  GitHub の権限そのものになる。
- **断ったら、理由をつけてログインの画面へ戻す**（`/?login=denied`）。コールバックは
  ブラウザの遷移で JSON を返せない。黙って戻すと、何が起きたのかが分からず、押し
  直しても GitHub が同じアカウントで通して同じところへ戻る。
- **照らすのはユースケース層。** 認証基盤のアダプタ（`Exchange`）で断る形にすると、
  セッションとトークンを照らす場所が別に要る。
- **ユースケース層は一覧で受ける。** 組み立て口（`etoki.NewAuthenticator`）と設定は
  1 人だけを渡す。一覧で受けるのは、共有のテストが 2 人目のログインを要るため。
  共有を外すとき（#495）に 1 人へ戻す。

### 設定が足りなければ起動しない

次のどれでも、起動の時点で落ちる。

- ループバック以外で待ち受けるのに、認証を設定していない（`etoki.ErrExposedWithoutAuth`）。
- 認証を設定したのに、通す利用者が無い。
- 通す利用者の値が、数値の ID の形をしていない。**先頭の 0 や空白を直さずに弾く。**
  照らすのは文字列の一致なので、受けると誰もログインできないまま起動する。直すと、
  書いた値と照らしている値が食い違っていることに気づけない。
- 通す利用者だけを書いて、App を設定していない（書き損じ）。

**ループバックでは、これまでどおり認証なしで動く。** 他の端末からは届かず、
ブラウザ経由の cross-site は Host と Origin の検証で弾いている（ADR 0013）。
手元の開発（`make dev`）と、偽の上流で回すテストの構成を変えない。

## 採らなかった案

- **コードに ID を埋め込む。** 公開リポジトリに載る。設定なら、値を非公開の置き場
  （デプロイの構成の、コミットしない設定）に置ける。
- **DB の表に通す人を持つ。** Cloud Run の DB は Litestream で 1 つのプロセスだけが
  書く前提なので、最初の 1 行を外から入れる手段が要る。マイグレーションで入れると
  リポジトリに載り、起動時に設定から入れると正本が設定になる。
- **最初にログインした人を持ち主にする。** デプロイの直後に URL を見つけた他人が
  先に入れる。
- **Cloud Run の前に IAP を置く。** Google の文書によると、プロジェクトが組織に
  属している必要がある（文書の版によって書き方が食い違う）。デプロイ先は組織に
  属していない。ロードバランサーを挟めば使えるが、月の固定費が掛かる。
- **Cloud Run の IAM で絞る。** ブラウザのログインが通らない。
- **GitHub App を「Only on this account」にして GitHub の側で絞る。** この設定が
  決めるのはインストールできる先で、他人がその App で認可できるかは文書で
  確かめられなかった。守りは etoki の側に置く。
- **手元でもログインを必須にする。** GitHub App に localhost の戻り先が要り、偽の
  上流で回すテストに偽のログインが要る。守れるものがほとんど増えない。
- **警告のまま、同意の設定（`ETOKI_ALLOW_UNAUTHENTICATED` のような）で外に開ける
  ようにする。** ADR 0016 でも採らなかった。防ぎたいのはうっかりなので、逃げ道を
  作らない。

## 結果

- Cloud Run で秘密の値を渡し忘れると、開いたまま動かず、起動に失敗する。
- **コンテナを手元で動かすときも認証が要る。** コンテナの中では `0.0.0.0` で
  待つため。GitHub App に手元の戻り先を足す。
- 共有（ADR 0017）は使えなくなる。招待の前提の「一度ログインした相手」が自分の
  ほかに居ない。
- 公開の組み立て口 `etoki.NewAuthenticator` の引数が増える（公開 API の約束を
  外すのは #493）。
- 断った相手の GitHub トークンは保存しないが、GitHub の側の認可（その人の
  Authorized GitHub Apps に App が載る）は残る。取り消すのはその人。
