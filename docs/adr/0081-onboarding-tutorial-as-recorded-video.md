# 0081: 使い方は、実画面を録った動画を小さなダイアログで見せる

ステータス: 採用

## 文脈

etoki は最初の一歩が重い（#66）。書ける Projects v2 が要り、Project には
`Kind` と `Parent` のフィールドが要り、注釈はフレームツールで囲んでから選んで
付ける。初見の人がどこで詰まるかはコードから分かっていたが、画面で案内する
手段が無かった。

手を動かして練習させる形は、どれも既存の判断とぶつかる。

- **ボードを作らせると、作成先の選択が要る**（ADR 0017）。書ける Project を
  持たない人は、練習すら始められない。作成先の無いボードを新しく許すと、
  0017 の「新規には生まれない」が崩れる。
- **作成まで練習させると、本番の Project に draft issue が残る。** 作成は
  取り消せず、etoki からは消せない（ADR 0009）。
- **解釈まで練習させると、LLM の設定が要る。** README は「LLM を設定しなくても
  起動する」を約束している。

## 決定

**ボードを作らせず、操作を録った動画を 3 ページの小さなダイアログで見せる。**
上の 3 つの壁にはどれも触れない。認証の有無にも LLM の設定にも関係なく、
同じ内容を見せられる。

### 順序

**ページの順序は思想 1 で決まる。** epic / issue という語は 3 ページ目まで
出さない。チュートリアルが最初に構造の語彙を教えると、ブレストの前に構造を
意識させることになる。

1. 描いて、フレームで囲む
2. 絵解いて、読み解きを見る
3. 作る（ここで初めて epic / issue が出る。GitHub 側の準備もここで書く）

### 動画にする

**囲む操作はドラッグなので、静止画では伝わらない。** 前後の 2 枚から動きを
想像させるより、ポインタが frame を引く軌跡をそのまま見せる。

- **動画は E2E のモック（ADR 0012）の上で Playwright が録る。** 毎回同じ
  内容になり、UI を変えたら撮り直せる。**ページごとに別のテストで録る。**
  1 本を秒数で切り分けると、操作の速さが変わるたびに区切りがずれる。2・3
  ページ目はモックで前の状態から始める。
- **形式は MP4（H.264）。** Playwright の WebM を ffmpeg で変換し、ボードを開く
  までの頭を切り落とす。**ffmpeg は録るときだけ使う。** `make build` と CI には
  要らない。
- **ヘッドレスの録画にはポインタが映らない。** 擬似カーソルを DOM に重ねて
  録る。**擬似カーソルは録る spec の中にだけ置き、製品のコードには入れない。**
- **ライトとダークの両方を録る。** テーマは OS に追従する（ADR 0055）ので、
  1 つだけだと片方で浮く。
- **生成した動画はコミットする。** ビルドで作るとビルドに Playwright と
  ブラウザが要る。古くなりうることは受け入れ、撮り直しを 1 つの `make` の
  ターゲットにする。**Vite に import させてファイル名にハッシュを付ける。**
  etoki が `no-cache` を付けるのは `index.html` だけなので、名前の変わらない
  素材は撮り直しても古いものが残りうる。

### GitHub 側の画面

**GitHub の画面は載せない。** 3 ページ目の Project の準備（種別と親を入れる
フィールド）は、本文に言葉で書く。

GitHub の画面は自前で再生成できず、GitHub は etoki と無関係に画面を変える。
手で撮った静止画は、画面が変わっても撮り直す合図が無い。動画と違って `make` で
撮り直せず、古くなってもどのテストも落ちない。言葉で書くのは要る設定
（フィールドの名前・型・選択肢）だけなので、GitHub が画面を変えても古くならない。

**フィールド名は既定の名前だと書く。** `ETOKI_GITHUB_KIND_FIELD` /
`ETOKI_GITHUB_PARENT_FIELD` で変えられるので、名前を言い切ると設定を変えた
人には嘘になる。

### 始め方

- **自動では開かない**（思想 3）。ボードが 0 件のとき、一覧の空状態の文の隣に
  「使い方を見る」を置く。押すかどうかは人が選ぶ。
- **見返す口は 2 つ。** ボードではキャンバスのメニュー（ADR 0065 の
  `MainMenu`）、一覧では上の帯。**一覧にはメニューが無い構成がある**（認証
  なしでは利用者のメニューが出ない）ので、`MainMenu` だけでは一覧から開けない。
- **見たかどうかは覚えない。** 自動で開かないので、覚える理由が無い。

### アクセシビリティ（ADR 0039）

- **動きを減らす設定では自動で再生しない。** 最初のコマで止めて、再生の
  ボタンを出す。設定が無ければ、ミュートで繰り返し再生する。
- **動画の中身は読み上げに届かない。** 各ページに同じ内容の説明を本文として
  置き、動画から `aria-describedby` で結ぶ。音声が無いので字幕（WebVTT）は
  持たない。
- **ダイアログはブラウザの `<dialog>` をモーダルで開く**（新しいボードの
  ダイアログと同じ）。閉じたら開いたボタンへ焦点を戻す。

## 採らなかった案

- **既存のボードの上でガイドする。** ボードを持たない人には出せない。持たない
  人がいちばん案内を要る。
- **チュートリアル専用のボードを作る。** 作成先の無いボードを例外として
  許すことになる（ADR 0017）。例外は 1 つ足すと線でなくなる。
- **静止画のコマ送り。** 動きを減らす設定にはそのまま従え、文字も止まって
  読めるが、囲む操作のドラッグが伝わらない。試作を並べて見比べ、動画を選んだ。
- **1 本を録って秒数で切る。** 試作はこの形で、操作の速さに区切りが引きずられた。
- **GitHub の画面を手で撮った静止画で見せる。** GitHub が画面を変えても撮り直す
  合図が無く、古い画面が残る。要る設定は言葉で書ける。
- **ボードが 0 件なら自動で開く。** 勝手に始めることになる（思想 3）。
- **README へのリンクだけにする。** README を読む人と、画面で迷う人は別。

## 結果

- **UI を変えたら動画が古くなる。** E2E は緑のまま、動画だけが古い画面を
  見せうる。撮り直しは `make` のターゲット 1 つでできるが、撮り直すかどうかは
  人が気づくしかない。
- devShell に ffmpeg が入る（録るときだけ使う）。
- GitHub 側の準備は画面で見せないので、フィールドを足す場所は利用者が GitHub の
  画面で探す。
