# 0108. 1 人専用のツールにしてクラウドで使い、手元は開発のために残す

- 状態: 採用
- 日付: 2026-11-27
- ADR 0016 の「単一ユーザー前提を捨て」を改める。1 人専用に戻す
- ADR 0004 の「単一ユーザーのローカルツール」を改める。認証なしで手元で動く
  構成は、開発と確かめのためのものになる

## 背景

etoki は、手元で動かす単一ユーザーのツールとして始まった（ADR 0004）。8 月から
人に出す前提で育て、単一ユーザー前提を捨てて（ADR 0016）、ボードの所有者、共有、
利用者ごとのトークン、MCP の OAuth を足した（ADR 0015・0016・0017・0076）。

2026-11-25 に、人に使ってもらうための開発を終えた。ホストして運用し続ける
イメージが持てなかったため（README の冒頭）。そのうえで、作者 1 人が Cloud Run で
動かして使う形に切り替えた。ねらいは、費用、デプロイの詰まりどころ、運用の
ライフサイクルを学ぶこと（#491）。ログインできるのも 1 人に絞った（ADR 0105）。

切り替えたあとも、前提を書いた文書は手元で使う形のままだった。

- `CLAUDE.md` は、冒頭で etoki を「単一ユーザー向けのローカルツール」と書いて
  いた。毎回読まれるので、判断の前提がそこで決まる。
- README の手順は、手元で動かして使う形が主だった。クラウドに載せるときに etoki が
  何を求めるかは、基盤の側（非公開の基盤のリポジトリと #472）にしか無かった。

前提が古いまま読まれると、クラウドで動かすために要るもの（載せるためのイメージ、
止まり方）が、手元のツールには要らないものとして扱われる。複数人で使う仕組みも、
使われないまま保守と検査の対象に残る（#495）。

## 決定

### 1 人で使う前提でアーキテクチャを組む

- **1 つの etoki を使うのは 1 人だけ。** いまは作者。通す 1 人は設定で渡す
  （ADR 0105）。
- **他の人に使われて費用がかかるのを避ける。** LLM とクラウドの費用を払うのは
  作者。**ループバックの外では、通す 1 人のほかは費用のかかる口に届かない。**
  LLM を叩く解釈と図の生成も、GitHub を叩く口も、ログインを要求するグループ
  （`requireAuth`）の内側にあり、ループバックの外で通すのは 1 人だけ
  （ADR 0105）。ログインの手前で他人が起こせる書き込み（ログインの開始と、MCP の
  クライアントの登録）は、窓の中の回数で縛ってある。
- **複数人で使うための仕組みは畳み、新しく足さない**（`CLAUDE.md` の
  「スコープ外」）。1 人用の形は下の表のとおり。順番と細部は #491 の sub-issue で
  決める。
- **1 人でも効くものは残す。** 下の「1 人でも残すもの」。

| 問い                       | 1 人用の形                               | どこで           |
| -------------------------- | ---------------------------------------- | ---------------- |
| 誰が開けるか               | 通す 1 人だけ                            | ADR 0105（済み） |
| GitHub を叩く資格情報      | PAT 1 本                                 | ADR 0106（済み） |
| ボードを誰と使うか         | 1 人だけ。共有・招待・ロールは持たない   | #495             |
| ボードは誰のものか         | 所有者で絞らない                         | #496             |
| LLM の上限                 | 利用者ごとではなく、プロセス全体で数える | #496             |
| 外のリポジトリから差し込む | 公開 API として約束しない                | #493             |
| MCP                        | クラウドで使ってみてから決める           | #494             |

### 使うのはクラウドに載せた etoki、手元で動かすのは開発のため

- **使う先はクラウドに載せた etoki。** いまの載せ先は Google Cloud Run。
- **手元で動かすのは、開発と確かめのため。** `make dev`、偽の上流で通す確かめ
  （ADR 0050）、E2E（ADR 0012・0097）、ローカル LLM（ADR 0008・0104）は、その
  ために残す。ループバックなら認証なしで動く形も残す（ADR 0105）。
- **README と `CLAUDE.md` は、クラウドで使う形を先に書く。** 手元で動かす手順は、
  開発のためのものとして書く。手元で常用するための手順は、保守の対象にしない。

### クラウドに載せる形は etoki が持ち、載せる先の構成は持たない

線は今のまま。`CLAUDE.md` の「コアは特定のクラウド基盤を意識しない」と、
「スコープ外」のデプロイ先の構成。

- **etoki が持つのは、どの基盤にも載せられる形まで。** 環境変数だけで設定できる
  こと、`/healthz`、コンテナイメージ（#446）、基盤の停止の猶予に収まる止まり方、
  構造化したログ。
- **載せる先の構成は、非公開の基盤のリポジトリに置く。** OpenTofu、DB の複製
  （Litestream）、デプロイの手順、通す利用者の ID のようなデプロイ先の値。
- **クラウドに載せるときに etoki が基盤へ求めることは、README に書く。** 1 台で
  動かす、DB のファイルを残す、応答を返したあとも CPU を止めない、など。どれも
  etoki の作りから決まるので、基盤の側ではなく etoki の側に置く。

### 1 人でも残すもの

人に出す前提で足したもののうち、畳むものは #491 の sub-issue で 1 つずつ決め、
ADR に残す（ADR 0105 など）。**次のものは、1 人専用でも残す。** 1 人なのに
残っているのは、畳み忘れではない。

| もの                                                              | 残す理由                                                  |
| ----------------------------------------------------------------- | --------------------------------------------------------- |
| ログインとセッション（ADR 0015・0105・0106）                      | クラウドに置くので、通す 1 人であることを確かめるのに要る |
| Host と Origin の検証（ADR 0013）、ループバックの既定（ADR 0016） | クラウドでも CSRF の守りとして要る                        |
| ジョブ、排他、版の照合（ADR 0085・0091・0060・0020）              | 1 人でも、タブや端末を 2 つ開けば効く                     |
| 設定の案内（ADR 0030・0083）、GitHub なしの構成（ADR 0090）       | 手元で鍵なしに `make dev` するときに効く                  |
| 持ち出しと取り込み（ADR 0045）                                    | 手元のボードをクラウドへ移す道具になる                    |
| 使い方のダイアログ（ADR 0094）                                    | 押したときだけ開くので、邪魔にならない                    |
| 同梱物のライセンス表示（ADR 0070）                                | イメージを公開の場所に置くなら、配布にあたる（#446）      |
| 偽の上流（`make try-fake`、stack E2E）                            | 開発の道具                                                |

## 採らなかった案

- **1 人で使うが、複数人で使える形も残しておく。** 誰も招待されないのに、ロールの
  分岐や 403 と 404 の使い分けが保守と検査の対象に残る（#495）。バックエンドを
  触るたびに自動で読まれる規約にも載る。通す相手を 1 人に絞った（ADR 0105）
  うえで残しても、使う場面が来ない。
- **手元のツールに戻す（ADR 0004 の形）。** 認証も基盤も要らず、いちばん軽い。
  採らないのは、クラウドで動かすこと自体がねらいだから（#491）。
- **手元でも常用できる形を保ち、手順を 2 通り並べる。** 使うのはクラウドの
  1 か所だけなので、手元で常用する手順は誰も通らなくなる。通らない手順は、
  壊れても気づかれないまま古くなる。開発に要る範囲なら、開発のたびに通る。
- **Cloud Run を前提にして、固有の扱いをコアに入れる。** 載せ先を替えるときに、
  etoki のコードまで替えることになる。#472 では、使う量に応じて載せ先を選び直す
  順（常時 1 台、Cloud Run instances、VM）を決め、載せ替えを軽く保つために
  「コアに Google Cloud 固有のものを入れない」としている。
- **載せる先の構成も、このリポジトリに入れる。** リポジトリは公開なので、
  デプロイ先の値を外へ出す仕組みが別に要る。通す利用者の ID は、非公開の
  置き場に置くと決めてある（ADR 0105）。
- **リポジトリをアーカイブする。** 人に出すための開発を終えると決めたときに、
  最初に考えた形。自分で使いながら直すなら push できる必要があり、Dependabot も
  動いていてほしい（#489）。

## 結果

- ADR 0016 の「単一ユーザー前提を捨て」は改まる。所有者の仕組みは #496 で畳む。
- 複数人で使う仕組みを足すなら、この ADR ごと見直す。
- LLM と GitHub を呼ぶ口を、ログインを要求するグループの外に足さない。ログインの
  手前の口に書き込みを足すなら、回数で縛る（`.claude/rules/http-handlers.md`）。
- 他人のリクエストでも、クラウドのインスタンスは起きる。その費用は etoki の側では
  止められない。止めるなら基盤の側で扱う（#472）。
- 認証なしで手元で動く構成は、開発のためのものになる。ADR 0004 の追記にある
  「その構成については現在も有効」は、開発の構成についての話として読む。
- コンテナイメージはまだ無い。#446 のイメージを作る PR（#480）は、開発を終えると
  決めたときにマージせずに閉じた。クラウドで使うには、自分用に絞り直したイメージが
  要る。
- 停止の猶予と、デプロイのあいだ 2 台が重なることは、最初のデプロイで確かめて
  から決める（#491）。猶予の短い基盤では、作成の記録が間に合わないことがある。
- 手元で常用する手順が壊れても、開発で通らない範囲なら気づかないまま残る。
