# 0010: 作成時に解釈時点の contentHash を必須にする

ステータス: 採用

## 文脈

draft issue の作成は、LLM が解釈した結果を開発者が確認してから手動で実行する。
一方で、状態判定と run 記録の基準は保存済みシーンである。

解釈後から作成処理が保存済みシーンを読むまでの間にシーンが保存されると、作られた
draft issue は古い解釈結果に由来するのに、run には新しいシーンの hash が記録される。
GitHub 側に作った draft issue は削除しないため、いったん作ると取り消せない。

## 決定

解釈レスポンスに、その時点の保存済みシーンから計算した `contentHash` を含める。
作成リクエストでは `contentHash` を必須にし、作成処理の開始時に現在の保存済み
シーンから計算した hash と比較する。

一致しなければ draft issue は 1 件も作らず、run も記録せず、HTTP API は
`409 Conflict` を返す。クライアントは解釈をやり直してから作成する。

`contentHash` は任意にしない。任意にすると、API を直接叩く経路で検証を素通り
できてしまい、今回防ぎたい非冪等性が残るため。

## 結果

作成は「開発者が確認した解釈結果」と「現在の保存済みシーン」が一致する場合にだけ
進む。食い違った場合は自動で続行せず、状態を見せて開発者に選ばせる。

既存のクライアントは作成リクエストに `contentHash` を含める必要がある。
