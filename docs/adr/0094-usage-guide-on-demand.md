# 0094: 使い方は押したときだけ開くダイアログに置き、心得を手順より先に書く

ステータス: 採用

## 文脈

ボードの画面には、囲んで絵解くまでの流れを説明する場所が無かった。手掛かりは
右のパネルの「選択中のフレーム」に出る 1 文（「フレームツール（F）で囲んでから、
そのフレームを選択してください。」）だけで、次のことが画面から読めなかった。

- 何をすれば etoki に読ませられるのか（フレームで囲み、絵にする）
- 絵にする操作がどこにあるのか
- 描いているあいだに何を意識すべきか（何も意識しなくてよい）

キャンバスのメニューにある「ヘルプ」は Excalidraw のもので、キャンバスの操作と
ショートカットの案内しか無い。

## 決定

### 押したときだけ開くダイアログにする

- **入口はキャンバスのメニューの「etoki の使い方」と、右のパネルの「選択中の
  フレーム」の案内の下の「使い方を見る」。** メニューは誰にでも出す。パネルの
  ボタンは、案内の文と同じく編集できる人にだけ出す（読むだけの人には絵にする
  操作が無い）。
- **初めて開いたときに自動で出すことはしない**（中核思想 3）。ボードを開く
  たびに、描き始めの前に説明が割り込む。初回だけに絞ると「初回」を覚える
  場所（`localStorage`）が要り、端末を変えるたびに出る。
- 器は共有のダイアログと同じ `<dialog>`（`ShareDialog`、ADR 0078）。キャンバスの
  形を変えない。

### Excalidraw の「ヘルプ」とは名前で分け、並べて置く

置き換えない。キャンバスの操作の案内も要る。名前を「etoki の使い方」にして、
どちらの説明かを項目の名前で分ける。

### 心得を手順より先に書く

最初の節で「描いているあいだは issue や epic のことは考えなくてよい」
「読むのはフレームで囲んで絵にした範囲だけで、囲むのは描き終えてから」と言う。
手順だけを並べると、「先に枠を決めてから描く」使い方に寄りやすい（中核思想 1）。

### 状態・粒度・種別の語は表から引く

`STATE_LABEL` / `GRANULARITY_LABEL` / `DIAGRAM_KIND_LABELS` を引いて書く。
書き写すと、表を直した日に使い方だけが古い語で説明する。ボタンの語は部品に
直書きされていて引けないので、本文に書き写す。そのぶん、ボタンの文言を変えた
日に使い方だけが古くなりうる。表に寄せ直すのは、ボタンの語を表に移す変更に
なり、使い方のためだけに部品を動かすことになるので今回は採らない。

### 開いたら焦点を見出しに置く

ブラウザの既定では最初の押せるもの（いちばん下の「閉じる」）に焦点が行き、
そこまでスクロールして心得が画面の外に出る。閉じたら、開いた口へ焦点を戻す。
メニューから開いたときは項目がメニューごと消えているので、メニューの口へ戻す
（`ShareDialog` と同じ）。

## 採らなかった案

- **キャンバスに説明を描いて置く（空のボードの下書き）。** 説明が描いたものと
  同じシーンに入り、消し忘れると `content_hash` と解釈の入力に並ぶ。ひな形が
  絵だけを置く（ADR 0047）のと同じ理由で採らない。
- **ボードの一覧にも入口を置く。** 使い方が要るのはキャンバスの前で、一覧からは
  ボードを開けばすぐ届く。要るようになったら足す。
- **README に書いて画面からリンクする。** README は動かす人に向けた文書で、
  画面を使う人の目には入らない。
