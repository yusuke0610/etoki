# 0027: 描画に失敗しても真っ白にしない（境界はキャンバスの外側に置く）

ステータス: 採用

## 文脈

Error Boundary が 1 枚も無かった。React はレンダリング中の例外を受け止める境界が
無いとツリー全体を unmount するので、どこか 1 箇所の描画が落ちると `#root` が空に
なり、画面が真っ白になる。

**ボードのシーンは、保存するまで Excalidraw のメモリにしかない。** 真っ白に
なった時点で、そこまでのブレストは取り返せない。ADR 0021 で入れた離脱の確認は
`beforeunload` と `window.confirm` の話なので、この経路は通らない。ページは
開いたまま、中身だけが消える。

失敗そのものもどこにも残らない。`logger.ts` は「フロントで完結する失敗が残らない」
ことを直すために置いたが、`log.error` を呼ぶのは catch した箇所だけで、捕まえて
いない例外は console のスタックだけになる。境界が無いので、捕まえる場所が無い。

## 決定

**境界を 2 層に置く。パネルは手前で受け、キャンバスを巻き込ませない。**

- **`BoardPage` のパネル（注釈・メンバー）を 1 枚ずつ包む。** この 3 つ
  （`MemberPanel` / `Excalidraw` / `AnnotationPanel`）は兄弟なので、パネルだけを
  潰せばキャンバスは載ったまま残る。**描いたものは画面に在り、保存ボタンも押せる。**
- **`main.tsx` で `App` を包む。** ここは最後の受け皿。ここまで来るとツリーごと
  外れているので、未保存のものはもう戻らない。
- **外側の 1 枚だけにしない。** それだと落ちた瞬間にキャンバスごと消え、理由は
  出せても失ったものは戻らない。境界を置く意味の大半はここにある。

**出口は巻き込んだ範囲で変える。** パネルは「再表示」（子を作り直す）、外側は
「読み込み直す」。**読み込み直す側では、未保存のものが失われていることを先に言う。**
消えた後に「消えた」と気づかせない。

**救い出す手段は入れない。** 境界が発火した時点で `ExcalidrawImperativeAPI` の
参照が生きている保証は無く、localStorage への定期退避を入れると「確定させるのは
人間の保存だけ」（ADR 0021）に別の下書きが並ぶ。パネルを手前で受ける形にした
ことで、いちばん起きやすい経路ではキャンバスが生き残り、人間が保存を押せる。
Excalidraw 本体が落ちた場合は救えない。手元に落とす手段は #42（`.excalidraw` の
書き出し）が入ってから改めて判断する。

**例外の中身は画面に出さない。** 利用者に読めないものが増えるだけで、打てる手は
変わらない。行き先を console に固定し、そこに出したことだけを画面で伝える。

**境界が拾わない経路（イベントハンドラの中と Promise の reject）は console に
残すだけにする**（`logUncaught`）。この経路には差し出せる出口が無く、画面に
出すと害の無い reject まで画面を塞ぐ。**残らないことだけを直す。**

## 結果

注釈パネルが落ちても、キャンバス・保存ボタン・ボード名は残る。`web/e2e/errors.spec.ts`
が API の応答を壊してこれを固定しているので、**境界を外側の 1 枚に戻すと落ちる。**

真っ白にはならなくなったが、**落ちた範囲は使えないまま**である。再表示は同じ
入力で作り直すので、原因が応答そのものにあるなら同じ場所で落ち続ける。それでも
キャンバスは残るので、保存してから読み込み直せる。

**開発ビルドでは、境界が受け止めた例外が console に二重（以上）に出る。**
React は DEV でだけ例外を window へ投げ直すので、`logUncaught` 側にも同じものが
「捕まえていない例外」として現れる。`StrictMode` の二重描画ぶんも重なる。
投げ直されたものだけを見分ける手が無く、間引くと本当に誰も捕まえていない例外まで
消えるので、そのままにしてある。本番ビルドでは投げ直されない。

見せ方（文言と配色）は #62 の UI 見直しと揃える余地がある。いまは `.error`
（既存のエラー表示）と同じ配色に寄せ、注釈パネルの代わりに出るときだけパネルと
同じ幅に収めてある。広がるに任せると、落ちた範囲が実際より大きく見える。
