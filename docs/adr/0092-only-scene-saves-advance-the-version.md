# 0092. 版を進めるのはシーンの保存だけにし、ほかの書き込みの応答の版は基準にしない

- 状態: 採用
- 日付: 2026-10-23
- ADR 0037 の結果の 1 行（「更新は `updated_at` を進める」）を改める

## 背景

ボードの `updated_at` は版で、シーンの保存の照合に使う（ADR 0020）。意味は
「何番目の保存か」に近い。

ボードの行を書く口は、保存のほかにも 4 つある。改名、作成先の設定、表示名の
取り直し、画像の移行。**どれが版を進めるかを決めた ADR が無く、決め方が割れて
いた。**

| 書き込み         | 版       | 出どころ                         |
| ---------------- | -------- | -------------------------------- |
| 改名             | 進めない | 760c100（#40）のコミット本文     |
| 画像の移行       | 進めない | ADR 0074                         |
| 作成先の設定     | 進める   | 理由の記録なし                   |
| 表示名の取り直し | 進める   | ADR 0037「ボードの行が変わった」 |

`.claude/rules/validation-boundaries.md` は「作成先や表示名の更新で版を前に出すと、
シーンを編集中の別の利用者に理由のない 409 が出る」と書いていて、0037 と逆だった。
実際に、owner が表示名を取り直すと（固定後も押せる）、同じボードを描いている別の
メンバーの次の保存が、誰もシーンを触っていないのに「他の人が保存しました」で
断られていた。

もう 1 つ、画面の側にも穴があった。画面は改名と表示名の取り直しの応答で手元の
ボードを差し替え、**版もそのまま置いていた。** 応答の版はサーバーのいまの版なので、
開いたあとに別のメンバーが保存していれば、その版になる。保存の基準がそこへ進み
（`useSceneSave`）、こちらの次の保存は照合を通って、**読み込んでいない相手の保存を
黙って上書きした。** ADR 0020 が塞いだはずの後勝ちが、改名を 1 回挟むだけで戻る。

## 決定

### 版を進めるのはシーンの保存だけ

照合したいのは、シーンの書き込みどうしの衝突である。名前や作成先の書き込みは
シーンを変えないので、版を進める理由が無い。**作成先の設定（`UpdateTarget`）と
表示名の取り直し（`UpdateTargetDisplay`）も、改名と同じく `updated_at` を書かない。**

**`port.BoardRepository` の 2 つの口から、更新時刻の引数を外す。** 公開の口
（`port/`、ADR 0001）の破壊的な変更になる。それでも外すのは、引数が残っていると、
口を実装する人が「渡されたので書く」と読むため。外せば、外部の実装はコンパイルの
段で引数が消えたことに気づく。

### ほかの書き込みの応答の版は、保存の基準にしない

画面は改名と表示名の取り直しの応答で手元を差し替えるが、**版は手元のものを持ち
越す**（`web/src/app/App.tsx` の `replaceBoard`）。基準にしてよいのは、自分の保存の
応答と、シーンごと読み直したときの版だけ。

上の決定で 2 つの口は版を動かさなくなったので、持ち越しても自分の操作で基準が
ずれることは無い。

## 採らなかった案

- **ボードの行が変わったら版を進める**（ADR 0037 の線）。表示名を取り直しただけで、
  描いている人の保存が断られる。改名で避けたのと同じ形で、片方だけ避ける理由が
  無い。
- **作成先の設定だけは進める。** 作成先を選び直すとキャンバスごと読み直すので、
  選んだ本人は困らない。ただ、同じボードを開いている別のメンバーにとっては、
  作成先が変わったこととシーンの版は関係が無い。シーンが変わっていない以上、
  保存を断る理由にならない。
- **応答の版をそのまま基準にし、画面の側で辻褄を合わせない。** 版を進めない口
  だけにしても、応答の版は「サーバーのいまの版」なので、相手の保存を含みうる。
  口の側を直すだけでは、上の上書きは塞がらない。

## 結果

- 作成先の設定と表示名の取り直しのあとも、ほかのメンバーの保存は断られない。
  改名のあとに相手の保存を上書きしなくなった（`web/e2e/boards.spec.ts`）。
- **ボード一覧の並び（`updated_at` の新しい順）は、作成先の設定や表示名の取り直し
  では動かない。** 改名と同じで、上に来るのは最後にシーンを保存したボード。
- `port.BoardRepository.UpdateTarget` と `UpdateTargetDisplay` のシグネチャが
  変わる。外部の実装は時刻の引数を外す。
