# 0053: login は最後にログインした 1 人に絞り、渡す前に相手を見せる

ステータス: 採用

## 文脈

招待と `etoki claim` は login で相手を指す。「一度ログインした相手だけを招待
できる」（ADR 0017）は、**改名で空いた login を取った別人に権限が渡る**のを
防ぐための規則だった。

実装はその相手を取り違えていた（#142）。

- `users` の一意制約は `(provider, subject)` だけで、login は本人がログインした
  ときにしか書き換わらない。A が bob から改名して etoki に入り直さないうちに、
  空いた bob を B が取ってログインすると、**login が bob の行が 2 つ並ぶ。**
- 引き当ては並び順の決まらない `SELECT` で、実際に試すと**先に入った A の行が
  返った。** owner が B のつもりで bob を招待すると A に、`etoki claim bob` なら
  所有者の無いボードが全部 A に渡る。規則が守ろうとした相手を、規則の実装が
  取り違えていた。
- 比較が大文字小文字を区別していた。GitHub の login は区別しないので、Alice で
  ログインした人を alice で招待すると「まだログインしていない」と断られた。

**etoki だけでは完全には直らない。** 手元の `users` が知っているのは「最後に
ログインしたときの login」までで、いまの持ち主が誰かは GitHub にしか分からない。

## 決定

**login の引き当ては最後にその login でログインした 1 人に絞る。そのうえで、
権限を渡す前に引き当てた相手を見せて、人に確かめさせる。**

- **ログインのたびに、同じ login（大文字小文字を無視）を持つ他の行から login を
  外す。** 行は消さない。ボードの所有者とメンバーが ID で指している。外された
  本人が入り直せば、新しい login が書かれる。
- **DB でも同じ login を 2 行に持たせない**（`(provider, login COLLATE NOCASE)` の
  一意索引、外した空文字は除く）。移行では、同じ login の行のうち最後に
  ログインした 1 行だけに login を残す。
- **招待の前に、引き当てた相手を見せる。** 表示名・login・ID・最終ログインを出し、
  「改名で空いた login を別の人が取っていないか」を確かめてもらってから送る。
  引き当ての口は owner だけに開く。未ログインを 400 で返すのは招待と同じで、
  **新しく漏れる情報は無い。**
- **招待は、確かめた相手の ID も一緒に送る。** 確認してから押すまでのあいだに
  持ち主が変わっていたら、招待せずに `invitee_changed` で断る。login だけで
  受けると、確認を飛ばす経路が残る。
- **`etoki claim` も同じ情報を出して `y/N` で確かめる。** 既定は止める。確かめ
  られない入力（端末でない標準入力）では、`--yes` を明示しない限り進めない。

### 残る穴

**B がまだ etoki にログインしていないあいだは、A の古い行が bob を名乗り続ける。**
ログインしていない B のことを etoki は知らないので、DB の側では塞げない。
確認で見せる最終ログインが古いことが、ここを見分ける材料になる。

### 採らなかった案：招待のたびに GitHub に訊く

`GET /users/{login}` の `id` と `subject` を照合すれば、取り違えは起きなくなる。
採らないのは、**招待を GitHub の可用性とトークンに依存させる**ため。ADR 0017 は
「招待するのに GitHub は見ない」と決めていて、ブレストに呼ぶ相手を決める操作が
GitHub の障害やレート制限で止まるのは、その判断を覆す。`etoki claim` は
サーバーの外から DB に直接当たる CLI で、利用者のトークンを持っていない。

## 結果

- 改名で同じ login が 2 行になっても、引き当ては最後にログインした人になる。
- 大文字小文字だけが違う login でも招待できる。
- 招待と claim は、相手を見せてからでないと権限を渡さない。
- 移行で login を外された行は、本人が入り直すまで login では引けない
  （一覧には表示名で出る）。
