# 0075. ボードの置き方は Excalidraw のモバイル判定の式に揃える

- 状態: 採用
- 日付: 2026-10-09

## 背景

UI の作り直し（#62）は広い画面だけを見て進めていた。右のパネルは 320px で
キャンバスの横に並び、狭い画面ではキャンバスがほとんど残らない（#199）。

もっと困るのは、**Excalidraw（0.18.1）がモバイル用 UI に切り替える条件が、画面
ではなくキャンバスの枠の大きさで決まる**ことだった。条件は「幅 730px 未満、
または高さ 500px 未満かつ幅 1000px 未満」で、定数（`MQ_MAX_WIDTH_PORTRAIT` /
`MQ_MAX_HEIGHT_LANDSCAPE` / `MQ_MAX_WIDTH_LANDSCAPE`）はどれも公開されていない。
パネルを横に並べてキャンバスを押し縮めると、1024px の画面でもキャンバスは
704px になり、モバイル用 UI に切り替わる。

モバイル用 UI では etoki の部品の出方が変わる。`renderTopRightUI` はツールバーと
同じ行に詰められ、**`Footer` は描かれない。** 下の帯のロール・作成先・
「作成先は確定」・大きさが消え、状態を常に見せる約束（ADR 0064 / 0065）が崩れる。

## 決定

### 置き方を 3 つにし、境目は Excalidraw の式を写す

| 置き方 | 条件（W, H はキャンバスが使える領域の幅と高さ） | 右のパネル                                | 右上・下の帯の中身          |
| ------ | ----------------------------------------------- | ----------------------------------------- | --------------------------- |
| 並べる | `!isMobileBreakpoint(W - パネルの幅, H)`        | キャンバスの横に並べる                    | 拡張点（ADR 0065）          |
| 重ねる | 並べるでもスマホでもない                        | キャンバスに浮かせる                      | 拡張点（ADR 0065）          |
| スマホ | `isMobileBreakpoint(W, H)`                      | 既定で畳む。開くと帯の 1 段目の下を全面に | キャンバスの上の etoki の帯 |

判定は `web/src/board/layout.ts` の純関数 1 つで、`isMobileBreakpoint` は
Excalidraw の式と定数の写し（写した版と定数の名前をコメントに書く）。**別の境目を
持たない。** 持つと、片方だけが切り替わった幅ができる。

**並べる条件は「並べてもキャンバスがモバイル用にならないこと」にする。** 重ねる
ときはキャンバスの枠が領域のままなので、Excalidraw の判定とスマホの判定が同じ
大きさを見ることになり、揃う。パネルの幅は CSS の変数（`--side-panel-width`）
1 つから読み、TypeScript に写さない。**パネルの幅は境界線まで含める**
（`box-sizing: border-box`）。線の 1px が外に足されていたので、並べる境目
ちょうど（1050px）でキャンバスが 729px になり、Excalidraw だけがモバイル用 UI に
なっていた。

写しが古くなったことには、ライブラリを上げたときに `web/e2e/layout.spec.ts` の
「置き方と Excalidraw の判定が揃っている」で気づく。実物の `excalidraw--mobile`
を、境目の両側で見ている。

### 測るのは画面ではなく、注意の帯を除いた枠

issue の案は Excalidraw と同じく `document.body` の大きさで測ることだったが、
**採らなかった。** 衝突・上限超え・削除の確認の帯はキャンバスを押し下げるので、
画面の大きさで決めると、帯が出ているあいだだけ Excalidraw がモバイル用 UI に
なり、etoki は「重ねる」のまま下の帯の中身が消える幅ができる（900 × 520 で
上限超えの帯が出ると起きる）。

測るのは、帯を除いた領域（etoki の帯・キャンバス・パネルを包む枠）を
`ResizeObserver` で。**etoki の帯はこの枠の中に置く。** 外に置くと、帯を出した
ことで枠が縮んで判定が動き、同じ大きさの画面で置き方が履歴に依存する。

### 右上の島の出し分けは etoki の置き方で決める

`renderTopRightUI` は、スマホの置き方では何も返さない。**引数の `isMobile`
（Excalidraw の判定）では決めない。** 島をどこに描くかを 1 つの判定で決めて
おけば、2 つの判定がずれた幅でも島は etoki の帯か右上のどちらか 1 か所に出る。
`isMobile` で返さないと、ずれた幅で島がどこにも無くなり、保存が押せなくなる。
`Footer` はそのまま渡しておく（モバイル用 UI では描かれないだけ）。

### スマホ

- **機能は絞らない。** 解釈と GitHub への作成まで、どの幅でも使える。幅で
  変わるのは置き方だけにする。
- **キャンバスの上に etoki の帯を 2 段置く。** 1 段目はボード名・未保存・保存、
  2 段目はパネルを開くボタン 3 つと下の帯の中身。2 段目は横に流し、はみ出したら
  横にスクロールさせる（どの画面も横スクロールを出さない約束の、唯一の例外）。
- **全面のパネルと注釈の詳細は、帯の 1 段目を覆わない。** 重ねるときに上を
  空けるのと同じ理由（ADR 0021）で、保存と「未保存」はいつも見えている。保存を
  押せるので、パネルも詳細もモーダルにしない（詳細と同じモードレス、ADR 0065）。
- **右端の縦の帯（#202）は出さない。** 開く口は上の帯の 2 段目にあり、画面の
  右端をキャンバスから取らない。開閉は覚えず、いつも畳んだ状態で始める。
  閉じたら、開いたボタンへ焦点を戻す。
- **置いた図と「キャンバスで見る」の先を見せるために、パネルを閉じる。** 図の
  ドラフトと mermaid の貼り付けは、置けたときだけ閉じる（置けなかったら理由を
  読ませる）。詳細の「キャンバスで見る」は、詳細と一緒にパネルも閉じる。どれも
  開発者が押した操作の結果で、何かを自動で判断しているわけではない（中核思想 3）。
- 画面全体の通知（ADR 0058）は下に出す。上は状態を出している帯で、下に並ぶ
  Excalidraw の操作は閉じるまで隠れるだけで済む。

### 重ねる

- パネルはキャンバスの右に浮かせ、**上下 72px を空ける。** 上は右上の島（保存と
  「未保存」）を、下は下の帯と Excalidraw の右下のヘルプを隠さないため。畳んだ
  帯も同じ位置に重ねる。開閉は並べるときと同じく覚える（#202）。
- **注釈の詳細は、浮かせたパネルを避けて残りの幅に開く。** 並べるときと同じく、
  詳細を開いたまま隣のカードを押せる。

## この判断を見直すとき

Excalidraw を上げて、モバイル用 UI に切り替える式か定数が変わったとき。
`layout.spec.ts` が落ちるので、`layout.ts` の写しを直す。モバイル用 UI で
`Footer` を描くようになったら、帯に移す理由の半分が消える。

## 採らなかった案

- **スマホでは描く・保存する・状態を見るだけにし、解釈と作成は「広い画面で
  開いてください」と出す。** 同じボードでも、開いた端末によってできることが
  違ってしまう。
- **右のパネルを下から出すシートにする。** 指で引く操作を自前で作ることになり、
  Excalidraw の下のツールバーとも重なる。
- **`document.body` の大きさで測る。** 上の「測るのは画面ではなく」のとおり、
  注意の帯が出ている幅で 2 つの判定がずれる。
- **`renderTopRightUI` を引数の `isMobile` で出し分ける。** 上のとおり、判定が
  ずれた幅で島が消える。
- **全面のパネルと詳細を画面全体（`inset: 0`）にし、モーダルにする。** 開いて
  いるあいだ「未保存」が見えず、保存も押せない。詳細で粒度を変えて保存する
  流れ（ADR 0065）が、閉じて開き直す往復になる。
- **重ねるとき、詳細をキャンバスの中央に開いてパネルの上に重ねる。** 詳細を
  開いたまま別のカードを押せなくなる。並べるときにはできていたことが、幅で
  できなくなる。
