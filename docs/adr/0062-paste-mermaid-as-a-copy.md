# 0062. 既存の設計（mermaid）は写しとして貼り、図形にして置くだけにする

- 状態: 採用
- 日付: 2026-09-27

## 背景

既存のプロジェクトの設計図（ER 図など）を前提に、etoki でブレストしたい
（#181）。今は写しとして持ち込む手段が無い。

| 今ある経路                   | 写しとして使えない理由                                                 |
| ---------------------------- | ---------------------------------------------------------------------- |
| ボードの取り込み（ADR 0045） | `.excalidraw` しか読めない。ボードを丸ごと置き換える                   |
| 画像の貼り付け               | 手で直せない。テキストの一覧に入らないので `content_hash` にも効かない |
| 図のドラフト（ADR 0041）     | 入力は開発者の文章だけ。mermaid を直接貼る口が無い                     |

**etoki を設計の正本にはしない。** etoki は版の管理も逆方向の同期も持たない
（ルートの `CLAUDE.md` のスコープ外）ので、正本にすると必ず古くなる。制約付きの
ER 図を Excalidraw の図形にすると、PK / FK / 多重度は「それらしい絵」になり、
制約としての意味を失う。流れは「写しを持ち込む → 議論する → issue にする →
issue を片付ける PR が正本を直す」。

## 決定

### mermaid のテキストを貼ると、図形に変換して空いている場所に置く。LLM は通さない

部品は図のドラフトのものをそのまま使う。変換と置けないときの判定は
`mermaidToElements`、置き場所は `draftOrigin` / `moveDraft`、frame を拒む門番は
ADR 0040。**バックエンドと OpenAPI は変えない。**

- **置くだけで、保存は人が押す**（中核思想 3）。
- **frame を作らない。** 囲むのは人（ADR 0047）。
- **種別は自動で付けない。** `erDiagram` を貼っても、ER 図の種別は注釈パネルで
  人が選ぶ（ADR 0047）。貼った文字列の書き出しで種類を判定するのは次の前検査の
  ためだけで、注釈には流さない。
- **LLM を設定していなくても使える。** `capabilities.diagramDraft` で止めると、
  LLM を通さない機能が LLM の設定に縛られる。**viewer には出さない。** 描いても
  保存できない（ADR 0017）。

### 入口はヘッダーのボタンと、キャンバスの左のパネル（論点 C）

図のドラフトのパネルに相乗りする案は採らない。LLM の会話と混ざり、LLM の有無で
出し分けにくい。**左の枠は 1 つにして、図のドラフトと貼り付けのどちらか一方だけを
開く。** 並べるとキャンバスが狭まり、置いた図を見ながら直すという、左に置いた
理由（ADR 0041）が崩れる。

### ADR 0061 の見直し: 入口で絞り、CSS の注入は受け入れる

ADR 0061 は mermaid を 11.13.0 に固定し、残る脆弱性を「mermaid に渡る文字列は
本人のプロンプトから LLM が作ったものだけ」という理由で受け入れた。貼り付けは
その前提を崩す。**貼る文字列は他のリポジトリや他人の文書から来る。** 変換器は
描いた SVG を etoki のページの DOM に一時的に差し込む（`svgContainer.innerHTML`）
ので、mermaid の穴はそのまま etoki のオリジンで開く。`securityLevel: "sandbox"`
にすると変換器が SVG を読めないので、この手は使えない。

11.13.0 に残る advisory ごとに、次のように扱う。

| advisory                                  | 経路                                                             | 扱い                                                                                                            |
| ----------------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| gantt / radar / xychart                   | 描くだけで無限ループ。**タブが固まり、未保存のブレストが消える** | **塞ぐ。** 受け付ける種類を絞り、mermaid に渡す前に拒む                                                         |
| architecture                              | プロトタイプ汚染                                                 | **塞ぐ。** 同上                                                                                                 |
| GHSA-ghcm-xqfw-q4vr                       | state 図の `classDef` による HTML の注入                         | **塞ぐ。** state 図を受け付けない                                                                               |
| GHSA-87f9-hvmw-gh4p                       | `%%{init}%%` と frontmatter の `themeCSS` などによる CSS の注入  | **塞ぐ。** 変換器に渡す設定の `secure` に `themeCSS` / `fontFamily` / `altFontFamily` / `themeVariables` を足す |
| GHSA-xcj9-5m2h-648r / GHSA-6x64-9x62-f2gx | `classDef` や兄弟セレクタによる CSS の注入                       | **受け入れる**                                                                                                  |
| GHSA-c4c3-pg64-4m4v                       | JS の設定 API だけ                                               | 図の文字列からは届かない                                                                                        |

**受け付けるのは `erDiagram` / `sequenceDiagram` / `flowchart`（`graph`）の 3 種。**
class 図と state 図も 11.13.0 では図形になるが、state 図に HTML の注入が残るので
入れていない。判定は mermaid が種類を見分けるのと同じ手順（frontmatter・
`%%{…}%%`・`%%` コメントを取り除いて先頭の語を見る）で行い、取り除き方の正規表現は
mermaid から写した。ずれると、etoki が erDiagram だと思った文字列を mermaid が
gantt として描く抜け道になる。

**残る CSS の注入を受け入れる理由。**

- JS は実行されない（各 advisory が明記している）。
- 差し込まれるのは変換のあいだだけで、終われば SVG ごと外される。
- 貼った文字列はシーンに残らない。シーンに載るのは Excalidraw の要素なので、
  共有ボードを開いた他のメンバーのブラウザでは mermaid は走らない。**影響を
  受けるのは貼った本人の画面だけ。**
- 手元で試した範囲では、flowchart と ER 図の `classDef` / `style` に素朴な注入を
  書くとパーサが構文エラーで弾いた。

`secure` で塞げていることは E2E（`web/e2e/mermaidPaste.spec.ts`）がビーコンへの
要求で見ている。`secure` から外すと要求が飛んで落ちる。**`secure` は変換器が
`mermaid.initialize` にプロセス全体で効かせるので、図のドラフトにも同じ設定が
効く**（経路ごとに分けても、最後に呼んだ側の設定になるだけ）。

### mermaid の上限を超える長さは、変換の前に拒む

mermaid は 5 万字を超えると**投げずに**、図を「Maximum text size in diagram
exceeded」と書いた 1 ノードにすり替える。何もしなければ、それが置けたものとして
置かれる。上限は変換器に渡す設定と前検査で同じ定数（`MERMAID_MAX_TEXT_SIZE`）
から出す。**保存の上限（ADR 0038）とは別物。** あちらはサーバーだけが持つ
シーンの大きさで、こちらは手元のライブラリが変換できる文字列の長さ。

### 全体を囲む ` ```mermaid ` のフェンスは 1 組だけ剥がす

GitHub の README や issue から写すと付いてくる。**全体が 1 つのフェンスで
囲まれているときだけ**剥がす。前後に文がある Markdown や複数の図から、どれを
置くかを etoki が選ぶことはしない。

### 失敗したら、パーサのメッセージを畳んで見せる（論点 D）

図のドラフトでは構文エラーを LLM に自動で頼み直していた（#59 / #61）。人が
貼ったものは頼み直す相手がいない。**どこが読めなかったかは、mermaid の位置
つきの英文にしか無い。** なので `web/CLAUDE.md` の「例外の中身は画面に出さない」
の例外にする。前に出すのは固定文で、パーサのメッセージは `<details>` に畳む
（サーバーの本文と同じ扱い、ADR 0034）。例外にするのは構文エラーだけで、
画像や frame で返ったときの変換器の文言は出さない。そちらは貼った人の打ち手が
変わらない。

失敗の文は図のドラフト（「種類を変えて」）と分ける。あちらは LLM への頼み方の
話で、貼った人が直すのは貼ったもの。

### 属性が断片になることは受け入れる（論点 B）

変換器は ER 図の属性を、実体の矩形の中身（`containerId`）ではなく、罫線と
ばらばらのテキストで返す（`int` / `id` / `PK` が別々の要素）。囲むと
`AnnotationTexts` は「実体名 → 関連のラベル → 全実体の属性の断片」の順に並ぶ。

- どの属性がどの実体のものかは、注釈範囲の画像（ADR 0018）で伝わる。写しの
  用途ならこれで足りる。
- **変換器は属性を持つ実体ごとに、矩形・罫線・属性へ同じ `groupId` を振る。**
  置いた後も実体単位でまとめて動かせる（E2E で固定してある）。
- 属性を実体ごとに 1 つのテキストにまとめる案は採らない。変換器の出力を etoki が
  組み替えることになり、「骨格から要素への詰め替えはライブラリに任せる」線
  （`mermaid.ts`）を越える。

### 取り込み元の印は付けない（論点 E）

「取り込み元・日時」を書いたテキストを図の横に置けば、写しであることが見て
分かる。ただ、囲むと解釈の入力と `content_hash` に入り、日時を含むと同じ図を
貼り直しただけで状態が「変更あり」に落ちる。写しだと書きたければ、人が付箋で
書けばよい。代わりにパネルに「議論のための写しとして置きます。正本は元の場所の
ままです」と出す。

## 残っている経路

**上の守りは etoki の口（図のドラフトと貼り付け）にしか効かない。** Excalidraw
自身の「Mermaid to Excalidraw」ダイアログがキャンバスの「その他」メニューから
開け、そこに貼った mermaid は種類の絞り込みも `secure` も通らずに描かれる。
この判断の範囲の外にあり、今回の変更より前から開いていた。扱いは #187 で
決める。

## 範囲の外（需要が見えてから）

| 形式                       | 入れない理由                                                                                                      |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| drawio（`.drawio` の XML） | 公式の変換器が無い。図形の対応表と崩れの扱いを自前で抱えることになる。当面は drawio 側で mermaid か画像に書き出す |
| DDL / SQL                  | LLM で `erDiagram` に書き直させることになる。列が黙って落ちても気づけず、写しとして正確か保証できない             |

## この判断を見直すとき

- **mermaid の固定（ADR 0061）を外したとき。** 新しい mermaid で CSS の注入が
  直っていれば、受け入れた分は消える。`secure` の追加分は残してよい。
- **受け付ける種類を増やすとき。** 増やす種類に残る advisory を先に確かめる。
  class 図は注入の advisory が名指ししていないが、state 図と同じ `classDef` を
  持つので、確かめてから入れる。
- **貼った文字列を保存する・他のメンバーに見せるようになったとき。** 「影響を
  受けるのは貼った本人の画面だけ」が崩れ、CSS の注入を受け入れた理由が
  成り立たない。
