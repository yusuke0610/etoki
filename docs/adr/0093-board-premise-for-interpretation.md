# 0093. 解釈に添える背景をボードに持たせ、ハッシュには入れない

- 状態: 採用（#68）
- 日付: 2026-10-24
- ADR 0047 が種別をハッシュに入れた理由づけを、ハッシュに入れる基準として
  言い直す

## 背景

解釈に渡っているのは、囲みのテキスト（先頭に囲みの名前）、囲みを写した画像
（ADR 0018）、その囲みから前回までに作ったもの（ADR 0026）、種別と粒度の
指示だけである。LLM は次のことを知らないまま読んでいる。

- どのリポジトリの話か。技術スタックも、そこでの呼び方も知らない
- チームの用語や前提。人が書いておける場所が無い
- 同じボードの別の絵から何を作ったか。同じ Project に何度も作るのに、
  別の絵のぶんは見えていない

結果として、重複した issue が生まれ、粒度がばらつき、用語が揺れる。使い
続けるほど効いてくる種類の欠落である（#68）。

出口の側も薄い。draft issue の body に入るのは LLM が囲みから起こした文
だけで、着手に要る背景（どの技術か、どの制約か）は載らない。作った issue を
そのまま実装に渡すと、結局人が書き足すことになる。

## 決定

### ボードに「背景」を 1 つ持たせ、人が書く

**単位はボード。** Project 単位は採らない。etoki は Project のメンバーという
概念を持たず（GitHub の権限は複製しない、ADR 0017）、誰が編集できるかを
決める材料が無い。作成先を持たないボード（ADR 0090）でも使えなくなる。

**置き場は `boards` の列で、シーンには入れない。**

- 背景はブレストの外に置く（中核思想 1）。キャンバスに書く場所を作ると、
  ブレスト中に「背景を書かなきゃ」が増える。
- シーンに入れると、背景を直すたびにシーンの版が進み、キャンバスを編集中の
  別のメンバーの保存が、誰も描いていないのに 409 になる（ADR 0020 / 0092）。

**読むのは viewer 以上、書くのは editor 以上。** 書く側は改名と同じで、
作成先のように取り消せない作成の行き先を決めるものではないので、owner に
絞る理由が無い。viewer にも読ませるのは、ボードの中身が共有した相手には
すでに全部見えている（ADR 0017）からで、隠す理由が無い。

**既定は空で、空でも催促しない**（中核思想 1）。ひな形の選択からも埋めない。
ひな形と種別を自動で結ばない（ADR 0047）のと同じで、ひな形をなぞらずに
別の図を描く自由を奪う。

**背景に何を書くかは人に任せる。** 「矢印は呼び出しとして読む」と書いても
よい。中核思想 2 が禁じているのは etoki が読み方を決めることで、決めて
いるのが人なら当たらない。etoki は既定の文を入れない。入れた時点で、
決めているのが etoki になる。

### 画面では「ボードの背景」、コードでは `premise` と呼ぶ

画面の語は「背景」にした。ただしボードのメニューには Excalidraw の
キャンバスの背景色を選ぶ項目（`ChangeCanvasBackground`）が並び、コードにも
`viewBackgroundColor` が多く出てくる。**画面では「ボードの背景」と書き、
識別子（列・フィールド・契約）は `premise` にする。** 画面の語にそろえて
`background` にすると、どちらの背景かを読むたびに確かめることになる。

### 同じボードの別の絵から作ったものも渡す

その囲み以外の注釈から作ったもの（`ListItemsByBoard` の畳み込み）の種別と
タイトルを渡す。すでに DB にあり、問い合わせも増えない。重複と用語の揺れに
効く。

- **確定したものだけ。** 畳み込みは確定したものしか返さない（ADR 0056）。
- **シーンから消えた注釈のぶんも含める。** GitHub には在るので、重複を
  避ける材料としては同じ（ADR 0046）。
- **対応づけの対象にしない。** `p1` のような ref を振らない。更新先はその
  囲みの畳み込みに限る（ADR 0026）。ref を振ると、別の絵から作った draft
  issue が書き換えの候補に見える。
- **重なると思っても項目を落とさず、summary で触れるよう指示する。** 落と
  すかどうかを LLM に決めさせない。外すのは作成前の選択（ADR 0024）で人が
  行う（中核思想 3）。
- **上限は 100 件。** 超えたら打ち切り、渡さなかった件数を結果に添える
  （ADR 0054 と同じ形）。黙って打ち切ると、渡したつもりの材料が消えた
  ことに気づけない。
- **body に関連項目として挙げさせない。** draft issue は番号を持たずリンク
  できないので、タイトルの羅列になる。別の絵は読むための材料に留める。

### GitHub（README・既存の issue）は読まない

解釈はいま GitHub に一切触れていない。読むようにすると、GitHub が不通の
ときや、GitHub を組み立てていない構成（ADR 0090）で解釈が止まる。必要な
部分は人が背景に貼れば足りる。

足したくなったときの線は次のとおり。**ボードの内容を GitHub の情報で書き
換えたら逆方向同期（スコープ外）。読んで LLM に渡すだけなら参照。** 参照は
同期ではないが近いので、足すならこの ADR を書き換える。

### ハッシュに入れる基準を言い直す

ADR 0047 は種別をハッシュに入れる理由を「種別を変えれば LLM が読む前提が
変わる」とした。これを「入力に入るものはハッシュに入れる」と読むと、
**すでに成り立っていない。** 囲みの名前（ADR 0079）、画像と矢印（ADR 0018、
ADR 0047 の追記）、前回までに作ったもの（ADR 0026）は、どれも解釈の入力
だがハッシュに入っていない。

基準を次のように言い直す。

> ハッシュは「この囲みから作ったものが、囲みのいまの中身と食い違って
> いるか」に答える。入るのは、囲みの中に人が書いたもの（子のテキスト）と、
> 囲みの読み方として人が選んだもの（粒度と種別）だけ。囲みの外から添える
> 材料は、LLM の入力であってもハッシュに入れない。

背景も別の絵の一覧も囲みの外の材料なので入らない。入れると、背景を一言
直しただけでボードの全注釈が一斉に「変更あり」になり、戻す道が絵解き直し
（課金を伴い、ADR 0044 の枠に数える）しか無い。名前をハッシュから外した
理由（ADR 0079）と同じ。

**黙らない。** 背景の編集画面と、絵解きの面の「作成済みのままになる変更」の
注記に、背景を変えても作成済みの絵は作成済みのままだと書く（ADR 0047 の
追記、ADR 0079 と同じ「言うだけ」）。読み直すかどうかは開発者が選ぶ
（中核思想 3）。

**作成時の照合（ADR 0010）は背景の変更で止まらない。** 作られるのは確かめた
下書きで、照合が守るのは囲みの中身のほう。

### ジョブの鍵には背景を入れる

鍵は「保存で、LLM に渡すものが変わったか」に答える（ADR 0085）。背景の保存は
それを変える。入れないと、背景を直して押し直したときに、古い背景で走って
いるジョブが返る（#321 で囲みの名前について起きたのと同じ形）。

別の絵の一覧は入れない。変わるのは保存ではなく作成で、前回までに作った
ものを鍵に入れない理由（ADR 0085）と同じ。

### 渡したものを見せる

**解釈の結果に、渡した背景と別の絵の一覧（打ち切った件数を含む）を載せる。**
黙って材料を足して結果だけを返すのは、システムが自動で判断することそのもの
（中核思想 3）で、出力がなぜそうなったかを読めない。

**押す前に見せるのは背景だけ。** 背景はボードを開いた時点で手元にある。
別の絵の一覧を押す前に見せるには、どれを渡すかの規則を画面でも持つか、
読み取りの口を 1 つ足すことになる。前者は規則が 2 箇所になり、後者は
結果に載るものと同じものを別の口で返すだけになる。

### 背景を保存しても、引いた解釈は捨てない

結果に渡した背景が載るので、古い背景で読んだものだと見分けられる。
ハッシュに入らないので作成も通る。捨てると、背景を一言直すたびに、課金した
結果が消える。シーンの保存で捨てるのは、解釈が読んだテキストの出どころ
（保存済みシーン）そのものが変わるからで、囲みの外の材料が変わるのとは
事情が違う。

### 同時の編集は、編集を始めた時点の本文と照らす

一致しなければ 409 にする。**版の列は足さない。** 本文そのものを比べれば
足りる。同じ本文なら上書きしても何も失われない。シーンの版
（`updated_at`）は使わない（ADR 0092）。照合は書き込みと同じ 1 文に置く
（ADR 0020 と同じ理由）。

### 長さは 4,000 字まで。超えたら弾く

背景は毎回の解釈の入力に載る。上限が無いと、使い続けるほど 1 回の解釈が
重くなる。**切り詰めない。** 切り詰めると、書いたつもりの背景が LLM に
届いていないことに気づけない（ADR 0038 と同じ）。

### 出口の側は LLM に書かせ、etoki は付け足さない

背景があるときだけ、背景のうちその項目の着手に要るものを body に書くよう
指示する。書かれたものは、作成前の下書きで人が確かめて直す（ADR 0024）。

### どの背景で作ったかは run に控えない

今回は見送る。背景を書き換えると、過去にどの背景で作ったかは分からなく
なる。要るようになったら、作成の瞬間に控える形で足す（作成の瞬間に控え
なければ取れない、という ADR 0023 の理屈がそのまま効く）。

## 検討したが採らなかった案

### 背景の全文を body に付け足す

着手に要る背景が確実に載る。**採らない。**

- 全 issue に同じ文が載る。
- 作った後に背景を直すと古くなり、draft issue は一括では直せない。
- 前回までに作ったものとして LLM に戻る（ADR 0026）ので、毎回の入力に同じ
  文が重なる。戻すときに取り除くには目印が要り、人が下書きで直した body
  では目印が崩れる。

### 出口のための欄を別に持つ

解釈のための背景とは別に「issue に添える文」を人が書き、body の末尾に
付ける。上の 3 つの問題がそのまま残り、書く場所が 2 つになる。

### 背景をハッシュに入れる

ADR 0047 の理由づけを素直に延ばすとこうなる。上の「ハッシュに入れる基準を
言い直す」のとおり、背景を一言直すと全注釈が「変更あり」になる。

### 背景をシーン（appState）に持つ

ボードを書き出せば背景も一緒に持ち出せる。**採らない。** 背景を直すたびに
版が進んで保存が衝突し（ADR 0020 / 0092）、背景がブレストの成果物の一部に
なる（中核思想 1）。

## 影響

- `port.BoardRepository` にメソッドが 1 つ増える。外部のリポジトリで実装
  している場合は追従が要る（ADR 0001）。
- `make try-fake` の偽の LLM は、user メッセージの最初の空行より後ろには
  利用者の書いた文字が入らないとして目印を探している。背景と別の絵の
  タイトルが入るので、目印を探す範囲を見直す。
- 背景はボードの書き出し（ADR 0045）には載らない。書き出すのはキャンバスで、
  背景はシーンの外にある。
- 解釈 1 回の入力が増える（背景が最大 4,000 字、別の絵が最大 100 件）。
- 一覧（`BoardSummary`）には入れないので、MCP の `list_boards` には出ない。

## 実装で決めたこと

提案の時点で「実装の PR で決める」としていた 3 つのうち、サーバーの側で決まる
2 つを決めた。

- **100 件を超えたら、最近作った・更新したものから残す**（`usecase.MaxOtherItems`）。
  解釈の結果に、渡さなかった件数を添える。
- **背景が長すぎるときは専用の code（`premise_too_large`、413）で返す。**
  `invalid_input` に寄せない。中身の誤りではなく長さで、打ち手は「短くする」。
  背景の食い違い（`premise_conflict`、409）も、シーンの衝突と打ち手が違う（読み
  直すのはキャンバスではなく背景）ので、同じ code に畳まない。

残る 1 つ（背景の編集を書きかけのまま閉じたときの扱い）は、画面の PR で次の
ように決めた。あわせて、先に書き換えられていたときの見せ方も決めた。

- **書きかけのまま閉じても捨てない。** ダイアログの外（ボードの画面）で持ち、
  開き直すと続きから書ける。背景は 4,000 字まで書ける文で、共有の招待のように
  打ち直せば済む量ではない。
- **ボードを離れたら捨てる。「未保存」には数えない。** 「未保存」と右上の
  「保存」はシーンについてのもので、背景はシーンの外にある。数えると、「保存」を
  押しても背景は保存されず、「未保存」も消えない。名前の書きかけと同じ扱い。
- **先に書き換えられていたら（409）、いまの背景を取り直して書きかけと並べる。**
  照合の基準もいまの背景へ進めるので、見比べたうえで押し直せば上書きできる。
  押し直すかどうかは人が決める（中核思想 3）。背景を返す口は開く口だけなので、
  取り直すと貼った画像も一緒に届く。409 は 2 人が同時に背景を書き換えたときに
  しか起きないので、背景だけを返す口は足さない。
