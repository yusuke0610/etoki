# 0073. CSS は機能のディレクトリに置き、読む順は入口の @import で決める

- 状態: 採用
- 日付: 2026-10-07

## 背景

画面のスタイルが `web/src/index.css` の 1 ファイルにあり、10 日で 984 行から
2,178 行に増えていた（#230）。並びは足した順で、同じ領域の規則が離れた場所に
散っていた。作成先のバッジは 1,750 行目、ロールのバッジは 1,950 行目、
大きさのバッジは 2,091 行目にある。**注釈の詳細を直すときに読む範囲が、
ファイル全体になっていた。**

ソースは機能ごとのディレクトリに分けてある（ADR 0072）。CSS だけが 1 か所に
残っていた。

ただし CSS には、TypeScript には無い制約がある。**特異性が同じ規則どうしは、
後に読まれたほうが勝つ。** 読む順は見た目の一部になっている。etoki の CSS は
Excalidraw の CSS より先に読まれる前提で書いてあり、ライブラリの配色の上書きを
`:root:root .excalidraw` で書いているのはそのため（ADR 0065）。

## 決定

**CSS は、それを使う機能のディレクトリに置く。読む順は入口
（`web/src/index.css`）の `@import` の並びだけで決める。** 入口は規則を
持たない。

- **コンポーネントから CSS を import しない。** 読む順を決める場所を 1 つに
  保つため。
- **並びは、変数、画面をまたぐ土台と部品、各画面の規則の順にする。** 変数を
  先頭に置くのは、どの規則よりも先に定義を読ませるため。
- **多くの画面が使う規則（`.hint` や `.badge`）は `app/` に置く。** ADR 0072
  で `app/` は画面をまたいで使う道具の置き場になっている。2 つの画面だけが使う
  規則は、ADR 0072 と同じく先に使い始めた側に置く。

## 採らなかった案

- **各コンポーネントが隣の CSS を import する。** 置き場所の見通しはいちばん
  良い。ただ、読む順が import の辿り方で決まるようになり、コンポーネントの
  import を 1 行入れ替えただけで見た目が変わりうる。Excalidraw の CSS より先に
  読まれるという前提も、`App.tsx` より先に読まれるモジュールから import した
  ものにしか効かなくなる。
- **`web/src/styles/` に領域ごとのファイルを並べる。** 読む順の扱いはこの決定と
  同じになる。違うのは置き場所だけで、ADR 0072 が採らなかった「種類で分ける」
  形になる。注釈を直すときに、TypeScript と CSS で 2 か所を開くことになる。
- **CSS Modules にする。** クラス名が書き換わる。E2E はクラスで要素と格を
  見ている（`web/e2e/buttonTiers.spec.ts` など）。ライブラリの DOM に重ねる
  規則（`.excalidraw` の中）は、どのみちグローバルに書くことになる。

## 結果

- 分割は 2 段で行った。先に 1 ファイルの中で行き先ごとに並べ替え、次に
  切り出した。切り出しの前後で、ビルドした CSS がバイト単位で一致する。
- **ファイルをまたいで規則を移すと、カスケードの順が変わる。** 移した規則と、
  特異性が同じで同じ要素に当たる規則とのあいだで、勝ち負けが入れ替わりうる。
  移すときはその組を確かめる。
- **新しい部品の CSS は、その部品のディレクトリのファイルに足す。** 新しい
  ファイルを作ったら、入口の並びのどこに置くかを決めて `@import` を足す。
