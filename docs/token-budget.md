# トークンの予算

Claude Code の 1 セッションで消費するトークンのうち、**リポジトリが握れるぶん**を
測って記録する。issue #125 の「先に測る。当てずっぽうで削らない」に対応する場所。

## なぜ測るか

消費は読み込みの回数ではなく、**context の大きさ × ターン数**で効く。context は
毎ターンまるごと読み直されるので（`cache_read`）、規約を 1 字削ると残りのターン数
ぶん効き、1 字足すと残りのターン数ぶん取られる。

**「大きい」ことは材料にならない。** どこが大きいかを出さない限り、削る先は
当てずっぽうになる。規約を厚くすることでレビュー指摘を減らしてきた経緯があるので
（[ADR 0033](adr/0033-review-derived-rules.md)）、削りすぎたかどうかも数で見る。
効果は [`review-findings.md`](review-findings.md) の指摘件数と併せて読む。

## 測り方

```sh
make token-report              # 直近のセッション
make token-report SESSION=…    # JSONL のパスを指定する
```

Claude Code が手元に残す transcript（`~/.claude/projects/<作業ディレクトリ>/*.jsonl`）
を読む。API が返す `usage` は合計しか言わないが、transcript にはハーネスが
差し込んだ本文がそのまま入っているので、そこから内訳を組み立てられる。

**数えるのは文字数（コードポイント）で、トークンでもバイトでもない。**

- トークンで数えない。トークナイザに依るので、こちらでは再現できない。
- バイトで数えない。日本語が 3 倍に出て、英語との比較ができない。
- `wc -m` を使わない。ロケールに依り、C ロケールではバイト数になる。

**ツール定義（MCP を含む）は transcript に残らないので計測できていない。** 報告に
出る「計測できたぶん」は context の全部ではない。トークン数との比はそのぶん
上振れする。

## 何を握れるか

| グループ   | 中身                                  | 誰が決めるか       |
| ---------- | ------------------------------------- | ------------------ |
| ハーネス   | system prompt / スキル一覧 / 各種通知 | Claude Code        |
| リポジトリ | `CLAUDE.md` 群・`.claude/rules/`      | **このリポジトリ** |
| 会話       | 応答と道具の呼び出しの入力            | やり方しだい       |
| ツール結果 | Bash・ファイル読み・MCP の返り        | **やり方しだい**   |

ハーネスのぶんは動かせない。**手を入れられるのは下の 3 つで、issue #125 の
「規約の量」がリポジトリ、「取得の仕方」が会話とツール結果。**

## 自動で読まれるもの

上限を置く対象。**どれも「載る条件」が違うので、合計だけを見ても減らせない。**

| 何をするときに載るか       | ファイル                     |
| -------------------------- | ---------------------------- |
| 常時                       | `CLAUDE.md`                  |
| ブランチを切る前           | `CONTRIBUTING.md`            |
| `internal/` を触る         | `internal/CLAUDE.md`         |
| `web/` を触る              | `web/CLAUDE.md`              |
| `api/` を触る              | `api/CLAUDE.md`              |
| `paths` に当たるものを読む | `.claude/rules/*.md`         |
| `/rv` `/pr-review`         | `.claude/skills/*/SKILL.md`  |
| 手で開いたときだけ         | `docs/adr/*.md`・`README.md` |

**現在値はここに書かない。** 書き写すと、ファイルを直した日にここだけが古くなる
（`.claude/rules/docs-consistency.md`）。いまの値は `make token-report` が出す。

## 記録

測ったセッションを 1 行ずつ残す。**同じ作業を 2 回はできないので、セッション
どうしを直接は比べられない。** 比べられるのは「何をするときに何字載るか」の
静的な側で、こちらはタスクの内容に依らない。

**走っている最中のセッションを測ると、値はその時点のものになる。** 測った回数を
併記してあるのはそのため。

| 日付       | 何をしていたか          | 呼び出し | 最終 context | cache 読み | 計測できた字 | `CLAUDE.md` 群 | ツール結果 |
| ---------- | ----------------------- | -------: | -----------: | ---------: | -----------: | -------------: | ---------: |
| 2026-09-10 | #125 の調査とプラン作り |      122 |      194,006 | 14,281,029 |      276,166 |         10,303 |     72,728 |

読み方の例（上の行）。

- **`CLAUDE.md` 群は計測できたぶんの 3.7%** しかない。ただしこのセッションは
  ルートの `CLAUDE.md` しか載っていない。`internal/` と `web/` を触る実装の
  セッションでは 4 倍前後になる。
- **ツール結果が 26%。** うち `Bash` が 24%。読み取りの出し方（`sed -n` の範囲、
  ログに落として終了コードだけ見る）が効く側で、ここは #127 で手を入れた。
- **`cache 読み` は最終 context のおよそ 74 倍。** 削った 1 字がこの倍率で効く。
