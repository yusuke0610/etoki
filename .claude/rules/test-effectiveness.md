# テストが失敗を検知できるか

CodeRabbit に最も多く指摘されたのは「テストはあるが、守りたいものを
守っていない」形。書いたテストごとに「どの壊し方をしたら落ちるか」を
言えるかを確かめる。

## 検知能力を確かめる

- **直したバグは、修正を一時的に戻してテストが落ちることを確認する。**
  ページング修正の `break` 条件を戻す、上限のリセットを入れる、境界を
  外す、のように壊してから緑に戻す。落ちないテストは書いた意味がない
  （#26 / #85 / #25）。
- **一番失いたくないものを直接検証する。** 「キャンバスが表示されている」
  ではなく「描いた未保存の図形が保存リクエストに載る」。見た目が同じ
  作り直しでも通る検証は、守りたいものを見ていない（#85）。
- **要素に現れない変更（背景色など）は、要素が 1 つも変わらない操作で確かめる。**
  同じ `.excalidraw` を 2 回取り込む形では確かめられない。`restore` はローカルの
  要素を渡すと version を上げるので、背景色を見ていない実装でも署名が変わって
  通る（#119）。

## 断言の書き方

- **期待値は「非空」ではなく値そのもの。** `optionID != ""` は全部に
  同じ値を割り当てる実装でも通る。epic は `O_e`、issue は `O_i` と書く。
  設定したフィールド名（親フィールド等）も名指しで断言する（#18）。
- **種類が複数あるなら全種類を検査する。** epic だけ見ていると、片方の
  item にしか効いていない詰め替えを素通りさせる（#73）。
- **前提の検査は `t.Fatalf`。** `t.Errorf` のまま添字アクセスに進むと
  空スライスで panic する（#73）。
- **応答を decode する前に status を断言する。** `ErrorResponse` も
  `map[string]any` に decode できるので、確かめずに進むと 403 や 500 が
  「フィールドが写っていない」という見当違いの失敗になり、原因まで
  遠回りする（#104）。
- **弾いた操作は「書かれていないこと」も断言する。** エラーの検査だけ
  だと、検証の前に書いてしまう実装でも通る（#28）。
- **上限・打ち切りは境界をまたぐ形でテストする。** 700 件を 1 つの
  インストールに入れると、上限をインストールごとにリセットする実装でも
  通る。300 件 × 3 に分けて通算で止まることを見る（#26）。

## フェイクの作り方

- **フェイクは実装と同じ絞り方をする。** 実装が `boardID` で絞るなら
  フェイクも絞る。全部返すフェイクは「別ボードの run が判定を誤らせる」
  バグを検知できない（#25）。
- **失敗ノブ（`saveErr` / `listErr`）を置いたら、使うテストも書く。**
  特に「GitHub に作れたのに記録に失敗した」は一番痛い経路なのに未検証に
  なりやすい（#18）。
- **外部が返しうる形は、扱いを決めたらテストで固定する。** GraphQL の
  `node: null` を denied に倒す、といった判断は、ケースを置かないと後の
  変更で黙って反転する（#28）。
- **差し替えのために型を絞るときは、引数だけ公開型から導出する**
  （`(...args: Parameters<typeof f>) => Promise<絞った形>`）。戻り値まで導出すると
  フェイクが 80 個超のフィールドを埋めることになり、production から消した
  `as unknown as` をテストの数だけ増やす。引数を導出しておけば実物がキャスト
  無しで入り、ライブラリが変わった日に `tsc` が落ちる（#119）。
- **新しいモード・経路を足すときはテストを同時に足す。** `ModeApp` に
  テストが無かったことが、ページング取りこぼしの残った理由だった
  （#26）。
- **2 つに分かれて載るものは、fixture の片方を空で固定しない。** 画像は
  要素（`fileId`）と `files` に分かれるので、`files: {}` の fixture では
  `addFiles` を呼ばない実装でも往復テストが通る。両方を入れて両方を
  断言する（#119）。

## やらないこと

- **共有ヘルパーが満たしている前提を、呼び出し側にも書き足さない。**
  レビュアーはヘルパーの中を追わないので「明示されていない」と言って
  くるが、足すと同じ値が呼び出しの数だけ増える。返事はヘルパーの場所と
  行番号で返す。ハンドラのテストの `Host` がこれで、**入れる場所の正本は
  `internal/CLAUDE.md`**（#104）。

- **docstring の網羅率を満たすために、テストの無名関数へ docstring を
  足さない。** CodeRabbit の pre-merge check は `test(...)` のコールバックや
  `let release = () => {}` の踏み台まで対象に数える。テストが何を守るかは
  既に `//` で上に書いてあり、移し替えても内容は増えない。閾値は
  CodeRabbit の既定で、`.coderabbit.yaml` はその系統を入れないと決めている
  （#121）。
