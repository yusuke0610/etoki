# 非同期 UI の競合と見せ方

フロントの非同期処理と表示で繰り返し指摘された形。未保存確認と
エラー境界の約束は `web/CLAUDE.md` にあり、ここには書かない。

## stale な応答を反映しない

- **非同期リクエストは世代（generation）で守る。** 開始時に採番して
  応答の反映前に照合し、古ければ捨てる。`useState` の関数型更新でも
  古い応答は混入する（#17 / #18）。
- **応答が対象を名乗るなら、世代ではなく ID で照合する。** 表示名の
  取り直しは応答そのものがボードを持つので、`board.id` が今開いている
  ボードと一致するときだけ入れる。照合を省くと、遅れて届いた応答が今の
  ボードを外し、未保存確認を通さずにキャンバスを作り直す（#96）。
- **対象が変わるイベントは、関連する世代を全部無効化する。** 保存・
  ボード切替は解釈と作成の両方に効く。React state をクリアしても
  進行中のリクエストは止まらない（#18）。
- **完了表示は後続の反映が終わるまで「実行中」を保つ。** 作成後の
  一覧再取得が終わる前に done にすると、その隙間の保存と競合する
  （#18）。
- **取り消せない操作と保存は相互に排他する。** 保存中は作成させず、
  作成中は保存させない。片方しか守らない形で漏れやすい（#18）。確認
  ダイアログまわりの約束は `web/CLAUDE.md`（#70 由来）。

## 表示と意味を揃える

- **データの意味を変えたら、ラベルと E2E の文言も同じコミットで変える。**
  `items` を「前回作ったもの」から「いま GitHub に在るもの」に変えたのに
  「前回作成した N 件」が残る、という形（#81）。
- **状態の説明を `title` 属性だけに置かない。** ホバーできない利用者に
  届かない。本文に出して `aria-describedby` で結ぶ。押せないボタンは
  押せない理由が画面に見えていること（#25）。**守っていることを何が
  確かめるかは `web/CLAUDE.md` の「アクセシビリティ」にあり、ここには
  書かない。**
- **繰り返す行のボタンには行固有の accessible name を付ける。**
  全行が「外す」だと読み上げで区別できない（#28）。選択状態は
  `aria-pressed` で公開する（#25）。
- **表示用の定数（ロールのラベル等）は 1 モジュールに置いて共有する。**
  2 箇所に同じ Record を書くと文言が割れる（#28）。

## 押したときだけ引くものの出口

- **一度引いた結果を key に残すなら、失敗と 0 件にも再試行の口を置く。**
  押されたときだけ引く画面（実行の履歴など）は、失敗した状態もキーとして
  残る。読み直す口が「引けたとき」にしか無いと、通信が 1 度失敗しただけで
  画面を開き直すまで読めない（#105）。

## やらないこと

- **手動トリガー直後の状態再取得を「自動同期」と誤解して外さない。**
  作成後の `refreshAnnotations()` は etoki 自身の状態の読み直しで、
  GitHub への同期ではない。外すと作成済みが未作成に見え、重複作成を
  招く（#18 で確定）。
