# 非同期 UI の競合と見せ方

フロントの非同期処理と表示で繰り返し指摘された形。未保存確認と
エラー境界の約束は `web/CLAUDE.md` にあり、ここには書かない。

## stale な応答を反映しない

- **非同期リクエストは世代（generation）で守る。** 開始時に採番して
  応答の反映前に照合し、古ければ捨てる。`useState` の関数型更新でも
  古い応答は混入する（#17 / #18）。
- **応答が対象を名乗るなら、世代ではなく ID で照合する。** 表示名の
  取り直しは応答そのものがボードを持つので、`board.id` が今開いている
  ボードと一致するときだけ入れる。照合を省くと、遅れて届いた応答が今の
  ボードを外し、未保存確認を通さずにキャンバスを作り直す（#96）。
- **対象が変わるイベントは、関連する世代を全部無効化する。** 保存・
  ボード切替は解釈と作成の両方に効く。React state をクリアしても
  進行中のリクエストは止まらない（#18）。
- **完了表示は後続の反映が終わるまで「実行中」を保つ。** 作成後の
  一覧再取得が終わる前に done にすると、その隙間の保存と競合する
  （#18）。
- **取り消せない操作と保存は相互に排他する。** 保存中は作成させず、
  作成中は保存させない。片方しか守らない形で漏れやすい（#18）。確認
  ダイアログまわりの約束は `web/CLAUDE.md`（#70 由来）。
- **同じ操作の多重実行は、押した時点の値で弾く。** 非同期の処理を始める前に
  ref を立て、`finally` で戻す。state だと同じ tick に届いた 2 回目がまだ
  `false` を読む。**押させない側は代わりにならない。** 一瞬で終わる処理では
  押せない理由を画面に出す間が無く、`aria-describedby` で結ぶ文も作れないので、
  守りはロジック側に置く（#108、ADR 0039）。
- **`void f()` で呼ぶ非同期は、`f` 自身が失敗状態を更新する。** `void` は
  返り値を捨てるので、戻り値だけで失敗を返しても呼び出し側には届かない
  （`generateDiagram` は `false` を返すが、`void generateDiagram(...)` で
  呼ぶ側はそれを捨てるので、失敗表示は `f` の中の `setChat` が担う）。投げる
  だけでも同じで、呼び出し側が捕まえないので rejected Promise になり、
  **失敗表示なしで操作が終わる。** 例外を投げうる詰め替え（変換器など）も
  `try` の内側に入れる（#108、#129）。

## 表示と意味を揃える

- **データの意味を変えたら、ラベルと E2E の文言も同じコミットで変える。**
  `items` を「前回作ったもの」から「いま GitHub に在るもの」に変えたのに
  「前回作成した N 件」が残る、という形（#81）。
- **状態の説明を `title` 属性だけに置かない。** ホバーできない利用者に
  届かない。本文に出して `aria-describedby` で結ぶ。押せないボタンは
  押せない理由が画面に見えていること（#25）。**守っていることを何が
  確かめるかは `web/CLAUDE.md` の「アクセシビリティ」にあり、ここには
  書かない。**
- **サーバーが消したと答えたものは、引き直しを待たずに手元からも外す。**
  引き直しが失敗すると一覧は前の値のまま残り、開くと 404 になる行が並ぶ。
  応答で確かめてあるので推測ではない。**外す対象は ID を引数で受け取る。**
  開いているものから読み直すと、遅れて呼ばれたときに別のものを外す（#109）。
- **理由を出す約束は、消したボタンにも掛かる。** 権限で使えない操作は
  ボタンごと出さないが、代わりの理由の文は出す（ADR 0030、#109）。
  disabled にするか消すかは分かれても、理由が画面に無い状態は
  どちらでも不可。**同じ画面に並ぶ owner 専用の操作とは形を揃える。**
- **繰り返す行のボタンには行固有の accessible name を付ける。**
  全行が「外す」だと読み上げで区別できない（#28）。選択状態は
  `aria-pressed` で公開する（#25）。
- **表示用の定数（ロールのラベル等）は 1 モジュールに置いて共有する。**
  2 箇所に同じ Record を書くと文言が割れる（#28）。
- **押せない理由は否定形で書く。** `disabled` の隣に「〜できます」と出すと、
  操作の状態と案内が逆になる。**E2E の期待文言も同じコミットで直す**（#121）。
  「保存してから〜できます」のように、あとでできることの案内は肯定形のままが
  正しい。**語尾ではなく、いま押せるかどうかで決める。**
- **モデルにだけ渡す内部の文言を、履歴や一覧にそのまま並べない。** 内部の
  投げ直しであることを行に持たせ、画面は固定文に置き換える。**印はサーバーに
  送らない。** 契約にあるキーだけを送る口に、そのまま渡すと契約に無いキーが
  混ざる。**行ごと消しもしない。** 往復を 1 つ使ったことが履歴から消えると、
  サーバーが返す残り回数が勝手に減ったように見える（#108）。

## 押したときだけ引くものの出口

- **一度引いた結果を key に残すなら、失敗と 0 件にも再試行の口を置く。**
  押されたときだけ引く画面（実行の履歴など）は、失敗した状態もキーとして
  残る。読み直す口が「引けたとき」にしか無いと、通信が 1 度失敗しただけで
  画面を開き直すまで読めない（#105）。

## やらないこと

- **失敗以外の表示ラベルを `web/src/api/errorMessage.ts` に寄せない。**
  「固定表示文はあそこに集める」という指摘で提案されるが、あれは失敗の `code`
  から日本語を引く層で、担保は `Record<ErrorCode, string>` の網羅検査
  （ADR 0034、`web/CLAUDE.md`）。**引くべき `code` の無い文言**は置いても検査に
  参加できず、表の意味を薄めるだけになる。用途ごとのモジュール
  （`annotationLabel.ts` / `diagramLabels.ts` / `roles.ts`）に置く（#108 で撤回済み）。

- **手動トリガー直後の状態再取得を「自動同期」と誤解して外さない。**
  作成後の `refreshAnnotations()` は etoki 自身の状態の読み直しで、
  GitHub への同期ではない。外すと作成済みが未作成に見え、重複作成を
  招く（#18 で確定）。
