# E2E モックの厳密さ

CodeRabbit のレビューで繰り返し出た落とし穴。緩いモックは「モックだけが
古い契約のまま緑になる」を招く（ADR 0012）。生成型・ルート述語・境界の
例外は `web/CLAUDE.md` にあり、ここには書かない。

## ルートの縛り方

- **ルートは HTTP メソッドを検査する。** 契約のメソッド以外は
  `route.fallback()` でキャッチオールに落とす。クライアントがメソッドを
  間違えても E2E が緑のままになるため。target / members / auth に入れて
  interpret だけ抜けていた、という形で漏れやすい（#29 / #26 / #28 / #25）。
- **パスはアンカー付きの述語で完全一致させる。** `endsWith` の末尾一致は
  間違ったパスでも成功応答を返す（#21）。
- **モックの判定はサーバーと同じ契約にする。** 必須フィールドの欠落は
  409 ではなく 400、というように、サーバーが返す区別をモックでも守る。
  モックだけが緩いと、フロントの送り忘れを競合テストが隠す（#69）。
- **省略された任意フィールドは、作成側と同じ既定値に落とす。** スプレッド
  で前の値を残すと、省略したのに古い値が生きているボードが返る（#75）。

## リクエストの検証

- **記録した本文を読む前に、応答後にしか出ない表示を待つ。** `click()` は
  応答を待たずに返るので、待たずに `mock.createRequests` を読むと空配列を
  見て通りうる。待ち方は expect.poll ではなく、そのファイルが既に使って
  いる表示待ち（`.waitFor()` など）に揃える（#74）。
- **画面の遷移だけでなく、期待するリクエストが飛んだことも断言する。**
  同じ表示を別の実装で作っても通るため。`page.waitForRequest` で
  メソッドとパスを縛る（#26）。

## やらないこと

- **`ApiMock` のプロパティに代入するリテラルへ `Reply<T>` を重ねない。**
  プロパティ型が生成型なので、代入の時点で検査済み。明示しても検査は
  増えない（#81 で撤回済み）。
- **`breakList` 系の壊れた本文を型に通さない。** 壊れていること自体が
  テストの入力。キャストで形だけ通すと意図が隠れる（#85 で確定、
  `web/CLAUDE.md` の例外）。
