# RV（セルフレビュー）

作業中の差分を etoki の規約に照らして点検し、直し、また点検する。

## 何を見るか

対象は**このブランチで加えた変更のみ**。既存コードの粗探しはしない。

```sh
git status --short
git diff main...HEAD        # コミット済みの差分
git diff                    # 未コミットの差分
git diff --cached
```

差分の周辺は必要なだけ読む。変更行だけ見て判断しない。

## 1 周の手順

1. 上のコマンドで差分を集める。
2. 下の「観点を集める」で読むものを決め、1 項目ずつ照らす。
3. 見つけたものを分類する（後述）。
4. 「直す」に分類したものを直す。
5. `make lint` と `make test` を通す。UI かハンドラを触っているなら
   `make test-e2e` も通す（`make` は devShell の外からでも自分を包み直す）。
6. 直したものがあれば次の周へ。なければ終了。

## 観点を集める

**観点をここに持たない。** 正本を開いて照らす。写しを持つと、レビューの指摘を
還しても正本しか育たず、ここだけが止まったまま残る（ADR 0033）。

読む順は「落としやすい順」ではなく「効き方の強い順」。

| 順  | 開くもの                         | 見るもの                                              |
| --- | -------------------------------- | ----------------------------------------------------- |
| 1   | `README.md`「中核となる思想」    | 3 つの思想。ここに反していたら他は見るまでもない      |
| 2   | ルートの `CLAUDE.md`             | 壊れやすい約束、依存の方向、公開 API 面、進め方       |
| 3   | 触ったディレクトリの `CLAUDE.md` | `internal/` / `web/` / `api/`。差分が及んだものすべて |
| 4   | `.claude/rules/` の該当テーマ    | 過去に実際に踏んだ形。選び方と数え方は下              |
| 5   | `CONTRIBUTING.md`                | ブランチ・コミット・PR 本文。**自動では読まれない**   |

**`.claude/rules/` は `ls` してから選ぶ。** 各ファイルの frontmatter の `paths` を
見て、差分にかかるものを**明示的に開く**。対象ファイルを読めば自動でも読み込まれる
が、点検の周では 1 項目ずつ照らす。**「やらないこと」の節は逆向きの検査**で、
そこに載っている「修正」を善意で入れていないかを見る。

**`paths` が 1 つもかからない差分があったら、それは報告に出す。** rules が
その領域に追いついていないという合図で、次に指摘が来るのはそこ。

## 指摘の分類

見つけたものは必ずどれかに割り振る。曖昧なまま直さない。

| 分類     | 扱い                                                       |
| -------- | ---------------------------------------------------------- |
| 直す     | 規約違反、バグ、テスト漏れ。その周のうちに直す。           |
| 直さない | 仕様として固定されているもの。**理由を添えて報告に残す。** |
| 聞く     | 設計判断が要るもの。手を動かさずユーザーに投げる。         |

好みの問題は指摘しない。周辺コードと違う書き方をしている場合だけ挙げる。

## 打ち切り条件

**最大 3 周。** 周回はこのスキルの中で回す（`/loop` は要らない）。

- 指摘ゼロなら、その時点で終わる。周回数を消化しない。
- 3 周して残った指摘は、直さずに一覧で報告して判断を仰ぐ。同じ箇所を
  3 周直しても収まらないなら、それは設計の問題であって手直しの問題ではない。
- 直した結果が別の指摘を生む堂々巡りに入ったら、そこで止めて報告する。

## 報告

各周について、見た範囲・指摘・対応を簡潔に。最後に:

- 直したもの
- 直さなかったもの（理由つき）
- ユーザーの判断を待つもの
- **観点ごとの件数**。どの正本のどの項目で何件見つけたかを数える。
  **`.claude/rules/` は 0 件でも「照らした」と書く。** 開いていないのか
  当たらなかったのかを、あとから区別できるようにするため。
- **`paths` が当たらなかった差分のパス。** 無ければ「無し」と書く。
- `make lint` / `make test` の結果
- UI を触ったなら `make test-e2e` の結果と、`web/e2e-output/screenshots/` の
  スクリーンショット（`web/CLAUDE.md`「報告にブラウザの実行結果を添える」）

**この件数が、PR に付いた初回指摘数と並ぶ。** 記録の付け方は
`.claude/skills/pr-review/SKILL.md`（`docs/review-findings.md`）。
