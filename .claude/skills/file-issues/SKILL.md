# 調べた結果を issue に積む

## 1. 公開か非公開かを分ける

**悪用できるもの（認証・認可の穴、他人に作用するもの）は、公開の issue にしない。**
`/security-audit` の「振り分ける」に従い、Security Advisory の下書きにする。

- **迷ったら非公開に倒す。** 公開してから引っ込めることはできない。
- **公開の場所に、非公開の件の中身も存在も件数も書かない。** 公開の場所とは、
  issue、PR、コミットのこと。

## 2. 重複を探す

候補ごとに探す。閉じたものも、PR も出る。

```sh
gh search issues "<語>" --repo yusuke0610/etoki --include-prs
```

- **開いた issue に同じ件がある。** そこに足す。
- **閉じた issue に同じ件がある。** 閉じた理由を読む。覆すなら、新しい issue に
  理由を書く。
- **同じ件を閉じる PR が、開いていないかも見る**（`.claude/skills/triage/issues.sh`）。

## 3. 本文を書く

**sub-issue の本文。** 該当しない節は消す。

```markdown
親: #<親の番号>

## 現象

## 何が困るか

## 方針の候補

## 決めること

## やらないこと
```

| 節           | 書くこと                                                               |
| ------------ | ---------------------------------------------------------------------- |
| 現象         | 何が起きているか。数・再現・出どころ（`ファイル:行`、PR 番号）を添える |
| 何が困るか   | 誰が何を失うか。中核となる思想や ADR のどれに反するか                  |
| 方針の候補   | 採る案と、採らない案の理由                                             |
| 決めること   | 着手するときに決める論点。`/spec` が拾う                               |
| やらないこと | この issue で扱わないこと                                              |

**親の issue の本文。** 次の 5 つを書く。

- 経緯
- 調べ方
- sub-issue の表（番号・一言・優先度）
- 順番（依存、同じ PR にしないもの）
- 見たが issue にしないもの（理由つき）

**タイトル。** Conventional Commits の形にし（`chore(claude): …`）、要約は日本語で書く。

## 4. 作って結ぶ

1. **親を先に作る。** sub-issue の本文に、親の番号を入れて作る。
2. **親の表を書き直す。** 作った sub-issue の番号を入れる。
3. **sub-issue として結ぶ。** 渡すのは issue の番号ではなく、数値の `id`。

   ```sh
   id=$(gh api repos/yusuke0610/etoki/issues/<子の番号> -q .id)
   gh api -X POST repos/yusuke0610/etoki/issues/<親の番号>/sub_issues -F sub_issue_id="$id"
   ```

4. **作ったら、本文を GitHub から取り直して確かめる。** 手元のファイルではなく、
   取り直した本文で見る。仮の番号（`#SUB1` など）で書いて後から置き換えると、
   置き換えたつもりでも GitHub に届いていないことがある。

## 5. 報告する

親と sub-issue の番号を、表にして出す。
